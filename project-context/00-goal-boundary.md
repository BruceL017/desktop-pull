# 00 · 目标边界(Goal Boundary)

> 本文件是循环 Phase 0–1 的落点。下面每节先空着,讨论清楚一节就填一节,并更新 README 状态表。
> 未填的节保留标题 + `(待填)`,这是"还没讨论到",不是占位壳。

## 北极星(North Star)

让个人用户在桌面和手机界面上快速整理、调整并回溯自己的任务计划,不因误操作丢失工作脉络。

## 设计箴言(Design Maxim)

创建只需一次明确提交且不中断连续输入;删除必须先让用户确认后果。

可恢复期内历史只追加,恢复只合并;永久删除按明确规则从当前数据库与新备份清除目标事实,并去身份化其他记录中的目标结构化引用。

存储故障时优先保持契约允许的日常操作可用,但未持久化就必须明确标为待保存;单任务永久清理、清空垃圾箱、自动永久清理和完整备份导入只在对应持久化健康条件满足时执行。

## Done(外部可观察)

- 第一版核心 Done:在 Windows 11 当前 Chrome 的 `1440 x 900` 桌面参考环境和当前 iOS Safari 的 `390 x 844` 移动参考环境中,每组 5 名首次用户至少 4 名无需教程在 `120s` 内创建 3 个任务、修改优先级、新建分类、完成组内与跨分类拖拽、删除并恢复一个任务,第 5 名也在 `180s` 内独立完成;最后刷新计时且刷新后任务、顺序与历史均正确。
- 用户可以把 Desktop Pull 作为普通网页或已安装 PWA 使用;首次成功加载后断网,核心任务路径仍可完成。
- M1 的正式发布矩阵覆盖 Windows 11 的 Chrome、Edge、Firefox 网页与 Chrome、Edge 安装形态,macOS 当前及上一受支持大版本的 Safari、Chrome、Firefox 网页与 Chrome 安装形态,iOS/iPadOS 当前及上一受支持大版本的 Safari 网页与主屏幕 Web App,以及 Android 当前及上一大版本的 Chrome、Firefox 网页与 Chrome 安装形态。
- 普通网页始终是基础入口,安装只是增强;矩阵外环境不按 User-Agent 硬拦截。不同浏览器、用户配置文件或隔离安装容器的本地数据不自动共享,用户通过完整备份导出与导入迁移。
- M1 提供完整的简体中文与英文界面,用户可以在运行中的 Desktop Pull 内切换语言;产品名始终显示为 `Desktop Pull`,切换不会改写任务、分类或历史事实。
- 首次进入时按设备或浏览器的有序语言偏好选择首个受支持的中文或英文;任何 `zh-*` 使用简体中文、任何 `en-*` 使用英文,没有匹配或无法读取时默认简体中文。
- 用户手动切换语言后立即在原上下文生效并由当前设备跨重启记住,优先于首次语言匹配;语言偏好不进入完整备份,覆盖导入不改变当前语言。
- 语言切换不占用任务主工具栏或移动底栏:桌面从侧边栏底部设置进入,移动端从任务页右上角菜单进入设置;设置中使用带地球图标、选项为 `简体中文` 与 `English` 的双选分段控件。
- 产品默认直接进入任务清单;桌面通过侧边导航、移动端通过任务/历史/垃圾箱三个底部标签切换高频视图,设置与备份使用低频入口。
- 当前会话内从历史或垃圾箱回到任务页时,用户能回到原滚动与折叠位置,但不会被自动重开的编辑器或移动键盘打断。
- 刷新或重开后继续保留当前设备的语言、分类与“已完成”折叠偏好,但新会话从清单顶部开始;这些界面偏好不进入完整备份。
- 完整备份覆盖导入成功后重置设备折叠偏好并从清单顶部展示,但保留当前语言偏好;取消或失败的导入不改变现有数据或偏好。
- 用户可以手动导出并导入包含任务、分类、顺序、垃圾箱、全部保留中的任务主体与分类主体历史和非空快速创建草稿的完整本地备份。
- 数据已成功加载后发生正式任务、分类或历史业务写入故障时,用户仍能继续日常任务操作,看见明确的待保存状态并导出包含待保存变更的应急完整备份;永久清理和覆盖导入暂时不可执行。自动清理等维护故障不得仅据此成为用户待保存操作。
- 应用启动时若尚未成功初始化并完整读取本地核心数据,不会把故障伪装成空清单或接受新修改;用户看到本地数据未被改写的保护状态及自动、手动重试,读取成功后恢复完整产品。
- 核心数据已经完整读取后,启动、回到前台或运行期自动到期清理事务失败时,用户仍能使用日常任务功能;到期任务及其任务主体历史在首次展示、恢复交互或运行期到期时立即从界面、搜索、筛选、计数和新备份中排除,其他保留记录中指向目标的结构化任务引用同时显示并导出为不含身份的“不可用”。界面持续提示本地物理清理待完成并自动、手动重试,其间暂停新的永久删除、清空垃圾箱和覆盖导入。
- 草稿暂时无法保存时,用户仍能连续输入;界面明确标记最新草稿未安全保存,应急完整备份包含其最新文字。
- 仅草稿自动保存失败不会让整个产品进入全局降级或新增对无关操作的冻结,也不会解除其他独立状态已有的限制;正式任务、分类或历史业务写入失败时才启用全局保护。
- 应用更新导致数据库 schema 迁移失败时,用户自动回到最近一次已验证且兼容旧 schema 的缓存应用版本,继续使用完整产品和原数据库。
- Schema 升级只迁移不可写候选数据库副本;候选完成完整读取与启动验证后才切换,任一步失败都在清理候选后继续使用未改写的旧数据库和 last-known-good 应用。
- 同一设备共享本地数据库的网页标签页、窗口和已安装 PWA 始终只有一个活动窗口加载并操作数据;其他窗口可请求无损移交,但不会展示陈旧任务或形成第二条待保存队列。
- 用户可以用必填标题和可选备注创建、查看和编辑任务;空白标题不能保存。
- 第一版任务备注为保留换行的多行纯文本,不提供富文本、Markdown、内嵌清单、附件或图片。
- 主清单对有备注任务只显示一行弱化预览,完整备注留在编辑器;无备注任务不占预览空间。
- 主清单任务标题最多显示两行并防止长字符横向溢出,完整标题仍保留在编辑器、历史和备份中。
- 用户可以通过全局快速入口把只含标题的任务立即创建到收件箱,也可以通过分类标题旁的新增入口直接创建到该分类;两种入口均不先打开完整编辑器。
- 用户输入标题后只需一次明确提交即可创建;创建过程不弹确认或成功弹窗,并能不中断地继续输入下一条任务。
- 用户暂时离开快速输入时,未提交文字不会被误建成任务或立即丢弃;回到同一入口可以继续输入。
- 用户可以把任务标记为已完成并重新设为未完成;两种操作都不改变任务的分类、优先级或持久顺序,也不会把任务移入垃圾箱。
- 每个分类默认聚焦未完成任务;已完成任务收纳在分类底部的折叠区域,重新打开后回到原顺序位置。
- 用户无需手动选择优先级即可新增任务,新任务默认是 `P3`;任一任务始终且仅有一个 `P0` 至 `P5` 优先级。
- 用户可以直接从任务行一次选择并修改 `P0` 至 `P5` 优先级,无需先打开编辑器;修改不会自动重排任务。
- 用户未选择自定义分类即可立即新增任务到固定收件箱;创建后既可跨分类拖拽,也可从任务菜单或编辑器共用的选择器立即改到已有分类、在原处新建分类并归入,或移回收件箱;选择器移动保持完成状态并置于目标状态区顶部,选择当前分类属于无操作且不会置顶、更新时间或生成历史,任务在活动期间始终只有一个当前归属。
- 从任务行选择器移动后用户留在当前清单位置并可主动定位任务;从编辑器移动时编辑器保持打开。两条路径都不会把待保存移动误报为成功。
- 用户可以从主清单分类列表末尾触发立即聚焦的原地输入,只用一次明确提交新建空分类;输入法组合或失焦不会误建,取消直接清空,无效名称留在原处修正。成功后仍停留在清单中,不弹窗、不跳页且不自动创建任务;未提交名称不跨刷新或进入备份。
- 主清单独立新建分类只形成 `category.created(eventOrder = 0)`,选择器内新建并归入任务则在同一原子操作中先形成该分类事件、再形成 FORMAT-025 `task.category_changed(eventOrder = 1)`;两条路径的分类创建事件都由公共分类主体保存创建时 ID 与用户原文名称,FORMAT-029 `details` 必须精确为 `{}`。
- 用户可以原地重命名自定义分类且无需确认;有效新名称经统一名称规则处理后,同一原子操作更新分类当前名称、推进操作顺序并只追加一条 `category.renamed(eventOrder = 0)`:公共分类 `subject.name` 保存改名后的用户原文,FORMAT-030 `details` 精确只保存 `{ beforeName }` 且旧名必须不同于新名。同一有效当前名称属于完全无操作;成功改名不改变分类 ID、分类顺序、任务顺序或任一任务的归属、状态、内容、优先级、生命周期和时间,也不生成任务事件。
- 用户可以从分类标题直接拖拽自定义分类并持久化顺序;收件箱固定第一且不属于可排序的自定义分类序列。真实换位在同一原子操作中只更新 `categoryOrder`、推进一次操作顺序并追加一条 `category.reordered(eventOrder = 0)`:公共分类主体保存被移动分类发生时的 ID 与用户原文名称,FORMAT-031 `details` 精确保存移动前后各自的前后自定义分类邻居或自定义序列首尾边界。放回原位属于完全无操作;排序不改变分类名称、任何任务事实或追加任务事件。
- 用户删除仍含任务的自定义分类后,其中任务按原相对顺序移动到收件箱末尾,不会被连带删除。
- 用户删除任何自定义分类前都能在一个确认框中看见分类名称和后果;非空分类还会明确显示任务数量及任务将移入收件箱而非垃圾箱。若分类标题入口有未提交草稿,同一确认显示可识别预览并把按钮改为“删除分类并丢弃草稿”;取消完整保留,确认只消费用户看过的草稿代次,换代后必须重新确认。
- 用户在桌面或移动视口中都能通过纵向分类分组浏览任务,折叠分组,并完成组内或跨组拖拽。
- 用户无需寻找拖拽手柄:桌面端可从任务行任一非控件区域直接拖动,移动端同一区域能可靠区分长按拖动与页面滚动。
- 拖拽时用户始终看见唯一精确落点,可直接投放到空或折叠分类并在长清单边缘自动滚动;只有有效位置松手才移动,取消或无效放下不会改变任务或历史。
- 拖拽始终保持任务完成状态;未完成与已完成只能通过复选框切换。移动端快速轻触、滑动滚动、长按未移动和长按后拖动产生四种互斥结果。
- 用户普通点击任务行即可编辑:桌面使用右侧面板,移动端使用全屏页;普通点击不会误切换完成状态。
- 用户修改任务标题或备注时无需点击保存按钮;有效修改自动持久化并进入历史,删除仍必须明确确认。
- 连续编辑停止约 `600ms` 或用户离开编辑上下文时,最新有效内容自动形成一次保存和一条历史,不会为每个字符生成记录。
- 编辑器以“保存中… / 已保存 / 待保存”安静反馈自动保存状态;成功提示自动消失,失败提示持续可见且提供既定恢复出口。
- 已有任务标题被清空时只阻止无效标题保存;其他修改和退出不受阻,任务继续保留最后一次有效标题。
- 用户拖拽任务后刷新或重启应用,顺序保持不变;修改优先级不会自动移动任务。
- 用户确认删除弹窗后,任务进入垃圾箱并能被单独恢复;后来新增或修改的其他任务保持不变。
- 恢复任务时只按当前 FORMAT-014 生命周期中的删除时分类、完成状态和无标题锚点回到最接近原位置;FORMAT-027 删除历史位置与 FORMAT-028 恢复结果都只供审计。原分类仍存在时 FORMAT-028 记录同一分类标识、恢复时当前名称、未改变状态及插入后同状态直接邻居;原分类已删除时进入收件箱对应状态末尾并记录该实际结果,且不会移动或覆盖当前其他任务。
- 用户在 30 天到期前已经被产品接受的恢复不会因待保存期间跨期而撤销;待保存项冻结已经算出的 FORMAT-028 实际目标和插入后位置,存储恢复后先按该结果补写恢复再清理其他到期任务,不得重读锚点或重算落点。到期时或之后才发起的恢复不生效,未补写且未导出的内存恢复仍可能随会话终止丢失。
- 垃圾箱按最近删除优先显示任务标题、优先级、删除时分类、删除时间和剩余天数;用户可直接恢复,但必须从菜单发起并确认永久删除,且不能在垃圾箱内编辑或拖拽。
- 恢复成功后用户仍可继续处理垃圾箱;只有主动选择“查看任务”时才进入任务页并定位、高亮目标任务,过程不自动打开编辑器或移动键盘。
- 用户从任务行菜单或任务编辑器底部发起删除,两处共用同一确认流程;第一版不使用滑动、常驻垃圾桶或单键删除。
- 用户编辑后立即发起删除时,最新有效内容先保存或排队,垃圾箱与恢复结果保留该内容;取消删除不会撤销编辑。
- 只要任务未被永久清理,用户始终能查看其完整历史;系统不会按时间或条数静默截断记录。
- 用户能在独立的全局历史页按任务、分类或动作追溯变更;任务恢复只在独立垃圾箱中进行。
- 历史页按正式操作进入工作状态时冻结的时间倒序显示事件发生时的标题和摘要,同时间操作及一次操作的多条事件始终具有稳定顺序;延迟补写和备份往返不会重排或重新计时。用户可在原地展开该事件专属且实际存在的完整精确事实;后来改名不会改写旧事件,历史页不提供编辑、撤销或恢复。
- 任务变化显示发生时任务标题,分类管理显示发生时分类名称且不伪造任务标题;删除分类后其管理历史仍可搜索和备份。历史任务邻居按 D-106 冻结发生时标识与标题,后来改名、移动、状态变化或软删除不回写;D-112 / FORMAT-027 以删除时分类、状态和移出前位置解释软删除,D-113 / FORMAT-028 以实际恢复目标分类、状态和插入后位置解释恢复,两者都不参与恢复或当前排序。永久清理任务移除该任务自己的完整事实链,其他事件继续保留但其中指向目标的位置邻居只显示通用“不可用”,不再保留目标标识或标题。
- `category.created` 的显示与分类筛选只读取创建事件公共主体,不得从当前分类、当前分类顺序或历史重放补值;其严格空详情不复制位置、入口、设备、语言、分类记录或关联任务。后来重命名、排序或删除分类不改写该事件,永久清理任务也不触碰这个独立分类事实;待保存队列、存储和完整备份只原样保留 `{}`。
- `category.renamed` 的紧凑摘要与展开只从 FORMAT-030 `details.beforeName` 到公共 `subject.name` 显示旧名到新名,动作按当前语言呈现而两个用户名称逐字保留。分类筛选只按 `subject.categoryId`,名称搜索同时匹配该条历史中的旧名和新名;不得查询当前分类、当前顺序、后来事件或重放历史补值。后来再次改名、排序、删除及任一任务永久清理都不改写或移除该独立分类事实;待保存队列、当前存储和新备份只保留精确 `{ beforeName }`,不得重复 `afterName` 或其他字段。
- `category.reordered` 的紧凑摘要只按 FORMAT-031 `afterPosition` 显示移到自定义分类序列顶部、末尾或某个发生时邻居之后,展开显示完整 `beforePosition` 与 `afterPosition`;动作和 `start` / `end` 边界按当前语言呈现,主体及邻居名称逐字保留。分类筛选只按 `subject.categoryId`,名称搜索匹配该条事件中的主体与邻居名称;不得查询当前 `categoryOrder`、当前分类、后来事件或重放历史补值。后来改名、排序、删除主体或邻居及任一任务永久清理都不改写或移除该独立分类事实。
- `category.deleted` 按 D-117 / FORMAT-032 只由公共被删分类主体与 `{ affectedTaskCount }` 表达:计数是在操作接受时从该分类活动顺序实际迁入 Inbox 的任务总数,空活动分类为 `0`,垃圾箱任务与草稿不计入。正常 N 项删除同操作产生 N 条 FORMAT-026;后来永久清理任务可以让这些任务事件减少或全部消失,但分类删除计数与主体不回写。历史按被删分类主体筛选,双语摘要从发生时名称、计数与固定 Inbox 语义生成,不读取当前任务、剩余事件或后来状态补值。
- 用户可从一个响应式筛选入口按任务、分类和多个动作即时缩小历史结果,看见并移除当前条件;FORMAT-025 主动跨分类任务事件只按 `target.categorySnapshot` 归入目标分类筛选结果,FORMAT-026 分类删除派生迁移只归入固定收件箱,FORMAT-027 软删除只按删除时 `categorySnapshot` 匹配,FORMAT-028 恢复只按实际恢复目标 `categorySnapshot` 匹配;来源快照与位置仍可查看,不按来源分类、垃圾箱或任务后来当前归属、状态和顺序匹配;筛选只在当前会话保留且不进入备份。
- 用户从任务编辑器查看历史时,最新有效编辑先保存或排队,旧筛选被替换为当前任务条件,因此无需清理遗留条件就能直接看到该任务的完整时间线;返回清单不会自动重开编辑器。
- 历史动作筛选使用八个稳定、可理解的分组,事件仍显示精确子类型;草稿、折叠、筛选和导航等界面行为不会污染事实时间线。
- 移动历史用发生时分类、完成状态与相邻任务解释移动结果;同分类组内排序按 D-109 / FORMAT-024 只保存一次分类、一次状态及移动前后位置,原位拖拽不形成事实。跨分类变化按 D-110 / FORMAT-025 只保存一次状态,在 `source` / `target` 中分别保存发生时分类与移出前 / 插入后位置;展开完整显示两侧,紧凑摘要先表达“从 A 移到 B”并只按 `target.position` 补充落点,目标位置不可用时降级为中性跨分类移动文案。历史前、后任务邻居分别使用 D-106 的方向严格联合,任务分支保留发生时标题且不与无标题恢复锚点混用;正常 FORMAT-025 四槽位中可识别任务 ID 跨侧两两不同且非主体。后来改名、移动、状态变化或软删除不改写旧记录,永久清理相邻任务时只按 D-097 去身份化整个目标引用;多个邻居去身份化使位置收敛时仍保留合法事件,且呈现不读取任务当前归属、状态或顺序。分类删除派生迁移按 D-111 / FORMAT-026 只保存一次状态、被删来源分类与整批前位置、以及整批完成后的最终 Inbox 位置;固定目标不另存快照,任务事件按来源总顺序且批次邻居可跨来源与目标同方向重复。软删除按 D-112 / FORMAT-027 只保存删除时分类、状态和移出前位置;恢复按 D-113 / FORMAT-028 只保存实际落点分类、状态和插入后位置,原分类已改名时保存恢复时当前名称,已删除时保存固定收件箱。时间、内容、优先级、删除生命周期与恢复锚点仍由各自字段拥有,后来恢复、再次删除或其他变更都不回写旧事件,且 FORMAT-028 从不作为之后恢复或排序输入。清理重复邻居时全部出现位置一起去身份化,迁移、软删除或恢复主体清理后允许事件缺口而独立分类删除事实保留。用户不会看到内部排序值、逐项中间位置、失真的绝对名次或拖拽实现来源。
- 没有在期限内接受恢复的垃圾箱任务删除满 30 天后会被自动幂等清理;无论清理发生在启动、回到前台还是运行期,物理清理失败都按 D-081 与 D-082 立即逻辑隔离,到期任务不再可见、可恢复或进入新备份,契约允许的日常操作继续可用。
- 用户能在二次确认后永久删除单个垃圾箱任务或清空垃圾箱;任务内容及其全部任务主体历史痕迹从当前数据库销毁且不进入之后的新备份,其他垃圾箱恢复锚点或任一事件 schema 已声明的历史任务邻居中指向目标的结构化引用在同一原子事务整体改为不含身份的“不可用”。无关任务、无关历史与独立分类主体事件不被连带删除。
- 永久清理确认明确显示任务标题或冻结任务数量,说明删除前导出的产品外备份可能仍含这些内容并可在主动导入后重新出现,且无需输入确认短语;确认期间新增或已恢复的任务不会被清空操作误删,整批清理不会留下半删除状态。
- 用户主动覆盖导入有效的删除前备份时,其中已被当前数据库永久清理的任务及当时历史可以随完整快照重新出现;产品不保存跨导入墓碑或删除黑名单,导入时已经到期的垃圾箱任务仍按既定规则排除。

## Non-goals(非目标)

- 不做团队共享、任务指派或多人实时协作;第一版只服务单个用户,避免引入与核心个人任务体验无关的账号、权限和协作冲突。
- 第一版不做登录、云端备份或跨设备同步;这些能力留到真正开发移动 App 时重新决策。
- 第一版不做原生移动 App;移动端交付形态是响应式、可安装的 PWA。
- 第一版不把 Windows 10、Linux、ChromeOS、内嵌 WebView、应用内浏览器、隐私模式、预发布浏览器、Android 厂商浏览器或已退出滚动支持窗口的环境纳入正式发布 Gate;具备必要能力时仍允许尽力运行。
- 第一版不做整份任务清单的历史快照回滚;任务按条恢复,并与当前清单共存。
- 第一版不做截止日期、提醒、重复任务、子任务或附件;先验证任务整理、拖拽和恢复体验。

## Constraints(硬约束)

- 第一版的数据保存在当前设备,页面刷新或应用重启后仍须存在。
- 核心任务路径必须离线可用,不得依赖登录、远程 API 或持续网络连接。
- 正式支持版本采用滚动窗口:Chrome 与 Firefox 覆盖当前及上一个 Stable,Edge 覆盖当前及前两个 Stable,Safari 随当前及上一个 Apple 支持系统组合;每次发布候选必须冻结并记录实际验收版本。
- 两分钟首次用户 Gate 只在 `1440 x 900` 桌面与 `390 x 844` 移动参考环境执行;`1280 x 720` 桌面、`360 x 800` 移动边界视口及 D-090 其他正式平台执行同一路径的非计时功能 Gate。
- 计时从应用可操作后的首次交互开始,在最后刷新完成并重新显示正确清单时结束;首次加载和任务卡预读不计时,最后刷新计时,停表后数据与历史核验仍可判失败。
- 首次用户证据不得来自开发者、agent、已阅读上下文包或已经测试过另一形态的人员;桌面与移动各 5 名样本中至少 4 名须在 `120s` 内、第 5 名须在 `180s` 内无帮助完成。任何产品数据丢失、删除非目标任务或虚假保存直接阻断发布。
- 安装能力不可用或安装失败不得使同一正式支持浏览器的普通网页模式不可用;矩阵外环境也不得仅因浏览器名称或版本被拒绝访问。
- 单活动窗口和共享数据只适用于实际访问同一源站 `IndexedDB` 的实例;不同存储作用域不得自动复制、合并或同步,只能由用户通过完整备份迁移。
- M1 的桌面与移动界面必须同时完整支持简体中文和英文,不得把其中一种语言推迟到后续版本。
- 产品自有状态、事件、系统分类和位置边界必须以语言无关语义持久化并按当前界面语言呈现;用户输入的标题、备注、自定义分类名称及其历史快照必须保留原文,不得自动翻译。
- 当前状态与对应历史必须原子持久化;不得出现状态变化但历史缺失,或历史存在但状态未变化。
- 核心数据只存入版本化 `IndexedDB`;迁移失败不得清库、丢弃数据或降级写入 `localStorage`。
- 应用必须先完整读取核心数据库再开放任务操作;初始读取失败时不得推断空库、建立临时工作区、导入覆盖或生成不完整备份。
- 新应用版本完成 schema 迁移并成功启动前,必须保留最近一次已验证的兼容应用版本;迁移失败的版本不得继续写库或在每次启动时重复迁移。
- Schema 迁移不得直接改写活跃数据库;候选代次验证成功后才能原子激活,旧代次和其他候选必须在开放写入前清理,任何代次歧义都进入数据保护态。
- 写入故障期间的待保存队列只属于当前运行会话,不得成为第二个持久化事实源;应用必须明确提示关闭或重载前尚未落盘的变更可能丢失。
- 同一存储作用域只允许一个活动窗口访问核心数据;正常移交必须先落盘全部有效编辑与草稿,待保存状态和敏感事务期间不得移交或强制抢占。
- 第一版必须提供不依赖账号或云服务的完整备份导出与导入。
- 后续 Desktop Pull 版本必须继续导入所有正式发布版本生成的有效旧备份;当前应用无法理解的更高版本备份必须在写入前拒绝并提示升级。
- 永久清理的不可恢复承诺只覆盖当前活跃数据库及后续新生成的备份;其中不得保留可识别目标的结构化引用。应用不得声称、尝试或记录为已经销毁用户自行保存的产品外备份。
- 未永久清理任务的任务主体历史必须完整保留;分类主体历史按独立生命周期保留。两者都不能单独删除某一条历史记录。
- 每个任务必须且只能有一个 `P0` 至 `P5` 优先级;新增任务默认 `P3`。
- 每个活动任务必须且只能由权威分类任务顺序表达一个当前分类;未选择自定义分类时默认属于固定收件箱。垃圾箱任务不占活动分类或顺序位置;FORMAT-014 删除时分类是当前垃圾箱展示和恢复输入,FORMAT-027 删除时分类与 FORMAT-028 恢复后实际分类都只是不参与恢复或当前排序的历史审计快照。
- 自定义分类名称去除首尾空白后必须非空且互不重复;系统名称“收件箱”与 `Inbox` 在两种界面语言下都保留,其中 `Inbox` 对 ASCII 大小写不敏感。
- 垃圾箱保留期固定为删除后 30 天;自动清理必须幂等。
- 启动、回到前台或运行期自动清理过程中,到期任务及其任务主体历史在物理清理失败时也不得重新进入产品视图或新生成的备份,保留记录中的目标结构化引用必须先逻辑去身份化;清理待完成状态不得阻断契约允许的日常操作。

## Stop / Escalate(停止条件)

- 当前会话尚未成功初始化并完整读取核心数据库时,必须停止全部核心状态修改并进入启动数据保护态。任何试图通过删除、重建、覆盖不可读数据库或引入第二事实源来恢复可写的方案,都必须停止实现并交由产品 owner 明确决策,不得自行推断。
- 任何试图增加多窗口同时写入、强制抢占活动窗口、跨窗口合并待保存队列或持续展示只读数据镜像的方案,都超出第一版边界,必须停止并交由产品 owner 重新决策。
- 任何实现选择只要会改变用户可观察行为、导航、交互或持久化事实,放宽正式支持与验收 Gate,改变优先级、分类、拖拽、历史、恢复、30 天清理、备份或语言语义,或者新增登录、同步、服务端、遥测、运行时外部请求或设备权限,受影响任务必须停止并升级产品 owner。
- 发现权威文档冲突、现有 Gate 无法实现、数据丢失或隐私风险,或者只能通过关闭核心能力、隐藏数据、缩减平台矩阵或冻结整个产品绕过问题时,不得自行选择折中方案。只暂停受影响任务;其他边界清晰且相互独立的任务可以继续。

## Autonomy(自主边界)

### 可自主决定

- 多种方案对用户可观察行为和持久化事实完全等价时,实现者选择范围最小、最简单且符合既有代码风格的一种。
- 实现者可以决定内部模块拆分、私有命名、测试组织、算法细节、既定设计内的样式微调和不改变承诺或后果的普通微文案。
- 代码明确违反已接受契约时,实现者可以在任务包范围内直接修复并补充相称验证,无需再次询问既定行为应否成立。

### 必须技术评审

- `IndexedDB` object store、索引和 schema 迁移实现,Service Worker 缓存与版本选择,单活动窗口锁算法,新增或升级依赖及性能优化必须按任务包指定的 peer 或 architecture review 路径通过。
- 技术评审只能裁决不改变产品契约的实现方案;一旦候选方案产生不同的用户结果、数据语义、兼容承诺或故障行为,立即转为产品 owner 决策。

### 必须产品 owner 确认

- `Stop / Escalate` 所列产品行为、范围、数据、隐私、平台和可用性变化都必须由产品 owner 明确确认。
- 沉默不构成批准。确认结论必须先写入 Decision Log 并同步所有受影响的高优先级契约或目标边界,受影响实现才能恢复。
- 升级只暂停受影响任务,不得无理由冻结其他独立工作;但实现者也不得把未决部分拆成隐藏默认值、临时关闭能力或不受约束的后续事项继续推进。
