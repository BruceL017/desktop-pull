# 任务顺序契约(Task Ordering Contract)

## 强制规则

### ORDER-001 · 手动顺序是权威顺序

任务清单的默认持久顺序必须由用户拖拽决定。刷新页面或重启应用后,任务顺序必须与最后一次成功拖拽后的顺序一致。

### ORDER-002 · 优先级不改写顺序

修改任一任务的 `priority` 不得改变任何任务的持久顺序位置。

### ORDER-003 · 拖拽进入历史

只有按 `drag-interaction.md` 在有效新插入标记上放下的拖拽,才必须作为一次已提交或待保存的移动操作处理。分类不变的真实位置变化只生成 FORMAT-017 `task.reordered`,其详情必须精确符合 FORMAT-024:发生时分类与完成状态各保存一次,`beforePosition` 冻结主体移出前的直接邻居,`afterPosition` 冻结插入后的直接邻居,两处都复用 FORMAT-021 的方向严格联合。跨分类有效变化只生成 `task.category_changed`,其详情必须精确符合 FORMAT-025:状态保存一次,`source` 冻结来源分类及移出前位置,`target` 冻结不同目标分类及插入后位置,两处位置都复用 FORMAT-021 且正常可识别邻居任务 ID 跨来源与目标互异。存在邻居时冻结其 ID 与发生时标题,没有邻居时使用方向正确的开头或末尾边界;正常拖拽生产者不得生成 `unavailable`。两类事件都不得保存拖拽来源。有效插入位置只能由对应分类中主体同一完成状态的前后任务或序列边界定义,另一状态的隐藏或可见任务都不得参与任一位置计算。落回原位、无效区域松手或取消拖拽不得修改持久顺序、推进时间、产生待保存项或生成移动记录。

### ORDER-004 · 快速新增建立顶部有序分组

快速新增会话的首个任务必须占据目标分类未完成任务的顶部持久位置。同一会话的后续任务必须紧随上一条新任务,保持创建输入顺序。每次插入都必须在同一创建操作中按 FORMAT-022 冻结初始分类和插入完成后的直接前后 FORMAT-021 邻居;后续任务可以把上一条新任务作为前邻居,但不得回写上一条创建历史。该插入只确定新任务的初始手动顺序,此后仍由用户拖拽决定,旧创建位置不参与当前排序。

### ORDER-005 · 恢复只按删除定位锚点插入

任务恢复必须按 `history-retention.md` 的 `categorySnapshotAtDeletion`、任务公共 `status` 和 FORMAT-014 的严格 `previousTaskAnchor` / `nextTaskAnchor`,把目标任务插入当前持久顺序中最接近原位置的有效位置。FORMAT-027 带标题删除历史位置和任何既有 FORMAT-028 恢复结果都只供审计,即使完整也不得读取为恢复锚点。FORMAT-013 的 `UnavailableTaskRef` 与不存在、已移出目标分类或完成状态不符的任务一样是无效锚点,不得解析为原任务、边界或其他任务。恢复不得回滚整份顺序、移动任何现有任务或撤销删除后发生的拖拽;原分类或全部锚点失效时,按该契约回退到目标分类对应完成状态序列末尾。

恢复插入完成后,同一原子事务必须追加精确 FORMAT-028 `task.restored` `{ categorySnapshot, status, position }`,其中分类与位置都是实际插入结果:原 Custom 分类仍存在时使用同一标识和恢复时当前名称,已删除时使用固定 Inbox,位置只含插入后同分类同状态直接 FORMAT-021 邻居。FORMAT-028 只供审计与结果呈现,不得成为当前顺序或后来恢复的输入;后来分类改名、任务移动、状态变化或删除也不得回写它。

### ORDER-006 · 选择器改分类插入状态序列顶部

用户通过任务行或编辑器的“移动到…”选择器改变分类时,必须保持目标任务完成状态并把它插入目标分类对应状态序列顶部,只生成精确符合 FORMAT-025 的 `task.category_changed` 且不保存选择器来源。`source.position` 冻结移出前直接邻居,`target.position.previousTask` 必须是 `start`,后侧按插入后的实际邻居使用任务分支或 `end`。该操作只为目标任务建立新的持久位置,不得改变目标分类其他任务的相对顺序。选择当前分类不得重排或生成事件;用户要表达目标分类内精确位置时必须使用拖拽。

本规则不得改写 ORDER-004 的连续快速创建分组,也不得替代 ORDER-005 的恢复锚点与末尾回退语义。

### ORDER-007 · 只更新直接移动任务的修改时间

组内排序、跨分类拖拽、选择器改分类和分类删除迁移必须把每个直接改变分类或持久顺序的任务 `updatedAt` 设置为对应操作冻结的原始 `occurredAt`。移动或插入一个任务导致周围任务的相对位置被动变化时,不得仅因此改写周围任务;分类删除迁移中的每个被迁移任务都属于直接受影响任务。

原位拖拽、无效放下、选择当前分类或其他没有实际分类与顺序变化的操作不得推进任何任务的 `updatedAt`。待保存补写与应急导出必须保留原操作时间,不得使用重试、导出或数据库提交时间。

### ORDER-008 · 分类删除使用整批最终位置

删除自定义分类时,必须把来源 `taskIds` 的完整权威总顺序作为一个连续分组追加到收件箱总顺序末尾,不得按完成状态拆批。每个 FORMAT-026 迁移事件的 `source.position` 在操作前来源同状态子序列中计算,`targetPosition` 在全部任务追加完成后的最终收件箱同状态子序列中计算;事件按来源总顺序排列,位置按根 `status` 投影,两者不得混为按状态执行的逐条插入。

批次内部相对顺序不变,因此同一迁移邻居可以在来源与目标的同方向槽位重复,且最终位置可以引用同一操作中更大 `eventOrder` 的任务。FORMAT-025 的跨分类四槽位全局互异规则不适用;每个位置内部的双任务邻居仍必须不同且非主体。FORMAT-026 位置只解释历史,不得在后来读取时重放为当前顺序。

## 验收 Gate

- 拖拽任务后刷新页面和重启应用,任务仍处于拖拽后的顺序。
- 把任务从 `P5` 修改为 `P0`,该任务及其他任务的位置均不改变。
- 成功改变位置的拖拽只追加一条对应移动记录;同分类使用 `task.reordered`,跨分类使用 `task.category_changed`。
- 在同分类未完成序列 `[A, B, C, D]` 中把 `B` 移到 `C` 之后,验证只产生一条 FORMAT-024 `task.reordered`:一份发生时分类、`status: "open"`、原位置 `A / C` 和新位置 `C / D`;跨两个位置重复出现的 `C` 合法,每个位置内双任务邻居仍必须不同且非主体。
- 分别重排未完成与已完成任务,验证 FORMAT-024 只保存一次对应语言无关状态,并按 FORMAT-021 为移动前后两组相邻任务保存方向正确的边界或精确 `{ kind, taskId, title }` 发生时快照;不保存分类或状态新旧对、绝对序号、内部排序键或拖拽来源,也不把 FORMAT-014 无标题恢复锚点误作历史邻居。
- 修改、移动、换分类、切换状态或软删除历史邻居后,验证旧 FORMAT-021 任务分支与标题不变且不约束当前顺序;永久清理邻居时整个分支才原子变为精确 `{ "kind": "unavailable" }`。
- 把任务放回原位时,持久顺序、主体 `updatedAt`、历史时间线、操作顺序进度和待保存数量均不发生变化;不含 `unavailable` 的 FORMAT-024 前后位置相同 fixture 必须拒绝。
- 永久清理足以区分 FORMAT-024 前后位置的多个邻居后,验证各目标分支分别变为精确 `unavailable`;两个位置即使因此收敛也能合法往返,且历史不驱动当前顺序。
- 把未完成和已完成任务分别跨分类拖到精确中间位置,验证 FORMAT-025 只保存一次状态、来源分类与移出前位置、不同目标分类与插入后位置;四个正常邻居槽位中的可识别任务 ID 全部互异且非主体,只移动主体并更新主体时间。
- 来源同状态序列只有主体、目标同状态序列为空时执行跨分类拖拽,验证 `source.position` 与 `target.position` 都合法为 `start / end`;不得按 FORMAT-024 的位置差异规则拒绝。来源与目标分类身份相同则不得生成 FORMAT-025。
- 在同一快速新增会话依次创建 `A`、`B`、`C`,刷新后验证它们位于目标分类未完成区顶部且顺序与输入顺序一致;三条 FORMAT-022 创建位置分别冻结实际邻居,B 的前邻居为 A、C 的前邻居为 B,创建后项不回写前项且历史位置不驱动当前顺序。
- 删除任务后移动其原相邻任务并新增其他任务,再执行恢复,验证只插入被恢复任务且当前其余任务的相对顺序不变;锚点失效时使用规定末尾位置。
- 分别让原 Custom 分类保持原名、恢复前改名和恢复前删除,验证恢复只读取当前 FORMAT-014 与公共状态,并原子追加精确 FORMAT-028 实际目标、未改变状态和插入后位置;改名路径保留同一 ID 与当前名称,删除路径使用 Inbox,FORMAT-027 / FORMAT-028 均不参与落点计算。
- 恢复后继续移动任务、切换状态、重命名或删除分类,验证旧 FORMAT-028 不变且不驱动当前顺序;永久清理其中的邻居时只把对应嵌套 FORMAT-021 `task` 分支去身份化,事件仍不成为排序来源。
- 永久清理其中一个恢复锚点后验证其引用变为 `UnavailableTaskRef`;另一锚点有效时只使用另一锚点,两侧都不可用时回退到状态序列末尾,任何现有任务顺序不变。
- 通过选择器把任务改到另一分类,验证任务进入对应完成状态序列顶部,FORMAT-025 目标位置前侧为 `start`、后侧为原首项或 `end`,且其他任务相对顺序不变;选择当前分类没有归属、顺序、时间、历史、操作顺序或待保存变化,随后仍可拖拽到任意精确位置。
- 在有效落点外松手以及用各取消路径终止拖拽,验证持久顺序与历史保持原状;有效新位置放下只产生一次顺序变化和一条移动历史。
- 分别执行组内排序、跨分类拖拽、任务行选择器、编辑器选择器和分类删除迁移,验证组内只使用 `task.reordered`,跨分类拖拽与两种选择器都使用 `task.category_changed`,分类删除迁移使用 `task.moved_to_inbox_by_category_deletion`;只有每个直接移动任务的 `updatedAt` 等于原操作 `occurredAt`,界面来源不持久化,目标周围任务、原位或无效操作均不改时间,延迟补写后仍保留原值。
- 删除含混合完成状态任务的分类,验证来源权威总顺序作为一个连续批次追加到 Inbox,任务事件按该总顺序而非状态分组排列;每条 FORMAT-026 的来源位置取整批前同状态邻居,目标位置取整批后最终同状态邻居,不保存逐条插入中间位置。
- 在批次内部选择一个前后都有同状态邻居的任务,验证其 FORMAT-026 `source.position` 与 `targetPosition` 可以包含相同邻居快照;目标位置引用更晚 `eventOrder` 的批次任务仍合法,且历史位置不参与当前顺序重建。
