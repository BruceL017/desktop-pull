# PWA 交付契约(PWA Delivery Contract)

## 强制规则

### PWA-001 · 双重入口

产品必须既能作为普通响应式网页运行,也能以 PWA 形式安装到受支持的桌面或手机环境。两种入口必须使用相同的数据模型和核心功能。

### PWA-002 · 离线核心路径

应用至少成功加载一次后,断开网络并重新打开应用时,用户必须仍能创建、查看、编辑、完成、分类、拖拽、删除和恢复本地任务,并查看本地历史。

### PWA-003 · 当前设备持久化

普通网页模式和已安装模式中已经明确显示为保存成功的任务数据必须保存在当前设备。刷新页面、重启浏览器或重新打开已安装应用不得丢失已持久化数据。`degraded-availability.md` 的待保存变更只属于当前会话,必须持续提示重载风险并提供应急完整导出,不得暗示其已经跨会话保存。

### PWA-004 · 无服务端依赖

第一版核心路径不得要求登录、远程 API、云数据库或联网校验。网络不可用不得阻止本地任务操作。

### PWA-005 · 可安装元数据

交付物必须包含有效的 Web App Manifest、应用名称、图标、启动地址和独立显示配置,并提供缓存核心应用资源的离线能力。

### PWA-006 · 保留可离线回退版本

PWA 更新不得在候选版本对隔离数据库代次完成 schema 迁移、完整读取、无错误启动和原子激活前删除 last-known-good 应用资源。候选失败时必须按 `migration-rollback.md` 在联网和离线环境中清理候选工件并自动启动与旧活跃代次兼容的缓存版本。

候选成功激活后,启动器必须能确定性选择标记中的数据库代次与兼容应用资源。旧数据库代次和其他候选工件未清理前不得开放核心写入;激活或清理状态不确定时必须进入数据保护态。

### PWA-007 · 安装形态保持同一导航

普通网页与已安装 PWA 必须遵守 `navigation.md` 的同一页面结构和默认任务入口。安装形态不得缺失历史、垃圾箱、设置或备份入口,也不得用另一套移动导航改变核心信息架构。

### PWA-008 · 网页与安装形态共享单活动窗口

共享同一源站存储作用域的普通网页标签页、浏览器窗口和已安装 PWA 必须共同遵守 `single-active-window.md`。安装形态不得绕过排他控制权成为第二个数据读取者或写入者;非活动实例只显示控制权提示与“在此窗口继续”。

### PWA-009 · Service Worker 不访问核心业务数据

Service Worker 只能缓存和选择应用资源、处理离线启动,并协调不含业务记录的应用版本或数据库代次启动元数据。它不得成为活动窗口、打开核心数据库连接,或读取、缓存、修改、清理、导出任务、分类、顺序、垃圾箱、历史和草稿。

后台自动永久清理、候选数据库复制与迁移、备份和待保存补写都必须由持有 `single-active-window.md` 控制权的前台应用实例执行。Service Worker 被唤醒或更新不得绕过窗口所有权发起这些操作。

### PWA-010 · 两种语言资源均可离线使用

简体中文与英文界面资源都属于 M1 核心应用资源。应用至少成功加载一次后,断网重开必须能使用任一语言并在两者之间切换,不得因尚未联网获取另一种语言包而阻断切换或核心任务路径。

### PWA-011 · M1 正式支持矩阵

M1 发布必须通过以下正式支持矩阵:

- Windows 11:普通网页模式覆盖 Chrome、Microsoft Edge 与 Firefox;安装模式覆盖 Chrome 与 Microsoft Edge。
- macOS 当前及上一个仍受 Apple 支持的系统大版本:普通网页模式覆盖 Safari、Chrome 与 Firefox;安装模式覆盖 Chrome。
- iOS 与 iPadOS 当前及上一个仍受 Apple 支持的系统大版本:Safari 普通网页与主屏幕 Web App 都属于发布阻断项。
- Android 当前及上一个系统大版本:普通网页模式覆盖 Chrome 与 Firefox;安装模式覆盖 Chrome。

“正式支持”表示对应环境必须通过本契约与 `golden-path.md` 的非计时功能 Gate 后才能发布,不表示矩阵外环境必须被产品拒绝访问。两分钟首次用户 Gate 只在 `golden-path.md` 指定的两个参考环境执行,不得扩张为每个正式支持组合分别招募用户。

### PWA-012 · 滚动版本窗口与发布冻结

Chrome 与 Firefox 的正式支持窗口分别为发布时当前 Stable 和上一个 Stable;Microsoft Edge 为当前 Stable 和前两个 Stable;Safari 使用 PWA-011 定义的当前及上一个 Apple 支持系统与 Safari 组合。每次发布候选冻结时必须记录实际操作系统、浏览器及安装容器版本作为验收证据,不得把当时的具体版本号永久写死为后续发布合同。

### PWA-013 · 安装是增强能力

普通网页模式是所有正式支持平台的基础入口,安装 PWA 或 Web App 不得成为查看或使用 Desktop Pull 的前置条件。安装入口不可用、安装失败或用户不选择安装时,不得使同一正式支持浏览器中的普通网页核心路径不可用。

Firefox 在 Windows 或 Android 的安装模式、Safari macOS Web App、Microsoft Edge macOS 安装模式及 Chrome iOS/iPadOS 主屏幕 Web App属于兼容但不阻断 M1 发布的环境。Windows 10、Linux、ChromeOS、内嵌 WebView、应用内浏览器、隐私模式、Beta/Dev/Nightly 等预发布浏览器、Android 厂商浏览器及已经退出正式支持窗口的系统或浏览器不属于 M1 正式支持矩阵。

矩阵外环境不得仅因 User-Agent 名称或版本被硬拦截;实现必须按实际能力渐进运行。缺少核心持久化能力时仍须遵守既定启动数据保护边界,不得用临时或不可靠存储伪装成完整产品。

### PWA-014 · 存储作用域之间不自动共享数据

本地数据库属于浏览器实际提供的存储作用域。不同浏览器、浏览器配置、用户配置文件或被平台隔离的安装容器不得被假定为共享任务数据、设备界面偏好或单活动窗口所有权。

普通网页与已安装形态只有在实际访问同一源站 `IndexedDB` 时才属于同一存储作用域并共同遵守 `single-active-window.md`;平台将两者隔离时,它们是两个独立本地数据库。Desktop Pull 第一版不得在作用域之间自动复制、同步或合并数据;用户只能通过既定完整备份导出与覆盖导入迁移。安装形态形成独立作用域不得改写或删除原作用域的数据。

### PWA-015 · M1 客户端实现基线

M1 的响应式 SPA 必须使用 React 构建界面,应用源码逻辑使用 TypeScript,Vite 负责开发与生产构建,既定顶层页面导航使用 React Router。React Router 不得持有或重建任务、分类、顺序、历史、草稿及设备偏好;URL 与浏览器历史必须遵守 D-119 / NAV-013。

Vite 生产构建必须生成可以通过静态资源托管交付的客户端应用。完成核心路径不得要求业务服务端、服务端渲染、远程 API、云数据库、联网许可检查或运行时 CDN;React、React Router、两种语言资源及其他核心依赖必须进入可离线使用的应用资源。TypeScript 静态类型不得代替各数据与导入契约要求的运行时严格校验。

M1 的构建、运行与验收不得依赖 Capacitor、iOS / Android 原生工程、原生桥接或设备权限,仓库也不得为未来移动 App 预建没有当前消费者的原生或持久化适配层。未来接入 Capacitor 时必须重新验证存储迁移、生命周期、窗口所有权、备份和权限边界,不得假定浏览器 `IndexedDB` 可以直接复用。

### PWA-016 · Hash 路由静态交付

Web App Manifest 的 `start_url` 必须解析为 NAV-013 的 `APP_BASE + "#/"`,不得锁死为源站根目录。Manifest `scope` 与 Service Worker 注册 scope 必须分别解析为 `APP_BASE`;Vite 生产资源基址必须解析为 `APP_BASE`,Manifest URL 与全部生产资源 URL 必须位于 `APP_BASE` 内。部署到子路径时不得把任一 scope 扩大到源站根目录,页面、资源、安装与离线启动也不得跳回源站根目录。完全关闭已安装 PWA 后从系统入口开始的新应用会话必须进入任务清单顶部。

生产静态托管和 Service Worker 离线资源必须允许 `APP_BASE` 文档承接全部顶层 Hash 路由。Hash 后内容只由客户端解释,不得要求为 `/history`、`/trash`、`/settings`、`/backup` 配置 History API 回退重写、远程路由服务或业务服务端。完整刷新、普通网页直接打开与完全关闭后的 PWA 新会话即使携带缺失、非任务或未知 Hash,也必须由客户端在呈现顶层页面前以 `replace` 归一化到任务 Hash;M1 不承诺冷启动深链恢复。浏览器或操作系统通过 BFCache、页面冻结恢复或其他机制继续使用仍存活的同一 Document 时不得重置当前页面;只有重新创建 Document 并执行启动流程时才按冷启动规则归一化。

## 验收 Gate

- 在普通桌面和移动浏览器中完成黄金路径,页面无横向溢出。
- 在支持安装的环境中安装 PWA,从系统入口启动后完成同一黄金路径。
- 成功加载应用后断网并重新打开,核心页面可用且本地任务与历史仍存在。
- 持久化健康时,在离线状态下新增、编辑、拖拽、删除和恢复任务,刷新或重启后结果仍存在。
- 注入写事务失败后,验证离线核心界面继续可用,待保存风险与应急导出持续可见,且刷新前没有虚假保存成功状态。
- 核心路径的网络请求失败不会阻止本地操作或破坏数据。
- 在联网和断网状态分别注入候选迁移、完整读取及启动失败,验证候选工件清理后自动回退到可完整使用的缓存版本,旧活跃数据库未被改写。
- 在候选激活与旧代次清理的各中断点离线重启,验证启动器确定性选择兼容的应用与数据库;清理完成前不开写,无法确认时进入数据保护态。
- 分别在普通网页和已安装 PWA 的桌面与移动视口验证导航结构一致,默认进入任务清单且全部既定页面可达。
- 同时打开普通网页标签页、浏览器窗口和已安装 PWA,验证只有一个实例加载并操作数据;完成正常移交后新实例重新完整读取,旧实例不再展示数据或提交延迟写入。
- 检查 Service Worker 在安装、激活、离线启动、更新和后台唤醒期间的存储访问,验证它只处理应用资源与非业务启动元数据,从不打开核心数据库或执行清理、迁移、备份和待保存补写。
- 成功加载后断网重开普通网页与已安装 PWA,分别从简体中文切到英文并切回,验证两种语言资源完整可用且没有网络请求失败阻断核心路径。
- 在 PWA-012 的滚动版本窗口内冻结本次发布的实际版本,逐项执行 PWA-011 的普通网页与安装模式 Gate;任一正式支持组合失败时不得发布。
- 在 PWA-013 所列兼容但非阻断安装环境中执行冒烟验证并记录结果;失败不得破坏同一浏览器的普通网页入口,也不得把该环境伪记为正式通过。
- 使用矩阵外但具备核心能力的浏览器访问,验证没有仅基于 User-Agent 或版本的硬拦截;模拟缺少可靠 `IndexedDB` 时验证进入既定数据保护行为而非临时存储。
- 分别验证普通网页与安装形态共享及不共享 `IndexedDB` 的平台:共享时共同执行单活动窗口规则;隔离时各自保持独立数据库,不自动复制、合并或删除另一作用域的数据,且完整备份可以由用户主动迁移。
- 检查依赖清单、源码、构建配置与生产产物,验证界面由 React 构建、应用逻辑使用 TypeScript、生产构建由 Vite 生成且既定顶层页面使用 React Router;类型检查通过不替代备份、导入与持久化数据的运行时 schema 反例测试。
- 仅以生产静态产物启动普通网页并执行核心路径,验证没有业务服务端、SSR、远程 API、云数据库、联网许可或运行时 CDN 请求;首次成功加载后断网重开仍能取得 React、React Router、中英文资源及其他核心依赖。
- 检查 M1 构建、仓库与发布产物,验证不要求 Capacitor,不含作为 M1 交付物的 iOS / Android 原生工程、原生桥接、设备权限或无当前消费者的持久化适配层。
- 检查生产 Manifest、Service Worker 注册和 Vite 资源地址,验证 `start_url` 在根路径与代表性 `/desktop-pull/` 子路径部署时都解析为各自 `APP_BASE + "#/"`,Manifest `scope` 与 Service Worker 注册 scope 分别精确解析为 `APP_BASE`,Vite 生产资源基址解析为 `APP_BASE`,Manifest URL 与全部生产资源 URL 位于其中;子路径部署没有扩大到源站根 scope。完全关闭后从系统入口启动已安装 PWA 直接显示任务清单顶部。
- 仅使用不配置 History API 子路径重写的静态托管分别打开五个规范 Hash 路由,验证都取得同一应用文档;同会话导航及浏览器后退/前进遵守 NAV-013。
- 在断网缓存状态下从缺失 Hash、历史、垃圾箱、设置、备份和未知 Hash 刷新或启动完全关闭后的 PWA 新会话,验证顶层内容呈现前以 `replace` 回到任务 Hash,后退不形成循环,且无需远程路由请求;再分别通过 BFCache 与页面冻结恢复同一 Document,验证当前页面不被误重置,重新创建 Document 后才执行冷启动归一化。
