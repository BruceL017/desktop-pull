# 历史界面契约(History Interface Contract)

## 强制规则

### HISTORY-UI-001 · 单一全局入口

产品必须提供一个独立的全局历史页面,作为查看全部仍受保留规则约束的任务主体与分类主体历史的唯一事实入口。不得为各任务或分类维护相互独立的历史副本。

### HISTORY-UI-002 · 时间线顺序与内容

全局历史必须按事件 `occurredAt` 对应的当前设备本地自然日分组,日期分组从新到旧排列。每个日期内先按 `occurredAt` 从新到旧,时间相同时再按 `operationSequence` 从大到小排列;同一操作的多条事件最后按 `eventOrder` 从小到大排列。时区变化可以依据原 `occurredAt` 重新计算分组,但不得修改事件时间、操作顺序或操作内顺序。

实际数据库提交或待保存补写时间不得参与用户可见时间、日期分组或时间线排序。`operationSequence` 与 `eventOrder` 只用于得到稳定全序,不得作为用户可见编号展示。

每条默认收起的紧凑记录必须显示组内时间、按当前界面语言呈现的动作类型、主体发生时显示名称,以及同语言下可理解的简短变化摘要。任务主体事件显示事件发生时用户原文任务标题;分类主体事件显示事件发生时用户原文自定义分类名称,不得伪造或展示任务标题占位。固定收件箱、状态与其他系统概念从语言无关语义码按当前语言呈现。记录不得用任务或自定义分类的当前名称替换事件发生时快照。

### HISTORY-UI-003 · 筛选

历史页面顶部只能使用一个紧凑的“筛选”按钮承载任务、分类和动作条件,不得把三组完整控件常驻铺在时间线上方。桌面视口必须从该按钮打开紧凑浮层,移动视口必须打开底部面板;两端使用同一筛选语义。

任务和分类各自只能单选,并提供名称搜索来定位选项。选择后必须按任务或分类不可变标识匹配历史;选项搜索必须能匹配当前名称和仍保留历史中的事件发生时名称,因此改名或删除但仍有历史的对象仍可找到。任务被永久清理并移除全部任务主体历史后,不得继续显示为无结果选项;已删除分类只要仍有分类主体历史或按本契约归入该分类的任务历史,就必须继续作为可搜索分类选项。

任务条件只匹配以该任务为主体的事件,纯分类主体事件必须排除。分类条件必须同时支持匹配以该分类为主体的管理事件和归入该分类的任务主体事件,不得因为分类不是任务事件的主体而漏掉任务历史。

任务事件只涉及一个分类时匹配该分类;其中 `task.created`、`task.content_changed`、`task.completed`、`task.reopened`、`task.priority_changed`、`task.reordered` 与 `task.trashed` 必须分别从 FORMAT-022 / FORMAT-019 / FORMAT-020 / FORMAT-023 / FORMAT-024 / FORMAT-027 的发生时 `categorySnapshot` 匹配,不得查询任务当前归属。发生时分类后来改名或删除也不得改变既有事件的筛选结果。`task.category_changed` 必须精确按 FORMAT-025 的 `target.categorySnapshot` 匹配目标分类,不得同时按 `source.categorySnapshot` 匹配来源分类。任务从分类 A 移到分类 B 后,该移动只出现在分类 B 的筛选结果中;分类删除导致任务迁入收件箱时,FORMAT-026 逐任务移动事件只匹配固定收件箱且不得按 `source.categorySnapshot` 匹配被删分类,分类删除主体事件仍只匹配被删除分类。FORMAT-027 软删除只匹配删除时分类,不得因任务进入垃圾箱或后来恢复而改按垃圾箱、恢复后分类或当前分类匹配。来源自定义分类的标识与用户原文名称快照必须继续保留用于摘要和展开;来源是固定收件箱时保留稳定系统身份并按当前语言呈现。两者都不得因此成为来源分类筛选匹配条件,也不得从任务后来当前归属、状态或顺序补算筛选结果。

`task.restored` 必须只按 FORMAT-028 的实际恢复目标 `categorySnapshot` 匹配。原 Custom 分类仍存在但已改名时按同一 ID 及恢复时当前名称归入该分类,原分类已删除时只归入固定 Inbox;不得按 FORMAT-027 删除时分类、FORMAT-014 生命周期、垃圾箱、锚点路径或任务后来当前归属匹配。

动作类型允许多选。任务、分类和动作三个维度之间必须按“且”组合,多个已选动作之间必须按“或”组合;某一维度未选择时不限制该维度。每次选择或移除条件必须立即更新结果,不得要求点击“应用”或关闭面板才生效。筛选后的日期分组与事件仍按 HISTORY-UI-002 排序。

当前条件必须以可单独移除的紧凑标签显示,并提供一次清除全部条件的操作。筛选状态只在当前应用会话内保留:切换页面后返回历史仍恢复,刷新或彻底重开应用后清空,且不得进入完整备份。

### HISTORY-UI-004 · 任务预筛选

从任务编辑器进入历史时,必须打开同一全局历史页面并自动应用当前任务筛选,不得打开第二套任务历史界面。进入前必须按 `task-editing.md` 立即提交或排队当前任务尚未自动保存的最新有效内容。

这次明确的“查看历史”操作必须用当前任务筛选替换历史页此前保留的全部任务、分类和动作条件,进入后只能保留一个“任务:当前任务标题”条件标签,并按任务不可变标识显示该任务的完整任务主体时间线。纯分类主体事件不得进入结果。不得让旧条件在不可见处继续限制结果,也不得保留一套隐藏的旧筛选栈。

进入历史后,用户可以继续添加分类或动作条件、移除当前任务条件或改选其他任务;这些操作直接成为 HISTORY-UI-003 定义的当前会话筛选状态。返回任务页时按 `navigation.md` 恢复浏览上下文,但不得自动重开任务编辑器。

### HISTORY-UI-004A · 分类改名或删除不切断历史

分类筛选必须使用分类不可变标识关联事件。`category.renamed`、`category.reordered` 与 `category.deleted` 都只按公共 `subject.categoryId` 匹配;改名事件的名称搜索必须同时匹配 FORMAT-030 `details.beforeName` 与公共 `subject.name`,排序事件的名称搜索必须匹配 FORMAT-031 公共主体及 `beforePosition` / `afterPosition` 中实际存在的发生时邻居名称,但邻居分类不得因此成为该排序事件的分类筛选命中;删除事件只以 FORMAT-032 公共主体名称命中搜索,`affectedTaskCount` 不形成任务或分类筛选。自定义分类重命名后,选择该分类必须同时返回改名前后的分类管理事件及按 HISTORY-UI-003 归入该分类的任务事件;每条既有事件摘要仍须显示事件发生时记录的分类名称,不得用当前名称回写旧摘要。分类删除后,该分类仍必须能通过保留历史中的当前或曾用名称搜索并返回保留事件,不得依赖已经不存在的当前分类记录、当前 `categoryOrder`、后来事件或历史重放补全选项、邻居与摘要。

### HISTORY-UI-005 · 垃圾箱独立

垃圾箱必须使用独立页面。历史页面只读且不得提供恢复操作;尚在 30 天可恢复期内的删除任务只能从垃圾箱恢复。

### HISTORY-UI-006 · 原地展开完整事实

除下述 FORMAT-029 空详情例外外,用户点击历史记录时,必须在当前时间线位置原地展开由 FORMAT-018 事件专属 `details` 保存的精确事实;长标题、备注换行和其他完整值不得因默认摘要截断而在展开内容中丢失。对于 `task.created`,必须从 FORMAT-022 显示 `subject.title`、发生时初始分类和创建完成后的前后邻居位置,不得显示快速入口、默认字段、草稿代次、提交键或当前重算位置。对于 `task.content_changed`,必须同时读取 FORMAT-019 定义的保存后 `subject.title` 和精确详情字段:标题变化显示 `beforeTitle` 到 `subject.title`,备注变化显示 `beforeNotes` 到 `afterNotes`,两者变化时同时显示两组,并显示发生时 `categorySnapshot` 对应分类。对于 `task.completed` 与 `task.reopened`,展开显示 FORMAT-020 的发生时分类,状态方向继续由精确事件类型呈现,不得伪造状态新旧字段。对于 `task.priority_changed`,必须从 FORMAT-023 显示发生时分类及 `beforePriority` 到 `afterPriority` 的精确方向,不得显示控件来源、位置或后来当前优先级。对于 `task.reordered`,必须从 FORMAT-024 显示发生时分类、`open | completed` 对应状态区以及完整 `beforePosition` 到 `afterPosition`,不得把分类或状态伪造成新旧对。对于 `task.category_changed`,必须从 FORMAT-025 显示根部一次 `status` 对应状态区、`source.categorySnapshot` 与移出前完整 `source.position`,以及 `target.categorySnapshot` 与插入后完整 `target.position`;不得把来源位置省略成当前重算值,也不得把状态复制到两侧。对于 `task.moved_to_inbox_by_category_deletion`,必须从 FORMAT-026 显示根部一次状态、来源被删 Custom 快照与整批前完整位置、以及整批完成后的最终 Inbox 位置;不得显示目标快照或把任务事件顺序解释成逐项插入。对于 `task.trashed`,必须从 FORMAT-027 显示删除时分类、一次状态及移出前完整位置;删除时间继续取公共 `occurredAt`,标题取公共 `subject.title`,不得显示内容、优先级、到期时间、恢复锚点、确认或界面来源。展开不得从当前任务或分类记录补全后来可能已变化的归属、状态、标题或顺序事实,也不得依赖完整实体快照。再次点击可以收起。

对于 `category.created`,必须从公共分类 `subject` 显示和筛选创建时 ID 与用户原文名称,FORMAT-029 `details` 必须存在且精确为 `{}`;含本地化动作和 `subject.name` 的紧凑行已经是完整可见事实。点击不得打开空白详情面板或显示原始 `{}`;若统一组件仍展开,只能显示公共外壳与分类主体中已经存在的事实,不得从当前分类、当前 `categoryOrder` 和历史重放补出位置、入口、设备、语言、任务关系及分类记录副本。

对于 `category.renamed`,必须从 D-115 / FORMAT-030 精确显示 `details.beforeName` 到公共 `subject.name` 的方向:前者是改名前保存的用户原文,后者是改名后保存的用户原文,两者必须不同。紧凑摘要和展开都不得读取当前分类、当前 `categoryOrder`、后来事件或历史重放补值,也不得显示或要求 `afterName`、分类记录、任务、数量、位置、相邻分类、排序键、入口、设备、语言或通用整实体新旧包。

对于 `category.reordered`,必须从 D-116 / FORMAT-031 精确显示公共分类主体及 `details.beforePosition` 到 `details.afterPosition`:每个位置都只含严格的 `previousCategory` 与 `nextCategory`,前者只接受 `start | category`,后者只接受 `end | category`;`category` 分支只显示发生时 Custom 分类 ID / 用户原文名称,Inbox 永不显示为邻居。紧凑摘要只从 `afterPosition` 表达移到 Custom 序列顶部、末尾或某个前邻居之后,展开显示完整前后两侧。不得显示或要求 `unavailable`、绝对索引、内部排序键、当前顺序、拖拽来源、设备、语言、任务、完整分类记录或通用整实体新旧包,也不得读取当前分类、当前 `categoryOrder`、后来事件或历史重放补值。

对于 `category.deleted`,必须从 D-117 / FORMAT-032 精确显示公共分类主体与 `details.affectedTaskCount`。紧凑摘要表达删除该分类并将 N 个任务移到固定 Inbox,展开只补充同一发生时数量事实;N 为 `0` 时必须明确表示没有任务被移动,不得显示成未知、隐藏数量或打开空白面板。界面不得列出或推断任务 ID/标题、按状态拆分数量、位置、确认、草稿、原因或后来当前状态;任务永久清理后仍显示原 N,不得按剩余 FORMAT-026 事件数量回写。

对于 `task.restored`,必须从 FORMAT-028 显示实际恢复目标分类、一次 `open | completed` 状态及插入完成后的完整 `position`;不得显示删除时分类、生命周期、恢复锚点、锚点命中或回退原因、30 天信息、界面来源、绝对位置或内部排序值。展开不得读取当前 FORMAT-014、FORMAT-027、当前任务顺序或后来事实补值。

展开不得打开弹窗、独立详情页、任务编辑器或垃圾箱,也不得提供编辑、撤销、回滚、恢复或删除历史的操作。展开与收起只改变临时界面状态,不得修改任务、分类、历史或追加新事件。

### HISTORY-UI-007 · 动作筛选使用八个稳定分组

动作多选只能显示八个稳定语义分组。简体中文资源为 `创建`、`内容编辑`、`完成状态`、`优先级`、`移动与归类`、`删除`、`恢复`、`分类管理`;英文界面必须从同一组语言无关语义显示对应英文。筛选必须按 FORMAT-017 / HIST-004 对 14 个精确事件类型的一对一分组映射执行,不得把显示文案当作筛选值或把底层类型逐项铺成更长的筛选列表。`category.created`、`category.renamed`、`category.reordered` 与 `category.deleted` 都只属于“分类管理”,前者不得因显示动作含“创建”而进入任务“创建”组,分类删除也不得进入任务“删除”组。

时间线紧凑行和展开内容仍必须按当前界面语言显示可理解的精确子类型。简体中文示例为“创建任务”、“标记完成”与“重新打开”、“将优先级从 P3 改为 P1”、“组内排序”与“跨分类移动”、“创建分类”、“重命名分类”、“调整分类顺序”与“删除分类”;不得只显示动作组名称而隐藏实际操作。`task.created` 从 FORMAT-022 的初始分类及嵌套位置生成创建摘要,系统边界按当前语言呈现而用户原文邻居标题不翻译。`task.content_changed` 的精确显示必须由 FORMAT-019 除共有 `categorySnapshot` 外的三个严格变化字段集合区分修改标题、修改备注或同时修改两者,不要求也不允许为三种显示新建额外 `eventType`、`changedFields` 或根级详情判别。标题新值只能读取发生时 `subject.title`,不得从当前任务或不存在的 `afterTitle` 补值。`task.completed` 与 `task.reopened` 只按事件类型区分精确动作,不得从 FORMAT-020 快照或当前状态推断方向。`task.priority_changed` 的方向只从 FORMAT-023 的不同旧新值生成,P0 至 P5 保持语言无关代码,不得读取当前任务或持久化本地化优先级标签。`task.reordered` 必须从 FORMAT-024 的一份分类、一份状态和移动后位置生成组内排序摘要,不得读取当前顺序或显示拖拽手势来源。`task.category_changed` 必须从 FORMAT-025 的发生时来源、目标分类和根部一次状态生成“从 A 移到 B”摘要,并且只能从 `target.position` 补充目标落点;不得用 `source.position` 生成摘要落点、读取当前状态或显示选择器、拖拽等界面来源。`task.moved_to_inbox_by_category_deletion` 必须从 FORMAT-026 生成“因删除「来源分类」移到收件箱”的精确摘要,并且只从最终 `targetPosition` 补充目标落点;不得显示确认、草稿、批次实现或逐项插入来源。`task.trashed` 必须从 FORMAT-027 生成“从「分类」的未完成/已完成区移入垃圾箱”的精确摘要;紧凑行不必列出删除前邻居,展开时才显示完整 `position`,不得显示确认入口、30 天规则说明或恢复操作。`category.renamed` 必须从 FORMAT-030 的 `beforeName` 与公共 `subject.name` 生成“从 A 重命名为 B”摘要,动作按当前语言呈现而 A / B 保留用户原文。`category.reordered` 必须从 FORMAT-031 的 `afterPosition` 生成移到 Custom 序列顶部、末尾或某个发生时前邻居之后的摘要,动作与边界本地化而主体和邻居名称保持原文。`category.deleted` 必须从 FORMAT-032 公共主体、原始计数和固定 Inbox 生成删除并移动 N 个任务的摘要;N 为 `0` 时显示明确零结果,不得从当前任务或剩余迁移事件补数。

`task.restored` 必须从 FORMAT-028 生成“恢复到「实际分类」的未完成/已完成区”摘要,并且只从插入后 `position` 补充落点;该事件只进入“恢复”动作组,不得从删除现场或当前状态生成摘要。

### HISTORY-UI-008 · 移动历史使用相对位置语言

创建任务的紧凑摘要必须按当前界面语言表达初始分类;需要位置补充时从 FORMAT-022 的创建后 `position` 生成顶部、末尾或相邻任务语义,不得显示快速入口或绝对序号。任务组内移动的紧凑摘要必须从 FORMAT-024 按当前界面语言表达“在「分类」的未完成/已完成区移到顶部/末尾”或“在「分类」的对应状态区移到「相邻任务」之后”的语义。若合法去身份化使移动后位置无法再判定顶部、末尾或具体相邻任务,摘要必须降级为中性的“在「分类」的未完成/已完成区调整顺序”,展开仍逐侧显示通用“不可用”;不得读取当前顺序补全或伪造边界。FORMAT-025 跨分类移动必须先从两侧发生时分类快照表达“从「原分类」移到「目标分类」”,再且只按 `target.position` 补充顶部、末尾或相邻任务。目标同状态序列为空、即 `target.position` 为 `start / end` 时只表达移入目标分类,不得同时声称位于顶部和末尾;合法去身份化使目标位置不能再可靠表达具体落点时,摘要只保留中性的“从「原分类」移到「目标分类」”,展开继续逐槽显示通用“不可用”,不得读取当前顺序、状态或邻居补全。选择当前分类属于无操作,不得生成 `task.category_changed` 或任何历史摘要。显示文案必须从语言无关位置边界生成。 FORMAT-026 派生迁移必须先从来源快照与固定目标表达“因删除「来源分类」移到收件箱”,再且只按整批后的 `targetPosition` 补充最终落点;目标位置因合法去身份化无法可靠表达时只保留该中性摘要,不得查询当前 Inbox 顺序补全。 FORMAT-027 软删除紧凑摘要只表达从发生时分类和状态区移入垃圾箱;展开显示移出前完整位置。位置去身份化后仍保留分类、状态和中性删除摘要,不得查询当前顺序或生命周期补回邻居。

FORMAT-028 恢复紧凑摘要只表达恢复到实际分类及状态区,再且只按插入后的 `position` 补充落点。位置去身份化后保留中性恢复摘要;不得查询当前顺序、删除时位置、生命周期或恢复锚点补回邻居。

正常业务事件生产不得生成 `unavailable`:没有邻居时必须显示对应的顶部或末尾边界,存在邻居时必须显示发生时任务标题。FORMAT-025 正常生产的 `source.position` 与 `target.position` 四个邻居槽位中,所有仍为 `task` 的可识别 ID 必须跨两侧两两不同且都不是主体。相邻任务被永久清理或进入清理待完成逻辑投影后,对应整个 `task` 分支必须原子替换为精确 `{ "kind": "unavailable" }`,并只显示当前语言下的通用“不可用”语义;不得保留或猜测原任务标识与标题,也不得把不可用伪装成边界或另一任务。FORMAT-026 每个位置内部同样要求可识别 ID 不同且非主体,但同一批次邻居在来源与目标同方向重复合法且必须显示为同一发生时任务;不得套用 FORMAT-025 的跨侧互异规则。多个分支被合法去身份化后,FORMAT-025 两侧位置、FORMAT-026 的来源与最终位置和 FORMAT-027 删除前位置允许出现重复 `unavailable` 并在结构上收敛,界面不得误判为无操作或读取当前状态补值;FORMAT-026 同一邻居被清理时全部出现槽位必须一起显示不可用,不得只隐藏一侧。FORMAT-021 只用于解释历史审计上下文,不得用于读取当前顺序、生成拖拽落点或恢复垃圾箱任务;FORMAT-014 的恢复锚点是另一种不含标题的定位引用,界面不得在两者之间补写或复制字段。FORMAT-027 即使与当前垃圾箱锚点同时存在也不显示恢复控件或成为恢复来源。

FORMAT-028 正常 `position` 内可识别邻居必须不同且非主体;永久清理或逻辑投影逐处去身份化嵌套任务分支后仍保留恢复事件。FORMAT-028 只解释本次恢复结果,即使与当前任务位置相同也不得被界面用作排序或恢复来源,后来变化也不得触发重算。

### HISTORY-UI-009 · 自动清理待完成时不泄漏到期任务

启动、回到前台或运行期自动到期清理事务失败并进入 AVAIL-016 的清理待完成态时,历史页面不得显示、搜索、筛选、计数或通过直接链接访问任何被逻辑排除任务的任务主体事件。任务筛选选项中不得保留该任务,任何动作或分类筛选也不得使其重新出现。

不携带该任务身份的独立分类主体事件继续按既定规则显示和筛选。其他保留任务事件中的目标 FORMAT-021 结构化邻居引用必须把整个 `task` 分支逻辑投影为精确 `{ "kind": "unavailable" }`,显示通用“不可用”语义且不得作为任务搜索或筛选选项。历史页面不得通过残留 `taskId`、`title`、空占位、已清理标题、事件数量或其他衍生信息泄露被排除任务的任务事实链。

- 跨多个自然日产生多种任务与分类变更后,验证日期分组与组内事件均最新在前,且每条紧凑记录包含时间、动作、对应主体发生时名称和变化摘要。
