# 任务内容契约(Task Content Contract)

## 强制规则

### CONTENT-001 · 标题必填

每个持久化任务必须有标题。去除首尾空白后不含任何字符的标题不得保存为任务。

### CONTENT-002 · 备注可选

任务可以不含备注。快速新增不得要求或展示备注输入;用户创建任务后可以在任务编辑器中填写、修改或清空备注。

### CONTENT-003 · 第一版字段边界

第一版任务内容不得加入截止日期、提醒、重复规则、子任务或附件。

### CONTENT-004 · 标题不是任务身份

任务必须在创建时取得符合 `backup-format.md` FORMAT-011 的规范小写 UUID v4,并以该不可变唯一标识贯穿当前状态、顺序、垃圾箱、历史和完整备份;不得在导出或导入时生成替代身份。标题不要求唯一;用户重新输入与现有任务完全相同的标题并再次提交时,必须创建另一条独立任务,不得按标题拒绝、合并或覆盖。

### CONTENT-005 · 未提交标题不是任务

快速入口中尚未提交的标题只属于草稿。它不得获得任务唯一标识、进入任务清单、占据持久顺序或追加历史;只有成功提交后才成为任务内容。

### CONTENT-006 · 已有任务内容自动保存

任务编辑器中的标题和备注必须自动保存,不得要求用户点击额外的“保存”或“完成”按钮才能持久化有效修改。标题仍必须满足 CONTENT-001;不合法的标题不得覆盖当前已持久化任务标题。

每次实际保存必须按 `state-history-consistency.md` 原子更新任务当前状态并追加对应 FORMAT-017 `task.content_changed`,其主体和详情必须精确符合 FORMAT-019。自动保存原则不得改变优先级、分类和删除各自已有的交互与确认规则。

### CONTENT-007 · 自动保存触发与历史粒度

用户连续编辑标题或备注时,每次输入都必须把自动保存计时重新推迟;停止输入约 `600ms` 后,必须对当前有效内容发起一次原子保存。一次连续输入片段不得按字符分别写入任务状态或历史。

标题或备注失焦、桌面侧栏关闭、移动端返回任务清单或应用进入后台时,必须立即尝试保存尚未提交的最新有效内容,不得继续等待剩余计时。若正式写入失败,必须按 `degraded-availability.md` 进入待保存机制,不得伪装保存成功。

每次成功保存有实际内容变化时必须追加且只追加一条 `task.content_changed`;只改标题、只改备注和同一次保存同时修改两者都使用该类型,并按 FORMAT-019 分别精确形成 `{ categorySnapshot, beforeTitle }`、`{ categorySnapshot, beforeNotes, afterNotes }` 或 `{ categorySnapshot, beforeTitle, beforeNotes, afterNotes }`。共有的 `categorySnapshot` 必须是保存操作被接受时任务当前分类的 FORMAT-012 快照;内容保存不改变分类,且不得在稍后自动重试时按后来归属重算。事件 `subject.title` 必须是本次保存后的有效标题;标题旧值只进入 `beforeTitle`,不得在 `details` 中重复保存 `afterTitle`。不得为字段组合新增类型、拆成多条事件或增加 `changedFields`、根级 `kind` 或其他判别字段。与当前持久化内容相同的保存尝试不得改变状态或追加历史。

### CONTENT-008 · 空标题只阻止标题保存

已有任务的标题输入为空或去除首尾空白后为空时,编辑器必须立即在标题输入位置显示错误并暂停该标题的自动保存。无效标题不得覆盖最后一次有效持久化标题,不得生成标题历史,也不得触发任务删除或保存为“无标题任务”。

无效标题不得阻止备注、优先级或分类等其他有效修改按各自规则保存,也不得阻止用户关闭桌面侧栏或从移动端返回。用户离开编辑器时必须放弃该无效标题输入;再次打开任务时显示最后一次有效标题。

用户在离开前重新输入有效标题时,行内错误必须消失,并从最新输入重新执行 CONTENT-007 的自动保存计时。

### CONTENT-009 · 备注为多行纯文本

第一版任务备注必须保存为保留换行的纯文本。编辑器必须允许输入、修改和清空多行内容,自动保存、历史摘要、备份导出与导入均不得丢失或改变原有换行。

第一版不得提供富文本格式、Markdown 渲染、内嵌清单、附件或图片。备注中的符号和 Markdown 样式字符必须按普通文本保存,不得隐式转换成另一种内容结构。

### CONTENT-010 · 清单只显示一行备注预览

任务备注非空时,主任务清单必须在任务标题下方显示一行视觉弱化的纯文本预览;超出可用宽度的内容必须省略,不得展开多行或撑开为完整备注。完整备注只能在任务编辑器中查看和编辑。

任务备注为空时不得显示占位文案或为预览预留高度。预览只读取备注内容,不得改变原始文本或换行,也不得提供独立点击、展开或编辑行为。

### CONTENT-011 · 删除前保留最新有效编辑

用户在编辑器中存在尚未自动保存的有效标题或备注时发起“删除任务”,必须先立即保存该编辑或按 `degraded-availability.md` 将其作为独立操作排入待保存队列,再进入删除确认。不得因发起、取消或确认删除而丢弃、回退或合并这项有效编辑。

删除确认必须使用任务的最新有效标题标识目标;若当前标题输入无效,必须使用最后一次有效标题。确认删除后,内容编辑必须先于软删除提交和记录历史;垃圾箱及随后恢复的任务必须包含最新有效内容。

### CONTENT-012 · 清单标题最多显示两行

主任务清单中的任务标题必须最多显示两行,超出部分以省略方式隐藏;该限制只作用于清单展示,不得截断或改写持久化标题。完整标题必须能在任务编辑器中查看和修改,历史与备份也必须保留完整值。

普通文本必须在可用宽度内正常换行,连续超长字符也必须允许断行,不得导致任务行或页面横向滚动。标题区域继续属于任务行非控件区域,不得因换行或省略产生独立展开控件。

### CONTENT-013 · 持久化内容保留原文且备注不为空值

标题校验只能用去除首尾空白后的结果判断是否至少含一个非空白字符;合法标题的持久化值必须保留用户提交原文,不得把校验结果写回任务。备注在任务记录中始终是字符串:没有备注或用户清空备注时保存精确 `""`,不得省略或使用 `null`;非空备注逐字保留原文与换行。

创建时任务 `createdAt` 与 `updatedAt` 必须同时取创建操作冻结的 `occurredAt`。标题或备注实际改变时,同一原子保存必须把该任务 `updatedAt` 更新为该内容编辑操作的原始 `occurredAt`;无变化保存和自动保存计时本身不得推进时间,待保存重试不得改用重试或提交时间。

## 验收 Gate

- 输入有效标题且不填写备注可以成功新增任务。
- 空标题或只含空白的标题不能创建任务。
- 快速新增界面不显示备注输入;创建后用户可以新增、修改和清空任务备注。
- 第一版创建和编辑界面不出现截止日期、提醒、重复任务、子任务或附件入口。
- 连续两次主动输入并提交相同标题,验证产生两条具有不同唯一标识的独立任务和两条创建历史。
- 验证新任务从创建事务起即使用规范小写 UUID v4,其当前状态、顺序、垃圾箱、历史和备份引用逐字一致;导出、导入或恢复不得更换标识。
- 输入并保留未提交草稿,验证任务数据、顺序和历史均未发生变化。
- 在任务编辑器中修改为有效标题或修改、清空备注,验证无需点击保存按钮即可持久化并产生对应历史。
- 尝试把已有任务标题改为空白,验证无效内容不会覆盖当前持久化标题;优先级、分类与删除仍遵守各自独立规则。
- 连续输入多个字符且每次间隔小于约 `600ms`,验证停止后只执行一次状态保存并只追加一条编辑历史,不存在逐字符历史。
- 在计时结束前分别让字段失焦、关闭桌面侧栏、从移动端返回和让应用进入后台,验证每种情况都立即尝试保存最新有效内容。
- 分别只改标题、只改备注和让两者在同一自动保存批次中变化,验证每次只产生一条 `task.content_changed`,且精确形成 FORMAT-019 的二、三、四个字段分支;每个分支都有保存操作接受时的合法 `categorySnapshot`,标题变化时 `subject.title` 为新标题并与 `beforeTitle` 不同,备注变化时新旧备注不同且空字符串和换行逐字保留。缺失或非法分类快照、空对象、部分备注对、相等新旧值、`afterTitle`、`changedFields`、根级 `kind`、`null` 及未知或额外字段均拒绝。操作后移动任务或改名、删除分类,验证既有快照和分类筛选不变;重复保存相同内容时状态和历史不变化。
- 注入自动保存事务失败,验证修改进入全局待保存机制且界面不显示已经安全保存。
- 清空已有任务标题后等待超过 `600ms`,验证标题输入就地报错且持久化标题和历史不变;重新输入有效标题后验证错误消失并恢复自动保存。
- 标题无效期间分别修改备注、优先级和分类,验证这些有效修改仍独立保存;关闭侧栏或移动端返回不受阻,再次打开时标题恢复为最后一次有效值。
- 在空标题状态离开编辑器,验证任务没有被删除、没有被改成“无标题任务”且没有产生标题历史。
- 输入包含多个换行和 Markdown 样式字符的备注,验证编辑、自动保存、历史、导出及导入后文本和换行保持一致,且没有被渲染或转换为富文本结构。
- 检查第一版任务编辑器,验证不存在富文本工具栏、内嵌清单、附件或图片入口。
- 分别显示无备注、短备注和多行长备注任务,验证无备注不占预览空间,有备注只显示一行弱化预览并在超宽时省略,完整原文仍可在编辑器查看。
- 点击或拖动备注预览区域,验证其行为与任务行其他非控件区域一致,不会单独展开或编辑备注。
- 在 `600ms` 计时结束前修改有效内容并立即发起删除,验证编辑先保存或排队,确认弹窗显示最新有效标题,确认后历史顺序为编辑在前、删除在后。
- 在上述场景取消删除,验证编辑仍按自动保存规则保留;确认并随后恢复任务,验证恢复内容包含删除前最新有效编辑。
- 分别使用超过两行的普通标题和连续超长字符标题,验证清单最多显示两行并省略,页面无横向滚动,编辑器、历史和备份仍保留完整标题。
- 从换行标题的任一可见位置点击或拖动,验证仍按任务行非控件区域打开编辑器或移动任务,没有独立展开行为。
- 创建含首尾空白的合法标题,验证校验通过且持久化、历史与备份逐字保留原文;创建无备注任务和清空备注后验证任务记录都保存精确 `""`,不出现缺失字段或 `null`。
- 创建和实际编辑内容时验证 `createdAt` / `updatedAt` 使用对应操作冻结时间;重复保存相同内容和待保存重试不推进 `updatedAt`。
