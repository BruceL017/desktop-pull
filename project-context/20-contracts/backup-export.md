# 完整备份导出契约

## 强制规则

### EXPORT-001 · 完整数据范围

每份完整备份必须包含导出时仍在逻辑保留范围内的任务、分类、持久顺序、垃圾箱状态及其恢复定位与删除时分类语义快照、全部保留中的任务主体和分类主体历史及其用户原文快照、语言无关系统语义、各事件实际存在的精确字段事实、`occurredAt`、`operationSequence` 与 `eventOrder`、`data.meta.nextOperationSequence`,以及全部非空快速创建草稿。每条历史必须精确符合 FORMAT-016 七字段公共外壳,以严格 `subject` 分支表达发生时主体,使用 FORMAT-017 的 14 个 `eventType` 之一、FORMAT-018 的事件专属最小 `details` 和 `(operationSequence, eventOrder)` 唯一稳定逻辑键;`task.created` 必须精确符合 FORMAT-022,原样导出初始 `categorySnapshot` 与创建完成后的嵌套 `position`,不得导出入口、草稿代次、提交键、默认字段或按当前顺序重算;`task.content_changed` 还必须精确符合 FORMAT-019,以保存后 `subject.title` 表达标题新值并保留发生时 `categorySnapshot`,且不得重复导出 `afterTitle`;`task.completed` 与 `task.reopened` 必须精确符合 FORMAT-020,只导出发生时分类快照而不重复状态方向;`task.priority_changed` 必须精确符合 FORMAT-023,逐值导出发生时分类和不同的旧、新优先级,不得导出位置、排序键或控件来源;`task.reordered` 必须精确符合 FORMAT-024,逐值导出一份发生时分类、一份 `open | completed` 状态及严格移动前后位置,不得导出分类或状态新旧对、拖拽来源、绝对索引、内部排序键或当前顺序副本;`task.category_changed` 必须精确符合 FORMAT-025,逐值导出一份 `open | completed` 状态以及严格 `source` / `target`,两侧各只含发生时 `categorySnapshot` 与嵌套 `position`,分类引用必须不同,来源位置冻结移出前邻居,目标位置冻结插入后同状态邻居。正常未清理事件四个槽位中的可识别任务 ID 必须跨槽两两不同且非主体,正常生产不得生成 `unavailable`;来源与目标位置结构相同仍可合法,不得套用 FORMAT-024 的差异约束。不得导出状态副本、分类或状态新旧对、平铺位置、拖拽/任务行/编辑器/新建分类入口、绝对索引、内部排序键或当前顺序副本。`task.moved_to_inbox_by_category_deletion` 必须精确符合 FORMAT-026,逐值导出根部一份不变状态、`source` 的被删 Custom 快照与整批前位置、以及整批完成后的最终 `targetPosition`;固定目标 Inbox 不得另存快照。事件按来源权威总顺序保留,最终位置可以引用更大 `eventOrder` 的批次任务;同一批次邻居可以在来源与目标同方向重复,每个位置内部仍必须身份不同且非主体。`task.trashed` 必须精确符合 FORMAT-027,逐值导出删除时 `categorySnapshot`、一份 `open | completed` 状态与移出前同状态 `position`;不得导出删除/到期时间、生命周期、恢复锚点、标题/内容/优先级副本、原因、确认/UI/设备、绝对索引、内部顺序或当前顺序。`task.restored` 必须精确符合 FORMAT-028,逐值导出恢复事务完成后的实际 `categorySnapshot`、未改变的 `status` 与插入后同状态 `position`;原 Custom 分类仍存在时快照使用同一 ID 和恢复时当前名称,已删除时使用 Inbox 快照。不得导出删除上下文、生命周期、锚点、锚点命中或回退原因、30 天字段、UI/设备来源、绝对索引、内部排序值或当前顺序。`category.created` 必须精确符合 FORMAT-029,只导出分类公共 `subject` 中的创建时 ID / 名称及必填精确空对象 `details: {}`,不得在详情中复制身份、名称、分类位置、入口、关联任务或其他字段;主清单创建只产生 `eventOrder = 0` 的该事件,选择器创建并归类在任务主体仍保留时导出 `category.created(eventOrder = 0)` 后的 FORMAT-025 `task.category_changed(eventOrder = 1)`,且两者目标分类身份逐字一致。关联任务后来永久清理或在导出逻辑状态中到期时,任务主体历史必须排除而独立分类创建事件仍以原 `eventOrder = 0` 保留;不得补建任务事件,反向孤立的 `task.category_changed(eventOrder = 1)` 不得导出。`category.renamed` 必须精确符合 FORMAT-030:公共 `subject` 只保存同一分类 ID 与改名后用户原文名称,必填 `details` 精确只含改名前存储的用户原文 `beforeName`,且 `beforeName` 必须与 `subject.name` 不同;不得导出 `afterName`、分类身份副本、位置、顺序、任务、入口、UI、完整分类记录或其他字段。同一有效当前名称不形成事件;后续改名、排序或删除不回写旧事件,任务永久清理不影响这个无任务引用的独立分类事件。事件 schema 已声明的每个历史任务邻居字段还必须逐值导出 FORMAT-021 的方向边界、发生时 `task` 快照或合法 `unavailable`;`task` 分支的 `taskId` 与 `title` 都不得从当前顺序、当前分类、当前状态或当前标题重算,邻居后来改标题、移动、换分类、完成或软删除也不得回写。不得导出独立事件 ID、动作组、本地化摘要、界面入口、手势来源、根级 `details.kind`、完整实体快照或通用整实体新旧包。草稿必须精确保留 FORMAT-015 的入口、当前代次、标题原文与 UTF-16 光标偏移,目标分类只从入口推导,且不得转换为任务或历史。已删除分类的分类主体历史也必须进入备份;已达到 `expiresAt` 且仍为软删除的任务及其任务主体历史必须排除,保留记录中指向这些目标的结构化任务引用必须按 FORMAT-013 物化为 `UnavailableTaskRef`;多个邻居去身份化使 FORMAT-024 前后位置收敛时仍须保留该合法事件,FORMAT-025 的任一合法任务邻居投影为不可用或两侧位置因此相同也不得删除事件;FORMAT-026 同一邻居跨两侧重复时必须投影全部出现槽位,迁移主体永久清理后允许任务事件少于分类事件原受影响数量且保留 `eventOrder` 缺口。FORMAT-027 与 FORMAT-028 邻居投影都只改各自整个历史任务分支;同一目标仍存在于 FORMAT-014 恢复锚点时按无标题联合独立投影,不得串型。除此之外不得因对象已删除、记录时间或数量省略数据。FORMAT-022 已锁定创建分支,FORMAT-023 已锁定优先级分支,FORMAT-024 已锁定组内排序分支,FORMAT-025 已锁定主动跨分类分支,FORMAT-026 已锁定分类删除派生迁移分支,FORMAT-027 已锁定软删除分支,FORMAT-028 已锁定实际恢复结果分支,FORMAT-029 已锁定 `category.created` 精确空详情,FORMAT-030 已锁定 `category.renamed` 精确 `{ beforeName }`,FORMAT-031 已锁定 `category.reordered` 精确 `{ beforePosition, afterPosition }`,FORMAT-032 已锁定 `category.deleted` 精确 `{ affectedTaskCount }`,且 FORMAT-021 只锁定可复用联合;14 个事件类型的精确详情分支均已锁定。

`category.reordered` 必须精确符合 FORMAT-031:公共 `subject` 只保存被移动 Custom 分类的规范小写 UUID v4 与发生时用户原文名称,必填 `details` 精确为 `{ beforePosition, afterPosition }`;每个位置精确只含 `previousCategory` / `nextCategory`。前邻居只能导出 `{ kind: "start" }` 或 `{ kind: "category", categoryId, name }`,后邻居只能导出 `{ kind: "end" }` 或同一 Custom 分类快照;`start` / `end` 只表示自定义分类序列边界,Inbox 不得作为邻居。每个位置内可识别邻居 ID 必须不同且均非主体,正常生产的前后位置必须不同。不得导出 `unavailable`、主体副本、绝对索引、rank、排序键、`categoryOrder` 副本、拖拽/UI/设备/语言元数据、完整分类或通用实体 `before` / `after`;后续改名、再次排序或删除主体及邻居不得回写发生时快照。原位放下不产生事件;真实排序只导出唯一 `category.reordered(eventOrder = 0)`,不伴随任务事件或任务/分类内容、状态、归属、时间变化。

`category.deleted` 必须精确符合 FORMAT-032:公共 `subject` 只保存被删 Custom 分类发生时 ID 与用户原文名称,必填 `details` 精确只含 JSON 非负安全整数 `affectedTaskCount`。`affectedTaskCount` 取删除受理时该分类活动总顺序中实际迁入 Inbox 的任务数,同时计入未完成与已完成任务,不计垃圾箱任务、逻辑到期物理残留、历史引用或未提交草稿;`0` 必须原样导出。正常生产中同一操作的 FORMAT-026 任务事件恰为 `N` 条且保持 `eventOrder = 1..N`;任务主体后来永久清理或导出逻辑到期时允许剩余迁移事件少于 `N` 并保留缺口,但分类事件与原计数不得删除或重算。不得导出任务数组、任务 ID/标题、状态拆分、分类身份/名称副本、目标 Inbox、位置、确认/草稿/UI/设备、原因或其他字段。

`nextOperationSequence` 必须来自同一冻结逻辑状态中的已持久化或待保存操作顺序进度,不得根据当前仍保留的历史最大值重新计算或因永久清理形成空洞而回退。

导出必须把逻辑状态映射为 `backup-format.md` FORMAT-010 的七个 `data` 顶层字段。固定收件箱不得导出为自定义分类或进入 `categoryOrder`;每个活动任务必须只通过 `taskOrderByCategory` 表达一次当前分类与总顺序,垃圾箱任务不得进入该顺序。不得直接序列化 `IndexedDB` object stores 或把内部排序、锁、缓存和迁移结构泄漏为备份契约。

导出必须按 FORMAT-011 生成或保留规范小写 UUID v4、判别式 `CategoryRef` 和 UTC 固定毫秒精度时间。不得为了排序、显示语言或设备时区改写标识、分类引用或已经冻结的业务时间。

导出必须按 FORMAT-012 只为自定义分类生成 `{ id, name }` 记录,用 `categoryOrder` 完整排列全部自定义分类,并为收件箱和每个现存自定义分类生成恰好一个 `taskOrderByCategory` 分组,空分组也不得省略。所有历史与垃圾箱分类上下文必须使用独立 `CategorySnapshot`;自定义分类删除或改名后仍保留发生时名称,固定收件箱不生成名称快照。

当前分类集合与顺序只能从同一逻辑快照中的 `categories` 和 `categoryOrder` 导出。FORMAT-029 `category.created`、FORMAT-030 `category.renamed`、FORMAT-031 `category.reordered` 与 FORMAT-032 `category.deleted` 只保存发生时审计事实,不得被导出器重放来补建当前分类、恢复或推导当前名称、顺序及任务。后续改名、排序、删除或任务永久清理不得回写这些分类事件;任务永久清理也不得删除无任务引用的独立分类事件或重算 FORMAT-032 计数。分类历史筛选只使用事件公共 `subject.categoryId`,搜索只使用公共 `subject.name` 与 FORMAT-031 已存邻居名称,不得查询当前分类记录补算。

导出必须按 FORMAT-014 为每条任务生成恰好八个顶层字段,其中 `lifecycle` 使用严格判别结构。活动任务记录不得重复分类或顺序;垃圾箱任务的公共内容、状态与优先级不得在生命周期中生成副本,恢复锚点不得携带标题。导出不得用导出时间、数据库读取时间或物理提交时间重写 `createdAt`、`updatedAt`、`deletedAt` 或 `expiresAt`;应急导出必须保留待保存操作首次被工作状态接受时冻结的 `updatedAt` 值。

导出必须按 FORMAT-015 为每条草稿生成恰好四个顶层字段。每个语义入口最多一条记录,全局入口与收件箱分类入口不得因目标相同而合并;不得输出空标题记录、目标分类副本、响应式形态标记、选区、焦点或键盘状态。待保存内存快照物化时必须保留当前非空代次的同一 `generation`,不得因导出生成新代次。

### EXPORT-002 · 第一版不加密

第一版备份不得使用密码、密钥、加密或混淆限制读取,也不得提供加密导出选项。任何取得备份文件的人都能够检查或解析其中的全部内容。

### EXPORT-003 · 下载前隐私提示

在每次完整备份下载开始前,界面必须明确说明文件包含任务、备注、未提交草稿、垃圾箱和历史,且文件未加密。提示不得隐藏在设置说明、帮助文档或下载完成后的通知中。

### EXPORT-004 · 本地生成

备份必须在当前设备本地生成并启动下载。生成过程不得把备份内容发送到 Desktop Pull 服务、分析服务或其他第三方服务。

### EXPORT-005 · 一致快照

健康态备份中的全部记录必须来自同一个一致的数据库快照。降级态应急备份必须来自同一个工作状态快照,并遵守 `degraded-availability.md`。任何导出都不得修改核心数据、追加持久化历史或清空待保存队列。导入前生成的安全备份也必须遵守本契约。

仅存在清理待完成态时,导出必须先冻结一个一致数据库快照和同一导出时刻,再从该快照生成单一逻辑保留状态;不得在物理清理重试或并发业务写入前后的记录之间拼接。清理待完成态与可写降级态重叠时,必须冻结一个包含待保存变更的工作状态快照,再统一排除该时刻已经逻辑到期的任务及其任务主体历史,并把保留事件中所有 schema 已声明且指向目标的 FORMAT-021 `task` 分支整体投影为精确 `{ "kind": "unavailable" }`,同时按 FORMAT-014 独立投影对应恢复锚点。历史邻居投影必须同时移除目标 `taskId` 与发生时 `title`,不得只覆盖移动事件或把两套联合串型。

### EXPORT-006 · 使用统一文件格式

所有手动导出和导入前安全备份必须遵守 `backup-format.md`,不得生成替代的 ZIP、多文件或私有内部格式。

### EXPORT-007 · 应急备份包含待保存变更

可写降级态的任何完整导出都必须把全部待保存变更及其历史意图按真实主体物化为备份中的当前状态和历史。物化事件必须精确符合 FORMAT-016,并原样保留入队时已经冻结的 FORMAT-017 `eventType`、FORMAT-018 `details`、`occurredAt`、`operationSequence` 与 `eventOrder` 及其稳定逻辑键;对于 `task.created`,还必须原样保留 FORMAT-022 初始分类与创建后嵌套位置;对于 `task.content_changed`,还必须原样保留入队时保存后的 `subject.title` 与 FORMAT-019 精确形状和值;对于 `task.completed` 与 `task.reopened`,必须原样保留 FORMAT-020 精确形状和值;对于 `task.priority_changed`,必须原样保留 FORMAT-023 发生时分类与不同的旧新值;对于 `task.reordered`,必须原样保留 FORMAT-024 发生时分类、状态与移动前后位置;对于 `task.category_changed`,必须原样保留 FORMAT-025 状态、来源移出前分类与位置及目标插入后分类与位置;对于 `task.moved_to_inbox_by_category_deletion`,必须原样保留 FORMAT-026 状态、来源整批前分类与位置、整批后最终 Inbox 位置及完整操作内顺序;对于 `task.trashed`,必须原样保留 FORMAT-027 删除时分类、状态、移出前位置与最新有效主体标题,并保持同一删除意图的 FORMAT-014 生命周期同值关系;对于 `task.restored`,必须原样保留恢复操作接受时已经由同一工作状态冻结的 FORMAT-028 实际目标分类、状态与插入后位置;对于 `category.created`,必须原样保留入队时 FORMAT-029 精确 `{}` 以及公共主体中的创建时 ID / 名称,不得因后来重命名、排序或删除分类而补算详情;对于 schema 已声明的历史任务邻居字段,必须原样保留入队时冻结的 FORMAT-021 分支及发生时标题。不得临时生成、按后来分类重分类或从当前界面入口及后来状态重新推断事件类型或详情,也不得用后来邻接、标题、当前 Inbox 尾部或事件顺序重建 FORMAT-021 / FORMAT-022 / FORMAT-024 / FORMAT-025 / FORMAT-026 / FORMAT-027 / FORMAT-028、为 FORMAT-029 补字段或生成事件 ID;导出还必须把 `nextOperationSequence` 推进到严格大于全部已持久化和待保存正式操作的值,并包含导出瞬间符合 FORMAT-015 的全部非空快速创建草稿。不得使用导出时间重写事件,不得为内存草稿生成新代次,不得提供只导出较旧 `IndexedDB` 状态的替代入口,也不得把待保存队列作为文件外依赖。

待保存 `category.deleted` 必须原样物化操作首次进入工作状态时冻结的公共主体、FORMAT-032 `details: { affectedTaskCount }`、同批 FORMAT-026 集合与稳定事件顺序。计数包含此前已经应用于工作状态并仍在被删分类中的活动任务变化,不包含本次确认消费的草稿;导出不得按后来任务操作、当前分类、当前 Inbox、剩余迁移事件数、逻辑清理或物理残留重算。

待保存 `category.renamed` 必须原样物化入队时冻结的改名后公共 `subject: { categoryId, name }` 与 FORMAT-030 精确 `details: { beforeName }`,`beforeName` 是改名前存储的用户原文且必须不同于 `subject.name`。不得从导出时当前分类记录、`categoryOrder`、后来事件、首次出现或历史重放补算任一名称,不得导出 `afterName`、分类记录、位置、任务、入口或其他额外字段。同一有效当前名称的提交是无变化操作,不得进入应急备份的历史或消耗 `nextOperationSequence`。

到期判断必须针对物化后的工作状态执行:在 `expiresAt` 前已接受待保存恢复的任务必须以活动任务及其恢复历史进入备份,即使导出时已经跨期;只有工作状态中仍为软删除且已达到 `expiresAt` 的任务及其任务主体历史必须排除。保留事件中所有 schema 已声明且指向这些目标的 FORMAT-021 `task` 分支必须整体物化为精确 `{ "kind": "unavailable" }`,并按 FORMAT-014 独立物化对应恢复锚点;历史分支不得残留目标身份或发生时标题。独立分类主体事件和无关历史继续保留。

### EXPORT-008 · 应急草稿按逻辑状态物化

应急导出必须先把全部待保存正式操作及其草稿消费应用到逻辑工作状态,再叠加每个入口当前代次的最新非空草稿。不得直接合并 `IndexedDB` 草稿记录与内存草稿快照。提交 `A` 后继续输入非空 `B` 时,结果必须是任务 `A`、其历史和草稿 `B`;尚未输入 `B` 时,结果只能是任务 `A` 及其历史。两种情况都不得包含草稿 `A`。

### EXPORT-009 · 排除设备界面偏好

完整备份不得包含界面语言偏好、分类折叠、“已完成”折叠、滚动位置、历史筛选条件、历史展开状态、打开的编辑器、未提交分类名称、输入焦点或移动端键盘状态。这些属于当前设备界面偏好或临时视图状态,不属于可移植核心数据。输入焦点不等于 FORMAT-015 明确要求的折叠 `cursorOffset`,后者仍必须随草稿导出。未提交分类名称不得混同于需要备份的快速创建草稿。

### EXPORT-010 · 仅活动窗口可以导出

完整备份只能由 `single-active-window.md` 定义的活动窗口生成。非活动窗口不得加载核心数据或提供导出入口。导出事务已经取得一致快照但尚未完成文件生成与下载启动时,窗口控制权移交必须等待本次导出结束,不得让两个窗口分别拼接或重复当前导出。

### EXPORT-011 · 所有新导出排除逻辑到期内容

普通完整导出、可写降级应急导出和导入前安全备份都必须先按导出时的逻辑工作状态判断保留范围。仍为软删除且当前时间达到或超过 `expiresAt` 的任务、任务内容及以该任务为主体的全部历史必须排除;所有保留事件中语义上指向这些目标且由 schema 明确声明的 FORMAT-021 历史任务邻居 `task` 分支必须按 ERASE-003 整体物化为精确 `{ "kind": "unavailable" }`,同时按 FORMAT-014 独立处理全部对应恢复锚点。历史替换必须移除目标 `taskId` 与发生时 `title`,不限于移动事件;边界、无关任务分支和既有合法不可用分支保持不变。独立分类主体事件和无关历史继续保留。到期前已经按 RESTORE-004 接受恢复的任务按活动任务处理,不得误排除。

启动、回到前台或运行期自动物理清理失败并进入 AVAIL-016 时,导出必须继续使用相同逻辑范围与引用去身份化投影,不得直接序列化原始 object stores 而把目标记录、目标身份或标题从物理残留复制到新文件。该规则只约束 Desktop Pull 此后新生成的备份,不修改或销毁用户此前已经保存到产品外的删除前备份;该文件之后按 IMPORT-013 主动覆盖导入时可能重新带回任务及当时历史。

### EXPORT-012 · 导出语言不改变业务载荷

在业务工作状态相同的前提下,从简体中文或英文界面导出的 `data` 必须使用相同的语言无关系统语义并保留相同用户原文,不得序列化当前语言生成的系统分类名、动作、状态、位置摘要、完整历史句子或语言偏好。除 envelope 中本就随每次导出变化的时间等字段外,界面语言不得改变核心业务载荷。
