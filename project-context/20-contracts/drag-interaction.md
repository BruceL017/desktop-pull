# 拖拽交互契约(Drag Interaction Contract)

## 强制规则

### DRAG-001 · 整行非控件区域可拖

任务行不得要求专用拖拽手柄。除复选框、优先级控件、操作菜单及其他明确交互控件外,任务标题、备注预览和其余空白区域都必须能发起拖拽。

### DRAG-002 · 桌面端点击与拖拽仲裁

桌面指针按下后,累计移动未超过约 `6px` 即松开时必须按普通点击处理;移动超过约 `6px` 时必须直接进入拖拽,不得要求第二次操作或先进入排序模式。

### DRAG-003 · 移动端滚动与拖拽仲裁

移动端在任务行非控件区域持续按住约 `200ms` 后移动时必须进入拖拽。在等待时间内直接滑动时必须保持页面滚动,不得误触发拖拽。

### DRAG-004 · 明确控件不发起拖拽

从复选框、优先级控件或操作菜单开始的点击、按压和移动必须交给对应控件处理,不得启动任务拖拽。

### DRAG-005 · 分类标题复用直接拖拽规则

自定义分类标题除折叠、快速新增、操作菜单及其他明确控件外,其余区域必须能直接发起分类排序。桌面端必须复用 DRAG-002 的位移阈值,移动端必须复用 DRAG-003 的长按与滚动仲裁;不得为分类排序增加专用手柄或排序模式。收件箱不得进入分类拖拽。

### DRAG-006 · 拖拽预览直接显示精确落点

进入拖拽后,任务行或分类分组的拖拽预览必须持续跟随当前指针或手指,并在当前有效目标处显示占据完整可用宽度的精确插入标记或等价占位。标记必须明确表示松手后的唯一位置,且随当前目标实时更新;不得要求用户先寻找专用投放区、进入投放模式或执行第二次确认。

拖拽预览、插入标记和自动展开都只属于临时界面状态。在 DRAG-010 定义的有效放下发生前,不得改写任务、分类、持久顺序或历史。

### DRAG-007 · 任务拖拽保持完成状态

任务拖拽只能在与该任务当前完成状态相同的序列中显示有效插入标记。跨分类拖拽必须保持任务当前完成状态并把任务放入目标分类的对应状态序列;未完成任务不得放入“已完成”序列,已完成任务也不得放入未完成序列。

无效状态区域不得显示可提交的插入标记。拖拽不得隐式切换完成状态;完成与重新打开继续只能由明确复选框操作触发。

### DRAG-008 · 空与折叠目标无需预处理

目标分类的匹配状态序列为空时,必须直接提供完整宽度的空序列插入标记,不得要求先创建占位任务或点击展开后重新拖拽。

拖拽停留在折叠目标分类的标题约 `500ms` 时,必须临时展开该分类及被拖任务匹配的状态序列;分类已展开但匹配的“已完成”区域折叠时,停留在该区域标题约 `500ms` 必须临时展开该区域。取消拖拽时,所有仅因本次拖拽展开的区域必须恢复原折叠状态。成功放下后,目标区域在当前会话中保持展开以展示结果,但这次自动展开不得改写 `task-list-layout.md` 定义的持久折叠偏好;只有用户明确执行折叠或展开才更新该偏好。

### DRAG-009 · 边缘自动滚动

活动拖拽接近任务清单可滚动区域的顶部或底部时,页面必须向对应方向连续自动滚动,且越接近边缘滚动越快。滚动期间必须持续重算并显示当前有效插入标记。

指针或手指离开边缘区域、到达滚动边界、成功放下或取消拖拽时,自动滚动必须立即停止。自动滚动不得造成任务状态、分类或顺序提前提交。取消只恢复被拖对象和本次自动展开状态,不得反向滚动以恢复拖拽开始前的视口位置。

### DRAG-010 · 只有有效放下才提交

只有在有效插入标记上松开指针或手指,才构成一次拖拽移动意图。该意图必须按现有原子一致性和可写降级契约提交为最多一次状态变化及对应历史;同分类真实换位必须生成且只生成一条精确符合 FORMAT-024 的 `task.reordered`,跨分类移动必须生成且只生成一条精确符合 FORMAT-025 的 `task.category_changed`,冻结一份状态、来源分类及移出前位置、不同目标分类及插入后精确落点。两种详情都不得保存拖拽或设备来源。落点与原位置相同时不得修改顺序、任务 `updatedAt`、历史、操作顺序进度或待保存数量。

在有效标记之外松手、桌面按 `Esc`、收到系统 `pointercancel` 或拖拽窗口失去活动窗口控制权时,必须取消拖拽,把预览恢复到原位置并停止自动滚动。取消不得提交移动、改变折叠偏好或追加历史,也不得退而采用最近位置猜测用户意图。

### DRAG-011 · 移动端长按未移动不触发点击

移动端在约 `200ms` 长按阈值前松手仍按普通点击处理;达到长按阈值后若未进入实际移动便松手,必须作为无操作取消,不得打开任务编辑器或改变任何状态。在阈值前直接滑动仍按 DRAG-003 滚动页面。

在任务行或分类标题可拖拽非控件区域进行手势判定与活动拖拽期间,必须抑制会竞争该手势的浏览器原生文本选择、图片拖动和长按上下文菜单。抑制方式不得阻断 DRAG-003 在长按阈值前识别纵向滑动并正常滚动页面,也不得影响输入框、编辑器、复选框、优先级或操作菜单等明确控件的原生交互。

### DRAG-012 · 分类排序复用完成规则

分类排序必须复用 DRAG-006、DRAG-009 和 DRAG-010 的跟随预览、精确插入标记、边缘自动滚动与取消语义。有效插入标记只能位于自定义分类序列中;收件箱保持固定第一且不得成为可移动位置。

分类拖拽成功只能改变被拖分类的持久顺序。拖拽预览、成功放下或取消都不得展开分类内容、移动其中任务或改变任何任务状态与顺序。

## 验收 Gate

- 桌面端从任务标题或空白区域移动超过阈值可立即拖动任务,且界面没有必须使用的拖拽手柄。
- 有备注的任务从备注预览区域开始操作时,验证桌面和移动端均按任务行非控件区域处理点击、滚动与拖拽。
- 从换行或省略后的任务标题任一可见位置开始操作,验证仍按任务行非控件区域处理点击、滚动与拖拽。
- 桌面端在阈值内按下并松开只触发一次普通点击,任务位置不变。
- 移动端按住非控件区域约 `200ms` 后可拖动任务。
- 移动端在按压等待时间内直接滑动时页面正常滚动,任务不移动。
- 从复选框、优先级控件和操作菜单开始操作时,对应控件正常响应且任务不进入拖拽。
- 从自定义分类标题非控件区域在桌面和移动端触发拖拽,验证与任务使用相同的位移或长按仲裁;从标题控件开始操作时不拖拽分类。
- 尝试拖动收件箱标题,验证收件箱不进入分类排序。
- 进入任务拖拽后移动经过多个位置,验证预览持续跟随且始终只有一个精确、完整宽度的有效插入标记;松手前持久状态与历史不变化。
- 分别拖动未完成和已完成任务到同分类及另一分类,验证只在匹配状态序列显示有效落点,成功后状态保持;尝试放入另一状态区域时验证取消且复选框状态不变。
- 向空分类拖入任务,验证无需预先点击即可出现匹配状态序列的空落点并完成移动。
- 将目标分类及其“已完成”区域折叠,分别悬停约 `500ms`,验证匹配区域临时展开;取消后恢复原折叠状态,成功后当前会话保持展开但刷新或重开仍使用拖拽前的持久折叠偏好。
- 在长清单顶部和底部边缘持续拖动,验证页面按方向自动滚动、靠近边缘时加速且落点持续更新;离开边缘、到达边界、放下或取消后立即停止。
- 分别在有效标记外松手、按 `Esc`、触发 `pointercancel` 和失去活动窗口控制权,验证对象回到原位、自动展开与滚动结束,状态及历史不变化。
- 把任务或分类放回原位置,验证不提交状态变化或历史;在有效新位置放下时验证最多形成一次移动和一条对应历史。
- 在同分类未完成与已完成序列分别完成真实换位,验证每次 `task.reordered` 都按 FORMAT-024 冻结一份发生时分类、一份状态和移动前后直接邻居;拖拽区域、手势阈值、设备形态、插入标记、滚动与折叠状态均不进入历史。
- 在未完成与已完成序列分别跨分类拖到中部、顶部、末尾和空目标,验证每次 `task.category_changed` 都按 FORMAT-025 冻结一份状态、来源分类与移出前直接邻居、不同目标分类与唯一插入标记对应的插入后直接邻居;拖拽区域、手势、设备、临时展开和滚动状态不进入历史。
- 来源只有被拖任务且目标同状态序列为空时,验证 FORMAT-025 两侧位置都为 `start / end` 仍能提交;在同一分类相同位置放下则仍是无操作,不会因位置形状相同或不同而混淆事件类型。
- 移动端分别执行快速轻触、阈值前滑动、达到约 `200ms` 后不移动松手及长按后移动,验证依次只产生打开编辑器、页面滚动、无操作和拖拽四种互斥结果。
- 在可拖区域验证手势期间不会触发文本选择、图片拖动或原生长按菜单;输入框和任务行明确控件仍保持各自正常交互。
- 拖拽自定义分类经过长列表并取消或有效放下,验证使用相同标记和边缘滚动语义,收件箱始终第一且分类内容、任务状态与任务顺序均不变化。
