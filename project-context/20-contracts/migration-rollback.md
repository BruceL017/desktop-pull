# Schema 迁移失败回退契约(Migration Rollback Contract)

## 定义

- 候选版本:已经下载并准备启动、可能要求升级数据库 schema 的新 Desktop Pull 应用版本。
- 活跃数据库代次:由持久化激活标记唯一选中、当前可供兼容应用完整读写的核心数据库。
- 候选数据库代次:从活跃代次一致复制、只用于隔离迁移与启动验证且不可接受用户操作的临时数据库。
- Last-known-good 版本:最近一次成功打开当前数据库 schema、完成启动并提供完整功能的应用版本。
- 提升:候选数据库完成迁移与启动验证,经原子激活、旧代次清理后成为唯一活跃代次,候选应用同时成为新的 last-known-good 版本。

## 强制规则

### ROLLBACK-001 · 迁移前保留 last-known-good

候选版本开始 schema 迁移前,必须确认 last-known-good 应用资源完整保存在当前设备并可离线启动。候选版本提升前不得删除、覆盖或使其不可寻址,激活标记必须继续指向与其兼容的旧数据库代次。

### ROLLBACK-002 · 迁移只作用于隔离候选代次

候选版本必须先按 `single-active-window.md` 取得无待保存状态、不可移交且其他实例不持有核心数据库连接的排他迁移窗口,再从活跃数据库代次创建包含全部当前状态、历史、垃圾箱、草稿和所需元数据的一致候选副本。不得直接对活跃代次执行 schema 迁移。

迁移必须在候选代次的可回滚 `IndexedDB` version-change 事务中执行。任一复制、迁移或结构与数据校验失败时,候选流程必须停止,活跃代次的 schema 和全部数据保持不变。

### ROLLBACK-003 · 失败候选停止写入

候选版本完成提升前不得打开可操作的主任务界面、接受核心写入、清库、重建活跃数据库或降级到其他持久化。它必须对候选代次完成迁移、完整读取和一次无错误应用启动后才能申请激活。

### ROLLBACK-004 · 自动完整回退

复制、迁移、完整读取、候选启动或空间检查失败时,持久化激活标记必须继续选择旧代次。失败候选及其部分工件被幂等清理后,回退不得要求用户手动选择版本或导入备份;last-known-good 版本必须自动启动并继续提供完整能力。

### ROLLBACK-005 · 失败版本隔离

同一失败候选版本不得在后续每次启动时再次自动尝试相同迁移。只有不同的修复版本可以从届时最新的活跃代次重新创建候选,避免启动循环和旧候选复用。

### ROLLBACK-006 · 回退期间数据继续演进

Last-known-good 版本在回退期间产生的全部新状态和历史仍写入旧活跃代次。修复版本后续迁移必须从该最新代次重新复制,不得复用失败候选或恢复迁移首次失败时的旧业务快照。

### ROLLBACK-007 · 成功后才能提升

候选版本必须在候选迁移事务提交后使用新 schema 重新打开候选代次、完整读取全部核心数据并完成一次无错误启动。迁移提交但候选启动失败时,必须清理候选并继续使用未改写的旧活跃代次,不得让旧应用读取候选 schema。

候选验证成功后,必须以一个持久化原子激活记录同时选择候选数据库代次、schema 和兼容应用版本。该记录不得存放核心业务数据。激活记录提交前发生中断时旧代次保持活跃;提交后重启时必须确定性选择候选代次。

### ROLLBACK-008 · 开放写入前清理其他代次

激活记录选择候选代次后,应用必须在开放任何核心写入、自动清理、导入或永久删除前幂等删除旧数据库代次和全部候选工件。清理完成后才能把候选提升为唯一活跃事实源和新的 last-known-good。

### ROLLBACK-009 · 代次不确定进入数据保护

候选失败后无法清理候选工件、激活后无法清理旧代次、非首次安装的激活记录缺失或冲突,以及 last-known-good 资源与所选代次不兼容时,应用必须进入 ADR-008 的数据保护行为。不得猜测使用较新或较旧代次、开放写入、导出不完整备份或自动删除无法确认角色的数据库。可证明不存在任何既有代次或候选工件的首次安装只适用 `indexeddb-storage.md` 的空库引导,不属于迁移回退。

## 验收 Gate

- 缓存可用旧版本后安装包含必然失败迁移的候选版本,验证迁移只改动候选代次,激活标记和旧活跃代次的 schema 与全部记录保持不变。
- 在联网与断网状态分别触发迁移失败,验证 last-known-good 版本均自动启动且无需用户导入备份。
- 回退后通过黄金路径执行创建、编辑、拖拽、删除恢复和刷新,验证完整功能与历史正常。
- 连续重启应用,验证同一失败候选不会再次执行迁移或形成启动循环。
- 回退期间新增并修改任务,再安装修复版本,验证迁移包含这些最新状态与历史。
- 让候选迁移事务提交后发生完整读取或应用启动失败,验证失败候选清理后自动回到未改写旧代次,旧版本可继续完整读写。
- 在候选复制期间注入空间不足或中断,验证部分候选先被清理、旧代次仍唯一活跃且没有数据回退。
- 完成候选启动验证并中断激活记录提交,验证重启后只会确定性选择完整旧代次或完整候选代次,不会混合两者。
- 在激活后、旧代次清理前中断,验证重启先完成清理且不开核心写入;清理成功后候选成为唯一活跃代次并完成黄金路径。
- 分别注入失败候选清理失败、旧代次清理失败、激活记录冲突和应用版本不兼容,验证进入数据保护态且不猜测代次或执行任何写入。
- 升级成功并开放写入后永久删除一个任务,枚举当前设备的数据库代次,验证旧代次与候选工件均已清理且被删除内容及历史没有残留副本。
