# 任务优先级契约(Task Priority Contract)

## 强制规则

### PRIORITY-001 · 必填且单值

每个持久化任务必须且只能包含一个 `priority` 值。

### PRIORITY-002 · 封闭值域

`priority` 只能是 `P0`、`P1`、`P2`、`P3`、`P4`、`P5` 之一;`P0` 最高,`P5` 最低。这六个持久值是语言无关系统码,不得翻译、改变大小写或换成本地化标签。空值或其他字符串均为无效数据。

### PRIORITY-003 · 新任务默认值

快速新增任务必须以 `P3` 保存。快速新增界面不得显示或要求用户点选优先级;用户创建后再修改。

### PRIORITY-004 · 可修改

用户必须能把现有任务的优先级修改为任一合法值;保存后任务仍只能有一个优先级。

### PRIORITY-005 · 列表行直接调整

每条任务行必须直接显示当前 `P0` 至 `P5` 优先级标识。用户点击或轻触该标识时,必须展开包含全部六个合法值的紧凑单选菜单;选择新值后立即保存并关闭菜单,不得要求先打开任务编辑器、再次确认或完成第二步操作。

优先级标识及菜单必须是任务行中的独立控件。操作它们不得打开任务编辑器、切换完成状态或发起拖拽。任务编辑器中仍须提供同一优先级字段,两处读取和修改同一个任务值。

### PRIORITY-006 · 修改不自动重排

选择不同优先级必须原子更新任务、把该任务 `updatedAt` 设置为操作冻结的原始 `occurredAt`,并追加且只追加一条 FORMAT-017 `task.priority_changed`,但不得改变任务持久顺序。事件 `details` 必须精确符合 FORMAT-023:`categorySnapshot` 冻结操作接受时任务所属分类,`beforePriority` 是接受前值,`afterPriority` 是任务原子更新后的值;两值都属于 `P0` 至 `P5` 且必须不同。任务行菜单和编辑器不形成不同历史类型或界面来源字段。

选择当前值属于无变化操作,不得写入状态、推进 `updatedAt`、追加历史或消耗 `operationSequence`;待保存重试不得改用重试时间或根据后来任务值重算 FORMAT-023。优先级修改不改变分类、状态或顺序,所以事件不得保存位置、邻居、排序键或这些字段的新旧值。

## 验收 Gate

- 不操作优先级控件直接新增任务,持久化结果的 `priority` 为 `P3`。
- 创建任务后分别修改为 `P0` 至 `P5`,六种值都能正确持久化。
- 空值、多个值及值域外字符串不能成为有效的持久化任务状态。
- 修改一个任务的优先级不会改变其他任务的优先级。
- 在桌面和移动视口中直接操作任务行优先级标识,验证六项菜单可达,选择新值后菜单关闭且无需打开编辑器或确认弹窗。
- 从优先级标识及菜单开始点击、按压或移动,验证不会打开任务编辑器、切换完成状态或启动拖拽。
- 在列表行修改优先级后打开任务编辑器,验证两处显示同一值;在编辑器修改后列表标识同步更新。
- 选择不同值只追加一条精确符合 FORMAT-023 的 `task.priority_changed`,其中 `categorySnapshot`、`beforePriority` 和 `afterPriority` 与操作接受时事实一致,任务位置不变;重复选择当前值时状态、时间、顺序、历史和操作顺序进度均不变化。
- 通过任务行菜单和编辑器执行相同旧新值变化,验证生成相同 FORMAT-023 业务结构且不保存控件位置、设备形态、本地化标签、位置或排序元数据。
- 连续执行 `P3 → P1 → P5` 后再移动或改名任务,验证两条历史分别冻结原旧新值与发生时分类,不会从当前 `P5`、当前标题或当前分类回写旧事件。
- 验证实际优先级修改的 `updatedAt` 等于原操作 `occurredAt`,重复选择和待保存重试不推进时间。
