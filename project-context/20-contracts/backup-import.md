# 完整备份导入契约

## 定义

- 当前数据库:导入开始前,Desktop Pull 当前设备上的全部核心数据。
- 待导入数据:从用户选择的完整备份中解析出的任务、分类、顺序、垃圾箱及其恢复定位与删除时分类语义快照、保留中的任务主体与分类主体历史及其语言无关系统语义、用户原文、操作时间与稳定全序、下一操作顺序进度,以及非空快速创建草稿。
- 安全备份:覆盖当前数据库前,按 `backup-export.md` 生成并启动下载的当前数据库副本。
- 删除前备份:某项永久清理发生前由用户保存到产品外的完整备份;它描述的是当时完整快照,可以使用当前或历史备份格式。

## 强制规则

### IMPORT-001 · 只做完整覆盖

第一版导入必须用待导入数据替换全部当前数据库,不得把两者合并、去重或逐条解决冲突。

### IMPORT-002 · 写入前完整校验

任何持久化写入发生前,必须按 `backup-format.md` 和 `backup-compatibility.md` 完成文件结构、版本兼容、七个 `data` 顶层字段、未知字段、记录关联完整性和当前领域约束校验。自定义分类名称违反 `task-categories.md` CATEGORY-011 的双语系统保留名规则时属于无效数据。无法支持或未通过校验的备份必须被拒绝,当前数据库不得变化。

校验必须确认 `categoryOrder` 完整且无重复,固定收件箱没有被伪造成自定义分类,每个活动任务在 `taskOrderByCategory` 恰好出现一次且每个垃圾箱任务均不出现,并且不存在第二套按完成状态划分的持久顺序。记录数组的偶然排列和任何实现内部存储字段不得用于补全或覆盖这些逻辑事实。

校验还必须确认全部任务和自定义分类标识符合 FORMAT-011 的规范小写 UUID v4 且在各自主体类型内唯一,每个当前 `CategoryRef` 使用唯一合法判别并解析到固定收件箱或一个现存自定义分类,所有 envelope 与业务时间使用 UTC 固定毫秒精度。导入不得通过改变大小写、生成新 UUID、用名称匹配分类、套用设备时区或改写精度来修复无效 v1 文件。

FORMAT-012 校验必须确认每条自定义分类记录只有 `id` 与合法当前 `name`,`categoryOrder` 完整且无重复,收件箱和每个现存自定义分类各有一个且只有一个 `taskOrderByCategory` 分组,每个活动任务恰好进入一个分组而垃圾箱任务均不进入。Custom `CategorySnapshot` 的 UUID 允许不解析到当前分类且名称允许不同于当前名称;这种历史悬空不得被当前 `CategoryRef` 的解析规则误拒绝。Inbox 快照不得包含名称。

FORMAT-013 的 `UnavailableTaskRef` 只允许出现在 FORMAT-014 明确声明的恢复锚点或事件 schema 明确声明且复用 FORMAT-021 的历史任务邻居位置,且必须只有 `kind: "unavailable"`;额外身份、标题、指纹、时间、映射或未声明位置中的该值都必须拒绝。合法不可用引用不要求解析到任务,也不得被当作任务墓碑查询。恢复锚点与历史邻居是两套不同联合:前者的 `task` 分支不得携带标题,后者必须携带发生时标题,导入不得串型或互相补字段。

FORMAT-014 校验必须确认每条任务恰好具有八个顶层字段且值合法,其中活动生命周期只含 `kind: "active"`,垃圾箱生命周期只含六个规定字段。每个活动任务必须只在 `taskOrderByCategory` 出现一次且不在自身记录重复分类或顺序;每个垃圾箱任务必须完全不出现在该顺序。垃圾箱公共内容、状态与优先级不得在生命周期中建立副本,恢复锚点必须使用方向正确的严格联合类型,其中 `task` 分支只含 `kind` 与解析到另一条现存任务的 `taskId`,不得携带 FORMAT-021 的标题快照。`deletedAt` 必须同时等于任务 `updatedAt`,且 `expiresAt` 必须为其后 30 天。导入不得补缺失字段、删除未知字段、把 `null` 解释为空备注、按数组位置猜测分类或用导入时间重建 `createdAt`、`updatedAt` 或删除时间。

FORMAT-015 校验必须确认每条草稿恰好具有 `entry`、`generation`、`title` 与 `cursorOffset` 四个字段。全局和分类入口必须使用各自严格联合分支,分类 `CategoryRef` 必须解析到固定收件箱或现存自定义分类;每个语义入口最多一条记录,代次必须是当前集合内唯一的规范小写 UUID v4,标题不得为空字符串,光标偏移必须是落在标题 UTF-16 code unit 长度范围内的 JSON 非负整数。导入不得按共同目标把全局与收件箱分类入口合并、trim 草稿、生成新代次、按 code point 重算光标、补目标分类副本或把无效草稿静默丢弃。

上述 FORMAT-029 严格校验直接适用于当前 v1 文件。当前 v1 中每个 `category.created` 都必须保持 `(eventOrder = 0, details = {})`:它可以是主清单创建的唯一事件,也可以是未清理选择器操作中匹配 FORMAT-025 `task.category_changed(1)` 的前序事件;若关联任务主体历史已合法永久清理,它还可以作为该选择器操作唯一剩余事件。仍同时存在的选择器两事件必须共享时间与操作顺序且目标分类身份逐字一致;不得从孤立分类事件猜测入口或补建任务事件。反向孤立的 `task.category_changed(eventOrder = 1)`、其他同操作事件、调换顺序或拆分操作必须拒绝。只有文件声明为 `backup-compatibility.md` 明确支持的旧版本时,才先按其原 schema 验证,再由版本化迁移规则把当时合法的冗余创建元数据确定性投影为 `{}`;当前 v1 的非空或错误类型详情不得改走旧版本迁移路径。

FORMAT-030 严格校验同样直接适用于当前 v1 文件。每个 `category.renamed` 必须保持唯一 `eventOrder = 0`,其公共 `subject.name` 是处理后的改名后用户原文,`details` 必须精确为 `{ beforeName }` 且前后名称不同;同一有效当前名称本应是 no-op,不能以历史事件进入文件。只有文件声明为明确支持的旧版本时,才能先按旧发布 schema 验证一条同时保存改名前后名称的合法旧详情;旧后值必须与规范化公共 `subject.name` 一致,再丢弃该冗余后值并把旧前值投影为 `beforeName`。未知、冲突或含混值必须拒绝,不得从当前分类、当前顺序、后来事件、首次出现或历史重放推断;当前 v1 的损坏详情不得改走旧迁移。

FORMAT-031 严格校验同样直接适用于当前 v1 文件。每个 `category.reordered` 必须以被移动 Custom 分类为公共 `subject`,保持唯一 `eventOrder = 0`,且 `details` 精确为 `{ beforePosition, afterPosition }`;两个位置都精确只含 `previousCategory` / `nextCategory`。前邻居只允许 `{ kind: "start" }` 或 `{ kind: "category", categoryId, name }`,后邻居只允许 `{ kind: "end" }` 或同一 Custom 快照,其中分类 ID 为规范小写 UUID v4,名称是发生时用户原文;Inbox 不是邻居,`start` / `end` 只表示自定义分类序列边界。每个位置内可识别邻居 ID 必须不同且均非主体,正常前后位置必须不同。缺失、`null`、额外字段、主体副本、`unavailable`、Inbox、绝对索引/rank/排序键、`categoryOrder` 副本、拖拽/UI/设备/语言元数据、完整分类或通用实体前后包均须拒绝。只有文件声明为明确支持的旧版本时,才能先按旧发布 schema 验证,再从旧记录自身无歧义证明两组有方向边界、邻居 ID 与发生时名称并确定性迁移;不得从当前顺序、后来历史、Inbox、索引或不可用分支猜测,当前 v1 损坏详情不得改走旧迁移。

FORMAT-032 严格校验同样直接适用于当前 v1 文件。每个 `category.deleted` 必须以被删 Custom 分类为公共 `subject`,保持 `eventOrder = 0`,且 `details` 精确为 `{ affectedTaskCount }`。未发生主体清理的正常操作必须有恰好 `N` 条同时间、同操作顺序、来源分类身份逐字一致的 FORMAT-026 事件并占据 `eventOrder = 1..N`;合法清理或 IMPORT-006 过滤后可缺少其中任意任务事件,但剩余顺序仍须在原范围内且数量不得超过 `N`。导入不得拿当前分类、当前任务归属、当前 Inbox、剩余事件数、最大 `eventOrder` 或历史重放对质或重算该值。只有文件声明为明确支持的旧版本,且旧记录自身保存原计数,或能证明保留了清理前完整无缺口的同操作迁移集合时,才能确定性迁移;缺失任务事件且没有原计数的旧记录必须拒绝,当前 v1 损坏详情不得改走旧迁移。

### IMPORT-003 · 展示覆盖摘要

校验成功后,必须在确认界面展示待导入备份的导出时间、任务和草稿等各类记录数量以及“全部替换当前本地数据”的结果。用户取消时不得修改当前数据库。

### IMPORT-004 · 先生成安全备份

进入最终覆盖确认前,必须按 `backup-export.md` 成功生成当前数据库的完整安全备份文件并启动浏览器下载。文件生成或下载启动失败时,不得允许继续覆盖。

### IMPORT-005 · 二次确认

覆盖必须经过独立的二次确认步骤。确认信息必须明确说明当前任务、分类、顺序、垃圾箱、历史和未提交草稿将被完整替换,且产品内不提供合并或撤销覆盖。确认还必须说明所选文件可能重新带回当前数据库后来永久清理的任务及当时历史;不得把覆盖导入描述为只增加缺失数据。

### IMPORT-006 · 单一原子替换

只有待导入原文件已经按 IMPORT-002 通过完整校验后,才能执行到期过滤。清除当前核心数据、排除执行时已经达到 `expiresAt` 的待导入垃圾箱任务及以其为主体的全部历史、把其余待导入保留事件中所有 schema 已声明且指向这些目标的 FORMAT-021 `task` 分支整体替换为精确 `{ "kind": "unavailable" }`、把 FORMAT-014 恢复锚点中的对应 `task` 分支按其联合做相同替换、写入其余待导入数据,必须发生在覆盖所有相关 `IndexedDB` object stores 的同一个读写事务中。替换必须同时移除历史邻居的 `taskId` 与发生时 `title`;不得只处理移动事件,也不得改变边界、既有合法不可用引用或无关任务分支。独立分类主体事件、无关任务和无关历史不得因该过滤连带排除。任一目标判断、过滤、引用扫描、替换、写入、约束或事务提交失败时,事务必须回滚,当前数据库保持导入前状态。

### IMPORT-007 · 保留备份语义

除 IMPORT-006 在同一事务中排除已经到期的垃圾箱任务及其任务主体历史、并只把保留记录中指向这些目标的结构化任务引用去身份化外,导入事务必须原样保留备份中的任务标识、`createdAt`、`updatedAt`、标题与备注原文、语言无关状态、优先级、判别式生命周期、分类归属、持久顺序、垃圾箱时间、恢复定位与删除时分类语义快照、全部保留历史的 FORMAT-016 七字段值、FORMAT-017 精确事件类型、FORMAT-018 事件专属且实际存在的完整精确字段事实、FORMAT-019 内容变化分支及其保存后 `subject.title` 和发生时 `categorySnapshot`、FORMAT-020 完成状态分支、所有已声明 FORMAT-021 邻居分支及其发生时标题、FORMAT-022 创建详情、FORMAT-023 优先级详情、FORMAT-024 组内排序详情、FORMAT-025 主动跨分类来源与目标详情、FORMAT-026 分类删除派生迁移的来源及整批最终 Inbox 位置详情、FORMAT-027 软删除的发生时分类、状态与移出前位置详情、FORMAT-028 恢复后的实际分类、状态与插入后位置详情、FORMAT-029 `category.created` 的精确 `{}` 与公共分类主体、FORMAT-030 `category.renamed` 的精确 `{ beforeName }` 与改名后公共分类主体、FORMAT-031 `category.reordered` 的精确前后位置与公共分类主体、FORMAT-032 `category.deleted` 的精确 `{ affectedTaskCount }` 与公共分类主体、语言无关系统语义、用户原文快照、`occurredAt`、`operationSequence`、`eventOrder` 与 `data.meta.nextOperationSequence`,以及草稿的语义入口、代次、标题原文与 UTF-16 光标偏移。覆盖导入不是任务变更,不得推进任一任务的 `updatedAt`。不得生成新任务、为草稿追加历史、生成新草稿代次、合并入口、补建事件 ID、删除或改写无关事件、把分类主体事件改写成任务主体事件、按导入时间重写任务或事件时间、重新解释顺序,也不得把到期清理推迟到覆盖事务提交之后再决定导入是否成功。当前分类记录与顺序只按导入文件的 `categories` / `categoryOrder` 建立,不得重放 `category.created`、`category.renamed`、`category.reordered` 或 `category.deleted` 历史补建、改名、排序或生成任务。

FORMAT-031 的移动主体、移动前后分类邻居 ID、发生时名称与方向边界必须逐值保留;后续改名、再次排序或删除主体及邻居不得使旧事件失效或触发改写。历史筛选只按公共 `subject.categoryId`,搜索只读公共 `subject.name` 与已存邻居名称;当前 `categories` / `categoryOrder` 仍是当前状态唯一来源,不得重放排序历史或查询当前分类补算旧位置。覆盖导入不得改变任何任务时间或从排序事件生成任务事件。

FORMAT-032 的被删分类公共主体与原 `affectedTaskCount` 必须逐值保留。IMPORT-006 排除到期迁移任务的任务主体历史时只删除对应任务事件并保留原 `eventOrder` 缺口;分类删除事件及计数不变。覆盖导入不得按过滤后的事件数、当前任务、当前 Inbox、物理残留或导入时刻重算,也不得由该审计计数生成任务。

### IMPORT-008 · 降级态禁止导入

存在任何正式待保存变更时,不得进入备份校验、当前数据库安全备份或覆盖确认流程。只有按 `degraded-availability.md` 恢复全局健康态后才能导入。仅存在待保存草稿快照时不禁止导入;导入前安全备份必须包含其最新内容,覆盖摘要和二次确认仍须明确当前草稿将被替换。

处于 AVAIL-016 的任一自动清理待完成态时同样不得进入备份校验、安全备份或覆盖确认流程,即使没有正式待保存变更。只有物理清理成功、重新扫描确认没有到期目标并恢复相关受限入口后才能导入。

### IMPORT-009 · 成功后重置设备折叠偏好

只有 IMPORT-006 的核心数据覆盖事务成功提交后,应用才能清除当前设备原有的分类与“已完成”折叠偏好。首次展示导入结果时,所有导入分类必须默认展开,所有“已完成”区域必须默认折叠,任务页必须从顶部开始。

应用不得按分类名称或与旧数据偶然相同的分类标识继承导入前折叠偏好。当前设备语言不得因成功导入而改变;导入取消、校验失败、安全备份失败、用户未确认或覆盖事务失败时,当前核心数据、语言和折叠偏好都必须保持导入前状态。

### IMPORT-010 · 仅活动窗口独占导入

完整备份导入只能由 `single-active-window.md` 定义的活动窗口发起。从 IMPORT-004 开始生成导入前安全备份,直到用户取消或覆盖事务完成并重新读取新数据库,窗口控制权移交必须暂停。非活动窗口不得读取所选文件、显示当前数据库摘要或提供导入入口。

### IMPORT-011 · 成功覆盖后失效旧运行时状态

覆盖事务成功提交后,应用必须使导入前的编辑自动保存计时器、草稿代次与重试、正式操作回调、待执行清理和所有其他异步写入令牌失效,清空已加载的旧工作状态,再从覆盖后的数据库完整读取。新任务页只能从这次重新读取建立状态,不得把导入前内存对象与导入数据合并。

导入取消或覆盖事务失败时不得失效仍属当前数据库的有效计时器、草稿代次或工作状态。导入成功后到达的任何旧回调必须被代次检查拒绝,不得重新写回已经被覆盖的任务、草稿、顺序或历史。

### IMPORT-012 · 导入后操作顺序继续递增

覆盖导入必须保留全部导入事件的稳定全序和 `(operationSequence, eventOrder)` 稳定逻辑键,不得为了适配当前数据库而压缩 `operationSequence` 或 `eventOrder` 空洞、重新编号、生成事件 ID 或按文件数组顺序改写。v1 备份的 `data.meta.nextOperationSequence` 必须存在、是表示正整数的十进制字符串且严格大于文件中全部历史事件的 `operationSequence`;没有历史事件时仍必须存在,全新数据的合法初始值为 `"1"`。缺失、表示无效或不满足大小关系时,必须在任何写入前拒绝整个备份。

与数据覆盖相同的原子事务必须原样持久化备份中的 `nextOperationSequence`,不得按过滤到期任务后的历史最大值、保留历史最大值或当前数据库旧进度重新计算。导入后的第一次正式操作消耗该值,后续操作继续递增;不得与导入事件共享顺序或填补永久清理留下的空洞。

### IMPORT-013 · 删除前备份可以恢复旧快照

有效删除前备份不得仅因当前数据库在导出之后永久清理过其中某项任务而被拒绝、删改或部分导入。除 IMPORT-006 的导入时到期过滤及其同事务引用去身份化外,覆盖事务必须按 IMPORT-007 保留文件中的完整语义;其中任务、当时历史及当时仍合法的结构化任务引用可以重新进入当前数据库。

应用不得查询跨导入墓碑、删除黑名单、外部文件索引或其他第二事实源来压制这些记录。该结果属于用户主动恢复完整旧快照,不得伪装为撤销了此前永久清理。

### IMPORT-014 · 导入按当前语言呈现同一业务事实

有效备份中的固定系统分类、状态、FORMAT-017 精确事件类型和位置边界必须按语言无关语义导入,动作组按 HIST-004 的稳定映射恢复,不得按导出语言固化显示文案。导入完成后,系统概念按当前界面语言呈现;任务标题、备注、自定义分类名称及其历史快照保持文件中的用户原文。不得为了适配当前语言改写业务记录或历史。
