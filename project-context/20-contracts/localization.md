# 中英文本地化契约(Localization)

## 范围

本契约锁定 M1 已确认的双语交付、首次语言选择、设备语言偏好、切换入口与数据语义边界。

### L10N-001 · M1 完整提供两种界面语言

M1 必须同时提供简体中文与英文界面。两种语言都必须覆盖桌面与移动端的核心任务路径、导航、空状态、校验、自动保存状态、历史、垃圾箱、备份、离线状态、数据保护状态以及删除和覆盖导入等确认文案。

不得把任一 M1 产品自有文案只留在其中一种语言,也不得向用户显示翻译键、开发占位文案或无意混用的另一种语言。`Desktop Pull`、`P0` 至 `P5` 等明确保持不变的产品名与稳定标识不算混用。

### L10N-002 · 运行中的产品可以切换语言

用户必须能从运行中的 Desktop Pull 内发起简体中文与英文之间的切换,不需要重新安装应用、清除本地数据、导出导入备份或建立新工作区。

语言切换只改变产品呈现层。用户输入的任务标题、备注与分类名称必须原样保留;任务、分类、顺序、垃圾箱、业务历史事实及完整备份中的业务事实不得因语言切换而新增、删除或改写。

产品名在两种语言中都显示为 `Desktop Pull`,不得翻译或替换。

### L10N-003 · 系统语义码与用户原文分离

产品自有的系统分类、任务状态、`P0` 至 `P5` 任务优先级、FORMAT-017 的 14 个精确事件类型、位置边界、FORMAT-013 的 `UnavailableTaskRef` 和 D-106 / FORMAT-021 的 `start`、`end`、`task`、`unavailable` 判别必须使用稳定、语言无关的语义码持久化;精确事件类型到 HIST-004 八个动作组的唯一映射必须与语言无关,不得为了本地化重复保存动作组显示文案。固定收件箱必须保存稳定系统身份而不是“收件箱”或 `Inbox` 等显示文案;这些系统概念在任务清单、历史、垃圾箱与备份摘要中都按当前界面语言呈现。不可用任务引用在简体中文和英文下只能显示通用中性语义,不得保存或呈现被清理任务的原标识、标题、链接或可搜索选项。

14 个 `eventType` 在两种语言中必须逐值保持不变,由当前语言资源和 FORMAT-018 的事件专属最小 `details` 生成精确动作及所属动作组。`task.created` 从 FORMAT-022 的初始 `categorySnapshot` 与创建后 `position` 本地化呈现分类和位置,标题只读取发生时 `subject.title`;不得持久化创建入口或预渲染摘要。`task.content_changed` 仍是一个持久类型;标题、备注或两者同时变化的具体动作必须从 FORMAT-019 除共有 `categorySnapshot` 外的三个精确变化字段集合本地化呈现,标题新值读取保存后的 `subject.title`。`task.completed` 与 `task.reopened` 的方向只从两个事件类型本地化呈现,FORMAT-020 只提供发生时分类。`task.priority_changed` 从 FORMAT-023 的 `beforePriority` 与 `afterPriority` 本地化呈现变化方向,但 `P0` 至 `P5` 值本身保持语言无关代码;发生时分类只从同一详情的 `categorySnapshot` 呈现。`task.reordered` 从 FORMAT-024 的一份发生时分类、一份 `open | completed` 状态及移动前后位置本地化呈现,状态、边界和不可用分支按当前语言显示,邻居 `title` 保留用户原文;不得持久化拖拽来源、绝对索引或预渲染摘要。`task.category_changed` 从 FORMAT-025 根部一次 `status`、发生时 `source.categorySnapshot` / `target.categorySnapshot` 及两侧各自 `position` 本地化呈现;紧凑摘要先表达“从 A 移到 B”且只能按 `target.position` 补充目标落点,展开则显示两侧完整位置。目标位置因合法去身份化无法可靠表达具体落点时,摘要必须降级为中性跨分类移动文案,不得查询任务当前归属、状态或顺序补值。`task.moved_to_inbox_by_category_deletion` 从 FORMAT-026 根部一次 `status`、来源被删 Custom 快照与整批前位置、以及整批后最终 `targetPosition` 本地化呈现;固定目标 Inbox 由事件类型按当前语言显示,不得持久化目标快照。紧凑摘要表达“因删除「来源分类」移到收件箱”并只按最终位置补落点;批次邻居跨来源与目标同方向重复时两处用户原文标题保持一致,去身份化后全部对应槽位显示当前语言通用不可用且摘要中性降级。`task.trashed` 从 FORMAT-027 的删除时 `categorySnapshot`、一次 `status` 与移出前 `position` 本地化呈现;紧凑摘要表达从对应分类和状态区移入垃圾箱,展开显示完整位置。系统分类、状态与边界按当前语言显示,主体和邻居标题保留用户原文;不得持久化删除摘要、确认入口、到期说明或恢复动作,也不得从当前生命周期或顺序补值。所有 `CategorySnapshot` 的固定收件箱按当前语言显示,Custom 名称保留用户原文。不得把中文、英文、界面入口、本地化状态或优先级标签、本地化摘要、`changedFields` 或冗余根级 `details.kind` 写回事件;未知、大小写变体、本地化动作名称和显示句子都不是合法事件类型。

`category.created` 只把 `eventType` 对应动作本地化,分类名称逐字读取公共分类 `subject.name`;D-114 / FORMAT-029 `details` 必须存在且精确为 `{}`,不含任何语言字段、摘要、位置、入口、设备或任务关系。两种语言的显示与分类筛选都只读同一公共主体,不得查询当前分类或重放历史补值;后来重命名、排序、删除和无关任务永久清理都不改写该事件。

`category.renamed` 只把 `eventType` 对应的“重命名分类”动作本地化,改名前用户原文逐字读取 D-115 / FORMAT-030 `details.beforeName`,改名后用户原文逐字读取公共分类 `subject.name`;两者必须不同且不得翻译。紧凑摘要与展开按当前语言表达从旧名到新名,分类筛选只按公共 `subject.categoryId`,名称搜索同时匹配两名;不得持久化 `afterName`、任一语言的摘要或其他字段,也不得查询当前分类、后来事件或重放历史补值。后来再次重命名、排序、删除和无关任务永久清理都不改写该事件。

`category.reordered` 只把 `eventType` 对应的“调整分类顺序”动作以及 FORMAT-031 的 Custom 序列 `start` / `end` 边界本地化;公共主体与 `beforePosition` / `afterPosition` 中的 Custom 分类名称都是发生时用户原文,必须逐字显示且不得翻译。紧凑摘要只按 `afterPosition` 表达移到顶部、末尾或某个发生时前邻居之后,展开显示完整移动前后位置。不得持久化本地化边界、摘要、`unavailable` 或 Inbox 邻居,也不得查询当前分类、当前 `categoryOrder`、后来事件或历史重放补值;后来改名、排序、删除主体或邻居及任务永久清理都不改写该事件。

`category.deleted` 只把 `eventType` 对应的“删除分类”、固定 Inbox 名称及数量语法本地化;公共 `subject.name` 是被删分类发生时用户原文,必须逐字显示且不得翻译,FORMAT-032 `affectedTaskCount` 是语言无关 JSON 非负安全整数。紧凑摘要与展开按当前语言表达删除该分类并移动 N 个任务,N 为 `0` 时明确显示零结果而不是未知或省略数量;不同语言可以使用各自单复数或量词规则,但不得改写底层数值。不得持久化摘要、翻译后的分类名、任务列表、状态拆分、位置、确认/草稿/UI/原因,也不得查询当前任务、当前 Inbox 或剩余 FORMAT-026 事件补数;永久清理后仍显示原 N。

`task.restored` 从 FORMAT-028 精确 `{ categorySnapshot, status, position }` 本地化呈现恢复后的实际目标分类、未改变状态与插入后直接邻居。原 Custom 分类已改名时使用同一标识及恢复时当前名称,已删除时使用固定 Inbox;紧凑摘要表达“恢复到实际分类状态区”并只按插入后位置补充落点。不得显示或持久化删除上下文、生命周期、恢复锚点、锚点命中或回退原因、30 天信息、界面来源、绝对位置、内部排序值或预渲染摘要,也不得从当前任务、FORMAT-014 或 FORMAT-027 补值。

用户输入的任务标题、备注、自定义分类名称以及历史中的对应发生时快照必须逐字保留,包括 FORMAT-021 `task` 分支的发生时 `title`;不得因当前界面语言而翻译、生成另一份本地化值、改成邻居当前标题或回写。前邻居的 `start` 与后邻居的 `end` 按当前语言显示边界文案,但不得交换方向或把本地化文案持久化。系统文案与用户原文即使同时包含中英文也不属于意外混用。

FORMAT-021 历史邻居与 FORMAT-014 恢复锚点必须保持为两种独立结构:前者的 `task` 分支恰好保存 `kind`、`taskId` 和发生时 `title`,后者的任务分支不保存标题。两者都可在永久清理或清理待完成投影后使用同一语言无关 `{ "kind": "unavailable" }`,但本地化层不得据此在两种结构间补字段或把正常业务事件的邻居预先变成不可用。

FORMAT-028 的 `position` 复用 FORMAT-021 但只审计恢复结果;后来改名、移动、状态变化、软删除或再次恢复不改写原文快照,永久清理或清理投影只把命中的整个 `task` 分支本地化为通用不可用。呈现层不得把该位置作为当前排序或后来恢复来源。

其他契约中用中文引号给出的按钮、动作、状态、系统分类和位置摘要代表简体中文资源或命令语义示例,不是持久化值,也不要求英文界面显示中文。备份不得依赖导出时语言才能解释任何系统事实。

### L10N-004 · 固定收件箱保留两种显示名称

自定义分类在创建与重命名时都不得使用去除首尾空白后的“收件箱”或 `Inbox`,无论当前界面使用简体中文还是英文。`Inbox` 必须按 ASCII 大小写不敏感匹配,因此 `inbox`、`INBOX` 和其他大小写组合同样属于保留名;包含其他字符的不同名称不因此被禁止。

名称校验失败必须遵守 `task-categories.md` 的原地修正规则,并用当前界面语言说明名称已被系统保留。切换语言不得让原本无效的保留名变为可创建或可重命名。

### L10N-005 · 首次语言匹配并默认简体中文

首次进入且尚无用户明确语言选择时,应用必须按设备或浏览器提供的有序语言偏好列表选择第一个受支持项。语言标签比较不区分大小写:`zh` 或任何 `zh-*` 匹配简体中文,`en` 或任何 `en-*` 匹配英文;不受支持的标签继续向后查找,不得只检查列表第一项。

语言偏好列表不存在、无法读取、为空或没有任何中英文匹配时,应用必须默认简体中文。选择过程必须完全本地执行,不得使用 IP、地理位置、账号、网络请求或系统地区之外的推断。

### L10N-006 · 手动选择立即生效并作为设备偏好保留

用户手动选择简体中文或英文后,界面必须在当前应用上下文立即重新呈现,不得刷新、重载、跳转页面或要求再次确认。当前页面、滚动位置、打开的任务编辑器、有效未提交编辑、快速创建草稿和其他既有交互状态必须保留;语言切换本身不得产生业务历史。

手动选择必须作为当前存储作用域的设备界面偏好跨刷新、普通网页重开与已安装 PWA 重开保留,并优先于 L10N-005 的设备或浏览器匹配,直到用户再次切换或清除该偏好。偏好不存在或被清除后,下一次启动重新执行 L10N-005。

语言偏好不得进入完整备份,不属于跨设备恢复语义。完整备份覆盖导入无论成功、取消或失败都不得改变当前设备语言;成功导入仍只按 `backup-import.md` 重置与导入分类身份相关的折叠偏好。

### L10N-007 · 语言切换位于设置中的双选分段控件

桌面端必须从常驻侧边栏底部的设置入口访问语言控件;移动端必须从任务页右上角菜单进入设置后访问同一控件。语言不得成为任务主工具栏的常驻按钮、独立主页面、侧边栏主工作区入口或移动端第四个底部标签。

设置中必须使用带地球图标的语言行和稳定双选分段控件,两个选项始终分别写作 `简体中文` 与 `English`,不得把它们随当前语言翻译成只有当前语言可读的名称。控件必须明确表示当前选择,不能只靠颜色区分;选择任一项立即执行 L10N-006,不得再要求点击保存、应用或确认。

## 验收 Gate

- 分别在简体中文和英文下走通桌面与移动端 M1 核心路径,验证所有产品自有文案均有对应语言版本,没有翻译键、占位文案或意外混用。
- 使用同一份已有任务数据从简体中文切换到英文,再切回简体中文,验证任务、分类、顺序、垃圾箱、历史事件数量与事实值均未改变。
- 在简体中文下产生涉及收件箱、完成状态以及 FORMAT-022 创建位置和 FORMAT-021 `start` / `end` / `task` 分支的创建、移动历史后切换到英文,验证系统分类、动作、状态与位置边界改用英文呈现,`task.title`、任务标题、备注与自定义分类名称仍为发生时用户原文且底层事件未改写;反向切换结果对称。
- 永久清理一个被 FORMAT-014 恢复锚点和 FORMAT-021 移动历史邻居引用的任务后切换中英文,验证两种独立结构中的精确 `{ "kind": "unavailable" }` 都显示各自通用中性文案,不显示原任务 ID、标题或链接,也不成为搜索或筛选选项;恢复锚点没有标题,历史邻居清理前的 `task` 分支恰好具有发生时标题。
- 检查数据库和完整备份,验证系统分类、状态、`P0` 至 `P5` 优先级、FORMAT-017 全部 14 个精确事件类型以及 FORMAT-021 的方向边界和不可用引用保存稳定语义码,动作组由稳定事件类型映射,没有把本地化优先级标签、“收件箱”、`Inbox`、“已完成”、`Completed`、“顶部”、`Top` 或“不可用”的任一界面文案当作系统事实值或冗余动作组值;前邻居 `end`、后邻居 `start` 和正常事件直接生成 `unavailable` 均被拒绝而非本地化纠正。
- 在两种语言下逐一呈现 14 个事件类型,验证持久值逐字相同、每个值只映射到一个动作组且精确动作完整翻译;`task.created` 从 FORMAT-022 显示初始分类及创建位置且不显示入口或默认值,`task.content_changed` 根据 FORMAT-019 的二、三、四个字段分支显示对应文案,`task.completed` 与 `task.reopened` 只按事件类型区分方向,`task.priority_changed` 从 FORMAT-023 显示精确旧新值且 P0 至 P5 不翻译,`category.renamed` 从 FORMAT-030 `beforeName` 与公共 `subject.name` 显示旧名到新名,`category.reordered` 从 FORMAT-031 `afterPosition` 显示 Custom 序列顶部、末尾或发生时前邻居之后,`category.deleted` 从 FORMAT-032 公共主体与原计数显示删除并迁入当前语言 Inbox,数据库不新增类型或语言字段。
- 在两种语言下分别呈现主清单与选择器生成的 `category.created`,验证动作文案随语言变化而公共主体名称逐字不变、分类筛选按主体 ID 一致,两条 `details` 都精确为 `{}`且不出现空详情占位。缺失、`null`、数组、字符串或含语言、入口、位置、设备和任务字段的详情必须在本地化前拒绝。
- 在简体中文和英文下分别呈现把分类从 `A` 重命名为 `B` 的 `category.renamed`,验证动作和方向词随语言切换,但 `details.beforeName = "A"` 与公共 `subject.name = "B"` 逐字不变且不翻译;旧名和新名搜索都定位同一公共分类 ID。缺失、`null`、数组、字符串、相等旧新值、`afterName`、语言字段、摘要及任意额外字段必须在本地化前拒绝,不得查询当前分类或后来历史补值。
- 在简体中文与英文下分别呈现 FORMAT-024 未完成与已完成组内排序,验证 `open | completed`、`start | end | unavailable` 和事件类型的底层值不变,状态区、边界与通用不可用语义按当前语言显示,发生时邻居标题不翻译;界面不从当前顺序补值或持久化摘要、拖拽来源、绝对索引与本地化状态。
- 在简体中文与英文下分别呈现 FORMAT-025 的选择器置顶与拖拽精确落位事件,验证两种语言都显示同一发生时 source / target 分类、根部一次状态和两侧完整位置;紧凑摘要只按 `target.position` 补位置,目标邻居去身份化后两种语言都降级为中性“从 A 移到 B”语义且不查询当前状态。正常生产四槽位中的可识别任务 ID 跨侧两两不同,清理后多个 `unavailable` 收敛仍可呈现;选择当前分类不产生待本地化事件。
- 在简体中文与英文下呈现 FORMAT-026 分类删除派生迁移,验证两种语言都从同一状态、来源原文名称、整批前位置和整批后最终 Inbox 位置生成“因删除 A 移到收件箱”语义,只按 `targetPosition` 补最终落点;不持久化任一语言的 Inbox 名称或摘要。
