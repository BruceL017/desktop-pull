# 第一版黄金路径契约(MVP Golden Path Contract)

## 验收层级

- D-090 的全部正式支持组合执行本文件核心路径的非计时功能 Gate,验证功能、持久化和布局正确;不得为每个组合重复招募首次用户样本。
- 两分钟首次用户 Gate 只在本文件指定的桌面与移动参考环境执行,用于验证无需教程的可发现性与操作效率。
- 桌面和移动边界视口执行同一核心路径的非计时布局 Gate,用于发现溢出、遮挡或控件不可达,不得用参考视口通过替代边界验证。

## 起始条件

- 使用全新的本地数据状态、默认简体中文和空任务清单。
- 应用已经完成首次加载并可操作;首次加载耗时不进入两分钟计时。
- 计时测试者从未接触 Desktop Pull,未阅读产品教程、设计文档或操作说明。
- 同一形态的所有测试者在计时前读完同一张外部任务卡。任务卡只描述要达成的核心路径目标和测试数据,不得提示控件位置、入口名称之外的寻找路径、手势技巧或操作演示。
- 分别在桌面视口与移动视口执行同一条路径。

## 参考环境与输入

| 形态 | 两分钟参考环境 | 两分钟参考视口 | 输入方式 | 非计时边界视口 |
|------|----------------|----------------|----------|----------------|
| 桌面 | Windows 11、发布时当前 Chrome Stable | `1440 x 900` CSS px、100% 页面缩放 | 鼠标与实体键盘 | `1280 x 720` CSS px、100% 页面缩放 |
| 移动 | 发布时当前 iOS、Safari | `390 x 844` CSS px、竖屏 | 单指触控与系统软键盘 | `360 x 800` CSS px、竖屏 |

## 计时规则

- 测试者已经读完任务卡且空清单可操作后,首次点击、触摸或按键开始计时。
- 核心路径最后一次刷新完成、最终任务清单重新显示且可观察状态符合任务卡时停止计时。最后一次刷新耗时计入,首次加载耗时不计入。
- 计时开始后不得暂停、演示、代替操作或提供口头及文字提示。与产品无关的外部中断使该次样本作废并从全新状态重测,不得扣除中断时间后继续。
- 停表后继续核验任务内容、优先级、分类、顺序、垃圾箱结果、持久化状态和完整历史;核验错误仍判该次失败,不得因为已经在时限内停表而通过。

## 核心路径

测试者必须连续完成以下操作:

1. 在同一次全局快速新增会话中连续创建 2 个收件箱任务。
2. 直接从任务行优先级菜单修改其中至少一个任务的优先级。
3. 从主清单分类列表末尾触发立即聚焦的原地输入,经一次明确提交新建一个自定义分类。
4. 通过该分类标题的 `+` 快速创建第 3 个任务。
5. 通过跟随指针或手指的精确插入标记,直接拖拽完成一次组内排序和一次跨分类移动。
6. 在确认弹窗中明确同意删除其中一个任务,再从垃圾箱单独恢复它。
7. 刷新页面。

## 首次用户样本 Gate

- 桌面与移动参考环境分别使用 5 名符合起始条件的首次测试者。同一人已经测试任一形态后,其另一形态结果不得再计入“从未接触 Desktop Pull”的计时样本。
- 每种形态至少 4 名测试者必须在不求助的情况下于 `120s` 内完成并通过停表后核验;第 5 名也必须在 `180s` 内独立完成并通过核验。
- 任何求助、演示、代操作、最终状态错误或核验错误都使该次样本失败。样本失败不得用熟练开发者、agent 或已经读过上下文包的人员补位。
- 任一样本出现产品丢失数据、删除非目标任务或在尚未持久化时显示保存成功,不受 4/5 阈值豁免并直接阻断发布。
- D-090 全矩阵和边界视口只要求非计时功能 Gate;两分钟首次用户样本不得乘以浏览器与安装组合数量。

## 通过条件

- 三个任务的内容、状态、优先级和分类均与用户最后一次操作一致。
- 全局和分类快速新增均只要求标题,没有先打开完整任务编辑器或分类选择器。
- 连续创建的两个收件箱任务位于未完成区顶部,顺序与输入顺序一致,创建后输入焦点保持可继续记录。
- 列表内优先级修改只需打开一次六项菜单并选择新值,不打开编辑器、不弹确认且不改变任务位置。
- 新建分类入口和自动聚焦的名称输入位于主清单内;只有桌面 `Enter`、移动端“添加”或确认图标明确提交才创建,成功后空分类追加到自定义分类末尾,不跳页也不自动创建任务。
- 组内与跨分类拖拽全程无需手柄或投放模式,有效落点明确且只位于任务当前完成状态序列;空或折叠目标无需预先处理,长清单边缘可以自动滚动。
- 组内顺序与跨分类移动结果在刷新后保持不变;取消、无效放下或放回原位不会改变任务或历史。
- 恢复任务没有覆盖或改变另外两个任务。
- 普通任务删除只有在确认弹窗中明确同意后才发生;没有前序编辑时取消确认不改变任务或历史,存在前序有效编辑时取消只保留编辑且不产生删除变化。
- 任务行操作菜单能够直接发起删除确认,无需先打开编辑器,但不存在滑动或常驻垃圾桶等易误触删除入口。
- 全局历史能按用户操作发生时间与稳定全序追溯上述已提交操作,一次操作产生的多条事件不会交错或跳动。
- 桌面与移动参考环境分别满足首次用户样本 Gate;两个边界视口均能完成整条路径且没有横向溢出、内容遮挡或不可达控件。

## 失败条件

- 任一步需要教程才能发现。
- 任一步在正常操作下造成任务、顺序或历史丢失。
- 用户必须寻找专用拖拽手柄才能移动任务。
- 拖拽没有明确落点、会暗改完成状态,或必须先手动展开空或折叠目标再重新拖动。
- 在无效区域松手、系统取消或移动端长按未移动时仍修改任务、写入历史或意外打开编辑器。
- 输入法组合回车、失焦、点击外部、`Esc` 或取消意外创建分类;确认图标因先触发失焦而丢失提交;无效名称清空文字或关闭输入。
- 移动端缺失桌面端核心路径中的任一能力。
- 用开发者、agent、已阅读上下文包或已经完成另一形态测试的熟练结果证明首次用户时限。
- 在应用尚未可操作时开始计时、把任务卡阅读计入产品操作时间、从计时中扣除最后刷新,或在产品内提示具体控件与手势以换取通过。
- 只验证参考视口而未验证 `1280 x 720` 桌面或 `360 x 800` 移动边界视口。
- 用各正式浏览器的非计时功能结果代替两组首次用户样本,或反过来要求每个浏览器与安装组合分别招募 5 名测试者。
