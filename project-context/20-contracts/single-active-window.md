# 单活动窗口契约(Single Active Window Contract)

## 定义

- 存储作用域:共享同一 Desktop Pull 源站 `IndexedDB` 的普通标签页、浏览器窗口和已安装 PWA 实例集合。
- 活动窗口:当前持有排他控制权、已经完整读取活跃数据库并可以执行核心操作的唯一实例。
- 非活动窗口:未持有控制权,不得加载核心数据且只提供控制权请求的实例。
- 移交:原活动窗口完成保存与事务收尾后释放控制权,由请求窗口重新完整加载数据库的过程。

## 强制规则

### WINDOW-001 · 同一作用域只有一个活动窗口

存储作用域内必须使用可在窗口正常关闭或崩溃后释放的排他所有权机制。任一时刻只能有一个窗口成为活动窗口;普通网页和已安装 PWA 不得各自形成独立写入者。

每次核心写入都必须确认当前实例仍持有有效所有权。窗口已释放或失去所有权时,尚未开始的写入必须拒绝,不得让旧自动保存计时器、重试或后台回调继续提交。

### WINDOW-002 · 非活动窗口不加载核心数据

非活动窗口只能显示“Desktop Pull 已在另一窗口打开”、一个明确的“在此窗口继续”操作及必要的移交状态。它不得读取、缓存或展示任务、分类、顺序、历史、垃圾箱、草稿、备份内容或其他核心数据。

非活动窗口不得提供创建、编辑、拖拽、删除、恢复、历史筛选、备份导出或导入等核心入口,也不得作为只读任务镜像。窗口失去控制权后必须移除已加载工作状态并进入相同提示界面。

### WINDOW-003 · 正常移交先冻结并落盘

收到“在此窗口继续”请求后,活动窗口必须先停止接受新的核心操作和输入,并立即按既定契约处理待计时的最新有效任务编辑、非空快速创建草稿及进行中的普通事务。尚未有效放下的任务或分类拖拽必须按 `drag-interaction.md` 取消并恢复原位,不得为移交猜测落点、修改顺序或追加历史。无效标题继续按 `task-editing.md` 保留最后有效值,不得为完成移交写入无效内容。

只有下列条件同时满足时才能释放控制权:

- 全部已触发的有效编辑和草稿快照已经成功持久化;
- 正式待保存队列与待保存草稿快照均为空;
- 没有尚在执行的核心数据库事务;
- 没有进行中的永久删除、清空垃圾箱、覆盖导入或 schema 迁移流程。

新窗口取得控制权后必须从持久化激活标记选择的唯一活跃数据库重新执行完整读取,不得继承原窗口的内存对象、待保存队列、编辑器、滚动或焦点状态。完整读取成功前继续遵守 `indexeddb-storage.md` 的数据保护边界。

### WINDOW-004 · 待保存状态禁止移交

原活动窗口无法提交有效编辑、正式待保存变更或最新草稿快照时,移交必须保持暂停。请求窗口只能说明原窗口尚有未安全保存工作,引导用户回到原窗口继续自动或手动重试,并从原窗口使用既定应急完整备份。

第一版不得通过窗口消息、第二持久化存储、文件或其他旁路把内存待保存队列交给新窗口,也不得合并两个窗口各自的操作意图。应急备份完成不等于待保存队列已经落盘,因此不得自动解锁移交。

### WINDOW-005 · 关闭或崩溃后从持久化状态接管

活动窗口正常关闭或崩溃后,排他所有权必须自然释放。随后请求控制权的窗口只能重新完整读取已持久化状态;原窗口尚未落盘且未应急导出的内存变更或草稿可以按 `degraded-availability.md` 既定风险丢失,不得从旧草稿或历史猜测恢复。

第一版不得提供忽略仍有效所有权的强制抢占。旧窗口若在移交后收到延迟回调或恢复运行,必须先识别自己已非活动并拒绝所有写入。

### WINDOW-006 · 敏感事务期间暂停移交

从永久删除或清空垃圾箱确认流程开始到事务完成,从覆盖导入安全备份开始到覆盖事务完成,以及从 ADR-009 取得排他迁移窗口到候选激活或回退清理完成,活动窗口都不得释放控制权。

Schema 迁移开始前必须确认当前窗口健康、没有待保存状态,且全部非活动实例不持有核心数据库连接。迁移期间不得响应新的控制权请求;完成后请求窗口可以重新发起正常移交。

### WINDOW-007 · 非核心视图状态不跨窗口移交

控制权移交只传递已持久化核心数据库和既定设备折叠偏好,不得传递编辑器打开状态、快速输入焦点、滚动位置、历史筛选、展开记录、移动键盘或原窗口临时导航状态。新活动窗口按正常新会话规则进入任务清单。

### WINDOW-008 · 数据库连接随所有权关闭

只有活动窗口可以打开核心数据库连接。窗口开始移交、失去所有权、进入非活动状态、收到数据库 `versionchange` 或被页面生命周期恢复时,必须先停止新事务并重新验证所有权;不再拥有控制权时必须中止未提交事务、显式关闭核心数据库连接、清除数据引用后才能显示非活动界面或确认移交完成。

数据库升级或旧代次删除遇到 `blocked` 时不得绕过连接或强制迁移。活动窗口必须保持当前兼容版本和数据不变,明确等待阻塞连接关闭并允许重试;若无法确认连接角色,遵守 `indexeddb-storage.md` 的数据保护边界。

### WINDOW-009 · 挂起与并发请求不产生抢占

活动窗口被浏览器挂起但尚未释放有效所有权时,其他窗口的移交请求可以等待,但不得因心跳超时自动或强制取得控制权。用户只能回到原窗口完成正常移交,或关闭、终止原实例使所有权自然释放。

多个非活动窗口同时请求控制权时必须串行处理,只有第一个完成全部 WINDOW-003 条件的请求可以成为新活动窗口,其余窗口继续保持非活动并可重新请求。新窗口取得所有权后若完整读取失败,必须保持唯一活动身份并进入启动数据保护态,直到重试成功或窗口关闭释放所有权。

## 验收 Gate

- 同时打开普通网页两个标签页、独立窗口及已安装 PWA,验证同一存储作用域始终只有一个实例加载并操作核心数据,其余实例不展示任何任务内容。
- 在活动窗口打开任务编辑器并修改有效内容,再从另一窗口请求控制权,验证原窗口冻结新输入并先持久化最新内容;新窗口重新完整读取后内容存在,原窗口清除数据并无法继续写入。
- 保存一个非空快速创建草稿后正常移交,验证新窗口按新会话进入任务页,从对应入口可恢复持久草稿,但不会继承焦点、键盘或原窗口滚动状态。
- 分别注入正式写入失败和草稿写入失败后请求移交,验证请求被暂停,新窗口不取得数据或控制权,原窗口保留重试与应急备份能力且没有跨窗口队列传输。
- 在活动窗口存在待保存状态时完成应急导出,验证移交仍保持暂停,直到全部待保存状态真正落盘。
- 活动窗口健康关闭后从另一窗口接管,验证只加载已持久化状态;模拟活动窗口崩溃并含未导出内存变更,验证新窗口不猜测或重复这些操作。
- 正常移交后触发原窗口的延迟自动保存、队列重试和数据库回调,验证全部被失效所有权拦截且状态与历史不变化。
- 分别在永久清理确认与执行、覆盖导入和隔离迁移期间请求移交,验证请求暂停到敏感流程结束,没有跨窗口半事务或数据库代次混用。
- 在非活动窗口检查 DOM、内存工作状态和核心数据库访问,验证没有任务、历史、垃圾箱、草稿或备份内容被加载或缓存,也不存在只读镜像入口。
- 正常移交和失去所有权时监测数据库连接,验证旧窗口在确认移交前显式关闭连接;随后迁移或删除旧代次不会被该窗口阻塞。
- 让活动与非活动窗口分别收到 `versionchange`,并注入遗留连接导致的 `blocked`,验证失效窗口关闭连接,升级不绕过阻塞且角色无法确认时不开写。
- 将活动窗口放入 BFCache 后完成控制权移交,再恢复旧页面,验证它在渲染数据或启动回调前重新验证所有权并保持非活动。
- 挂起但不关闭活动窗口,验证其他窗口不会按超时强制抢占;关闭原实例后验证一个请求窗口可以从持久化状态接管。
- 由多个窗口同时请求“在此窗口继续”,验证请求串行且只有一个新活动窗口;让新所有者完整读取失败,验证它进入数据保护而其他窗口仍不能并发加载。
- 在任务与分类拖拽尚未放下时请求移交,验证原窗口取消拖拽且不产生顺序或历史变化,之后才按正常条件释放控制权。
