# 快速任务创建契约(Quick Task Creation Contract)

## 强制规则

### CREATE-001 · 单一快速创建语义

桌面与移动端、全局与分类上下文入口必须使用同一套单行标题快速创建行为。第一版不得并存另一套要求先打开完整编辑器的任务创建流程。

### CREATE-002 · 全局入口进入收件箱

桌面主列表必须提供全局单行标题输入;移动端必须提供始终可达的固定 `+` 操作以唤起同一输入。通过全局入口创建的任务必须归属固定收件箱。

### CREATE-003 · 分类入口直接归类

每个分类标题必须提供 `+` 操作。由该入口唤起的快速创建必须直接以该分类为目标,不得要求用户再次选择分类。收件箱标题入口与全局入口具有相同归属结果。

### CREATE-004 · 只收标题并应用默认值

快速创建只显示并校验标题。去除首尾空白后标题非空时,新任务必须按 FORMAT-014 创建为 `status: "open"`、`priority: "P3"`、`notes: ""` 和精确活动生命周期,标题保留用户提交原文,`createdAt` 与 `updatedAt` 都取创建操作冻结的 `occurredAt`;唯一分类与初始顺序只写入 `taskOrderByCategory`。不得在快速创建中显示备注、优先级或分类选择器。

### CREATE-005 · 创建即形成任务与历史

每次成功提交必须创建且只创建一个任务,并按 `state-history-consistency.md` 同时追加且只追加一条 FORMAT-017 `task.created`。该事件的 `details` 必须精确符合 FORMAT-022:初始分类保存为 `categorySnapshot`,插入完成后在目标分类未完成序列中的直接前后 FORMAT-021 邻居保存于严格 `position`;不得另写移动事件。提交标题只在 `subject.title` 保存,创建时间只在公共外壳保存,固定默认值和快速入口不得复制到详情。空白标题或重复触发不得产生空任务、重复任务或历史事件。

### CREATE-006 · 详细编辑发生在创建后

成功创建不得自动打开完整任务编辑器。用户通过既定任务行点击行为,在桌面右侧面板或移动端全屏页补充备注、修改优先级或调整其他已有属性。

### CREATE-007 · 写入故障保持同一行为

在 `degraded-availability.md` 的可写降级态中,快速创建仍可使用;创建操作进入有序待保存队列并持续显示未安全保存状态。

### CREATE-008 · 连续新增保持输入顺序

一次快速新增会话中的首个任务必须插入目标分类未完成任务的顶部,其 FORMAT-022 `position.previousTask` 为 `start`,后侧按插入后的实际邻居使用任务快照或 `end`。该会话后续创建的任务必须依次插在上一条新任务之后,形成位于顶部的连续分组并持久保持输入顺序;后一条创建历史把上一条任务冻结为前邻居,但不得回写上一条事件,也不得因每次置顶而反转顺序。

### CREATE-009 · 创建后保持输入状态

每次成功创建后必须清空标题输入,同时保留输入焦点;移动端还必须保持软键盘可继续输入。用户显式关闭快速输入器或离开当前页面时,本次快速新增会话结束;下次打开时重新从首条插入规则开始。

### CREATE-010 · 同名任务与重复提交分离

标题相同不得作为去重条件。用户清空后重新输入同一标题并再次提交,必须创建具有新唯一标识的独立任务。只有同一次提交动作被重复派发时才必须幂等,且只能生成一个任务和一条创建历史。

### CREATE-011 · 一次明确提交

桌面端必须允许用户在输入框中按一次 `Enter` 创建任务,并提供明确的提交图标作为指针操作替代。移动端必须把软键盘动作键配置为“添加”或等价提交动作,并提供同一提交图标作为触屏替代。任一入口都不得要求用户先确认、打开编辑器或完成第二次操作。

输入法仍处于组合输入期间时,`Enter` 只能确认候选文本,不得创建任务;组合输入结束后的下一次独立 `Enter` 才能提交。失焦、点击输入框外部或按 `Esc` 均不得自动提交。

### CREATE-012 · 创建反馈不打断

成功提交后,任务直接出现在既定顶部有序分组中即构成成功反馈。不得显示创建确认弹窗、要求用户关闭的成功提示或自动打开编辑器。输入清空、焦点与移动端键盘保持行为继续遵守 CREATE-009;可写降级态仍须显示全局待保存状态。

### CREATE-013 · 未提交草稿不因失焦丢失

用户已输入但尚未提交的标题不得因失焦、点击外部、按 `Esc` 或关闭移动端输入器而创建或清空。草稿必须与发起它的快速入口关联;用户重新聚焦或打开同一入口时,必须恢复原文字与光标位置。

只有成功提交、用户点击明确的清空图标、用户直接把输入编辑为空字符串,或按 CATEGORY-012 在分类删除确认中明确同意丢弃时才能移除该草稿。除分类删除本就必需的单个确认框外,不得为保留或清空草稿新增弹窗。草稿不是任务,不占据任务顺序,不产生任务或历史记录。

### CREATE-014 · 草稿跨刷新与重启保存

每个非空快速创建草稿必须按 FORMAT-015 保存其语义入口、代次、标题原文与 UTF-16 光标偏移,目标分类只从入口推导,并保存到应用现有的版本化 `IndexedDB`。页面刷新、普通网页重新打开、已安装 PWA 关闭重开或被移动操作系统回收后,重新打开同一入口必须恢复草稿;不得使用 `localStorage`、`sessionStorage` 或其他后备存储。

成功提交时,创建任务、追加一条 `task.created` 和条件删除语义入口与 `generation` 都匹配提交快照的草稿必须在同一个原子事务中完成,不得在重启后同时出现已创建任务和提交前旧草稿。明确清空只删除草稿且不追加历史。完整备份必须包含非空草稿。

### CREATE-015 · 草稿写入失败不中断输入

草稿 `IndexedDB` 写入失败时,用户必须仍可继续输入和提交,不得弹出阻断对话框。对应快速入口必须显示非阻断的“草稿未保存”状态、自动重试,并明确关闭或刷新可能丢失最新草稿。

仅草稿写入失败不得据此显示全局降级横幅、暂停无关操作或解除其他独立状态已有的限制;正式任务、分类或历史业务事务也失败时才按 `degraded-availability.md` 升级为全局可写降级态。

同一快速入口尚未保存的连续草稿修改只保留最新快照,后续输入可以覆盖此前待保存快照;不得把每次按键追加为任务待保存操作或历史意图。任务创建、编辑、拖拽、删除等正式操作仍须遵守不可合并的有序队列。应急完整备份必须包含导出瞬间的最新内存草稿。同入口草稿与任务提交的消费顺序遵守 CREATE-016。

### CREATE-016 · 提交建立草稿代次边界

每个快速入口的草稿必须具有内部代次标识。用户提交草稿 `A` 时,提交动作必须冻结包含提交幂等键、`A` 的 FORMAT-015 语义 `entry` 与 `generation`、内容、由入口推导的目标分类、初始顺序位置、由同一工作状态生成的 FORMAT-022 创建详情,以及 `history-retention.md` 定义的 `occurredAt` 与 `operationSequence` 的完整创建意图,把它转换为正式任务创建操作,并立即从待保存草稿快照中按入口与代次消费 `A`;任何独立的 `A` 草稿重试随即失效。提交幂等键、草稿入口与代次只存在于创建意图和条件消费边界,不得写入 `task.created.details`。界面同时清空输入,用户之后输入的 `B` 必须属于同一入口的新草稿代次。

存储恢复时必须先原子提交任务 `A`、其创建历史以及对 `A` 语义入口与 `generation` 的双条件草稿消费,再持久化新草稿 `B`。任务 `A` 的提交不得只按入口或只按代次无条件删除草稿;数据库或内存中的草稿已属于 `B` 代次时,消费 `A` 不得删除或覆盖 `B`。提交 `A` 后生成的应急完整备份必须表示为“任务 `A` 及其历史 + 草稿 `B`”,不得包含草稿 `A`。

上述保证适用于降级会话仍在运行或已通过应急完整备份恢复的情况。若用户在补写或应急导出前强制关闭、崩溃或重载应用,内存中的任务提交意图与新代次草稿可能按 `degraded-availability.md` 丢失;产品不得承诺从较旧持久草稿推断已经发生过提交。

### CREATE-017 · 草稿入口身份与可移植光标

全局快速入口在桌面布局、移动布局和未来兼容客户端中必须使用同一个语义入口;每个分类标题入口按 FORMAT-015 的 `CategoryRef` 识别,不得因响应式切换、界面语言、分类改名或分类排序生成第二份草稿。全局入口与收件箱分类标题入口虽然都创建到收件箱,仍是两个独立入口,不得按目标分类合并或互相覆盖。

每个语义入口最多有一个当前非空草稿。入口从无草稿进入非空输入时生成新的规范小写 UUID v4 代次,同一非空代次的每次内容或光标更新复用该值;输入被删成空、明确清空、成功提交,或按 CATEGORY-012 确认删除所属自定义分类后记录消失,下一次仍合法入口的非空输入使用新代次。代次只用于条件消费,不得成为任务身份、提交幂等键或产品顺序。

草稿标题只要不是空字符串就必须逐字保存,包括纯空白输入;任务提交仍独立执行 CREATE-004 的非空白校验。光标只保存 FORMAT-015 的 UTF-16 code unit 偏移并在恢复时折叠到该位置,不把选区、焦点、软键盘或输入器开关状态持久化。合法状态不得用空记录、`null`、目标分类副本或同入口多记录表达草稿。

## 验收 Gate

- 桌面端从全局单行输入创建任务,验证任务只进入收件箱且为未完成、`P3`、无备注。
- 移动端从固定 `+` 唤起快速输入并创建任务,验证结果与桌面全局入口一致且不打开完整编辑器。
- 分别从收件箱和自定义分类标题的 `+` 创建任务,验证每个任务只归属对应分类且未出现分类选择器。
- 验证全局与分类入口都不显示备注或优先级控件。
- 输入空字符串或纯空白,验证任务与历史均不增加。
- 对一次提交注入重复事件,验证只创建一个任务和一条精确符合 FORMAT-022 的 `task.created`,且没有额外移动事件。
- 创建后普通点击任务行,验证才打开对应的桌面右侧面板或移动端全屏编辑页。
- 注入写事务失败后快速创建,验证任务出现在工作状态、操作进入待保存队列且没有虚假保存成功提示。
- 在空分类、已有未完成任务和混合完成状态分类中分别创建首条任务,验证 FORMAT-022 的初始分类准确,前邻居为 `start`,后邻居只从插入后的未完成序列取当时任务或 `end`,已完成任务不成为创建邻居。
- 在同一快速新增会话依次创建 `A`、`B`、`C`,验证三者作为目标分类未完成区顶部的连续分组持久显示为 `A`、`B`、`C`,原有任务紧随其后;B 的创建位置以前邻居 A 冻结,C 以前邻居 B 冻结,后续提交不回写先前创建事件。
- 每次成功创建后,验证标题被清空而输入焦点仍保留;移动端软键盘不收起。
- 显式关闭输入器或离开当前页面后再次打开并创建 `D`,验证它按新会话首条规则插入未完成区顶部。
- 主动两次输入并提交相同标题,验证创建两条独立任务;对其中一次提交注入重复派发,验证该次只创建一个任务和一条历史。
- 桌面端输入标题后只按一次 `Enter`,验证任务立即创建并可继续输入;点击提交图标产生相同结果。
- 移动端固定 `+` 唤起输入后,验证焦点与软键盘立即就绪;按键盘“添加”或提交图标均只创建一次任务。
- 使用中文输入法选字并按 `Enter`,验证候选文本被确认但任务未创建;组合输入结束后再次按 `Enter` 才创建。
- 输入非空标题后分别触发失焦、点击外部和 `Esc`,验证均未创建任务或历史。
- 成功创建后验证没有确认弹窗、需关闭的成功提示或自动打开的编辑器;任务出现在列表中且输入仍可连续使用。
- 输入非空标题后失焦、点击外部、按 `Esc` 或关闭移动端输入器,再重新打开同一入口,验证未创建任务且原文字与光标位置仍在。
- 成功创建后检查任务记录,验证状态、优先级、空备注、活动生命周期和创建/修改时间符合 FORMAT-014,分类与顺序只存在于权威分组且标题逐字保留;创建历史详情只含 FORMAT-022 的初始分类与嵌套位置,不复制这些默认字段、标题、时间、入口、草稿代次或提交键。
- 点击明确的清空图标,验证草稿消失且没有任务、顺序或历史变化;保留和清空过程均不弹窗。
- 保存非空草稿后分别刷新页面、关闭并重开普通网页或 PWA,验证同一入口恢复原草稿且未产生任务或历史。
- 提交持久草稿后立即重启应用,验证只存在一个已创建任务和一条创建历史,旧草稿没有再次出现。
- 检查草稿持久化实现,验证只使用现有版本化 `IndexedDB`,未写入其他本地或远程后备存储。
- 注入草稿写入失败并继续输入多个字符,验证输入不中断、无阻断弹窗、入口显示未保存状态,且内存中只保留该入口的最新草稿快照。
- 草稿未保存时导出应急完整备份,验证文件包含界面中的最新草稿而非较旧持久版本。
- 在草稿写入失败后执行多次正式任务操作,验证这些操作仍按先后顺序保留且没有被草稿快照合并规则改写。
- 注入持续写入失败,依次执行“输入 `A`、提交 `A`、输入 `B`”,验证工作状态为待保存任务 `A` 和新代次草稿 `B`,不存在待保存草稿 `A`。
- 恢复存储并重试,验证先原子创建任务 `A` 及其一条历史,再保存草稿 `B`;重启后 `A` 不作为草稿复活且 `B` 未被删除。
- 在任务 `A` 待保存期间导出应急完整备份,验证导入结果为任务 `A`、原样冻结的 FORMAT-022 创建历史和未提交草稿 `B`;入口、A 的代次和提交幂等键都不进入创建详情。
- 模拟草稿 `B` 已先写入数据库,再重放提交 `A`,验证 `A` 的条件消费不会按入口删除 `B`。
- 对提交 `A` 的同一幂等键重复派发或重试,验证只创建一个任务 `A` 和一条创建历史。
- 向创建详情平铺前后邻居、缺失一侧、使用错误方向、自引用、让两侧引用同一任务、正常生产 `unavailable`,或加入默认状态、优先级、备注、生命周期、标题、时间、入口、草稿代次、提交键、会话标识、内部排序键、绝对序号、`before`、`null` 或额外字段,验证创建意图不能形成有效事件且不会生成部分任务。
- 在未补写且未应急导出的状态下模拟会话被强制结束,验证结束前持续显示内存提交意图和最新草稿可能丢失,且重启后不猜测丢失操作。
- 仅让草稿保存失败且正式任务写入成功,验证提示局限于对应输入器,无全局降级横幅或无关操作冻结。
- 分别在桌面和移动布局编辑同一全局入口草稿,验证两端读取同一记录;再同时保留全局入口和收件箱分类标题入口草稿,验证两者不因目标同为收件箱而合并。
- 在自定义分类改名、排序和中英文切换前后恢复其分类标题入口,验证草稿身份、标题、代次和 UTF-16 光标偏移不变且没有第二份记录。
- 依次输入纯空白、删至空字符串并重新输入,验证纯空白按原文保存但不可提交任务,空字符串不保存记录,重新输入使用新代次。
- 删除带有分类标题入口草稿的自定义分类,验证只有 CATEGORY-012 的明确确认可以消费该入口与代次;草稿不迁移、不创建任务或历史,取消及代次变化都保留当前草稿。
