# 任务状态契约(Task Status Contract)

## 强制规则

### STATUS-001 · 二态模型

每个任务必须且只能处于“未完成”或“已完成”状态;持久化语言无关值必须分别为 `"open"` 与 `"completed"`,不得保存本地化文案、布尔值、`null` 或其他状态。新增任务默认处于 `"open"`。

### STATUS-002 · 完成不等于删除

任务从未完成切换为已完成时,不得进入垃圾箱,其分类、优先级和持久手动顺序不得改变。

### STATUS-003 · 可重新打开

已完成任务必须能重新切换为未完成;重新打开同样不得改变分类、优先级或持久手动顺序。

### STATUS-004 · 状态历史

未完成变为已完成时必须追加且只追加一条 FORMAT-017 `task.completed`;已完成变为未完成时必须追加且只追加一条 `task.reopened`。两种事件都必须精确使用 FORMAT-020 `{ categorySnapshot }`,其中快照取状态切换被接受时任务当前分类;状态切换不改变分类,不得保存分类新旧对或在重试时按后来归属重算。两个事件类型已经完整表达状态方向,不得另存 `beforeStatus`、`afterStatus`、`status` 或其他详情字段。状态更新、对应事件和任务 `updatedAt` 必须在同一原子操作中提交,其中 `updatedAt` 使用操作冻结的原始 `occurredAt`。把任务设置为其当前状态不得改变任务、推进 `updatedAt` 或产生新记录;待保存重试不得改用重试时间。

### STATUS-005 · 状态视图不改写顺序

已完成任务可以显示在分类底部的折叠区域,但该视图变化不得改写任务的分类或持久手动顺序。重新设为未完成后,任务必须按原持久顺序位置重新显示。

### STATUS-006 · 拖拽不改变状态

任务拖拽必须保持开始拖拽时的完成状态,并且只能在同状态序列中形成有效落点。跨分类拖拽同样不得把未完成任务变为已完成或把已完成任务重新打开;状态变化只能通过明确复选框提交。

## 验收 Gate

- 新增任务保存后处于未完成状态。
- 标记任务完成后,任务未进入垃圾箱,且分类、优先级和持久顺序与操作前一致。
- 将已完成任务重新设为未完成后,分类、优先级和持久顺序仍保持一致。
- 验证未完成到已完成只追加 `task.completed`,反向只追加 `task.reopened`,且两者 `details` 都精确为 FORMAT-020 `{ categorySnapshot }`;缺失或非法快照、任意状态字段和额外字段均拒绝,重复设置相同状态不改变历史。
- 状态事件发生后移动任务或改名、删除原分类,验证既有 `categorySnapshot` 不变且事件仍只匹配发生时分类。
- 检查持久化状态,验证只出现 `"open"` 与 `"completed"`;每次实际切换的 `updatedAt` 等于原操作 `occurredAt`,重复设置与待保存重试不推进时间。
- 完成后再重新打开任务,该任务回到原分类中由未改变顺序确定的位置。
- 分别尝试把未完成任务拖入已完成区域和把已完成任务拖入未完成区域,验证两处都没有有效落点、松手后任务回到原位且不产生状态或历史变化。
