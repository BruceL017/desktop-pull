# 应用导航契约(Application Navigation Contract)

## 强制规则

### NAV-001 · 默认进入任务清单

普通网页和已安装 PWA 正常启动时,默认主视图必须是“任务”清单。用户不得先经过欢迎页、仪表盘、分类管理页或设置页才能查看和操作任务。

### NAV-002 · 桌面常驻侧边导航

桌面视口必须提供常驻的窄侧边导航,主要入口按“任务、历史、垃圾箱”呈现。设置与备份入口必须位于侧边导航底部,不得与三个高频主视图混排为同级工作区。设置中必须按 `localization.md` 提供语言分段控件,不得在任务主工具栏另设语言按钮。

### NAV-003 · 移动端三个底部标签

移动视口必须使用固定的三个底部标签:“任务、历史、垃圾箱”。每个标签必须包含图标和可读名称,当前标签状态必须明确。设置与备份不得占用第四个底部标签。

### NAV-004 · 移动端低频入口

移动端任务页右上角菜单必须提供设置与备份入口。进入设置后必须能访问 `localization.md` 的语言分段控件;进入备份后必须能访问既定完整备份导出与导入能力。返回时回到任务清单,不得要求经过历史或垃圾箱页面。语言不得占用第四个底部标签。

### NAV-005 · 分类不拆成独立页面

收件箱和自定义分类必须继续直接存在于任务清单。第一版不得新增独立分类管理页面或分类底部标签;分类创建、重命名、排序和删除均按 `task-categories.md` 在主清单上下文完成。

### NAV-006 · 响应式导航不得遮挡内容

桌面侧边导航和移动底部标签不得遮挡任务清单、编辑器内容、全局快速新增或移动端固定 `+`。移动底栏必须计入设备安全区和页面底部内容间距,页面不得因导航产生横向溢出。

### NAV-007 · 会话内恢复任务浏览上下文

用户在同一应用会话内从任务页切换到历史或垃圾箱再返回时,必须恢复离开前的任务页滚动位置、各分类展开或折叠状态以及各分类“已完成”区域的展开或折叠状态。

尚未提交的快速创建文字必须继续由 `quick-task-creation.md` 的草稿规则保留并能从原入口继续编辑。返回任务页时不得自动重新打开此前的任务编辑器、自动聚焦快速输入或主动弹出移动端键盘。

若用户从打开的任务编辑器导航离开,必须先按 `task-editing.md` 尝试保存最新有效内容;返回任务页时编辑器保持关闭。

### NAV-008 · 跨重启保留设备偏好而不恢复临时视图

刷新页面或彻底重开普通网页与已安装 PWA 后,当前设备必须恢复用户最后一次手动选择的界面语言、明确设置的分类展开或折叠状态和各分类“已完成”区域展开或折叠状态。没有语言偏好时按 `localization.md` L10N-005 选择;新建分类默认展开,从未手动调整过的“已完成”区域默认折叠。

新应用会话必须从任务清单顶部开始,不得恢复旧滚动位置、任务编辑器、输入焦点或移动端键盘。语言与折叠状态属于当前设备界面偏好,不得进入完整数据备份。

### NAV-009 · 覆盖导入后使用默认视图

完整备份覆盖导入成功后,必须按 `backup-import.md` 清除导入前折叠偏好,从任务清单顶部显示全部展开的导入分类和默认折叠的“已完成”区域。不得按名称或标识猜测继承旧折叠偏好,但必须保留当前设备语言;导入未成功时导航、语言和折叠状态保持不变。

### NAV-010 · 主动查看被恢复任务

恢复成功反馈不得自行离开垃圾箱。只有用户选择其中的“查看任务”时,应用才能切换到任务页,展开目标分类;若目标任务为已完成,还必须展开该分类的“已完成”区域。随后必须把任务滚动到可见位置并短暂高亮,但不得打开任务编辑器、聚焦输入框或弹出移动端键盘。

这次用户主动定位可以覆盖 NAV-007 原本要恢复的滚动与折叠视图,但系统为定位自动展开的区域不得写成跨重启的用户折叠偏好。用户之后亲自调整折叠状态时,才按 NAV-008 持久化新偏好。

### NAV-011 · 主动查看经选择器移动的任务

任务行选择器移动成功后必须保持当前任务页滚动位置。只有用户选择反馈中的“查看任务”时,应用才能展开目标分类及必要的“已完成”区域,把目标任务滚动到可见位置并短暂高亮。定位不得打开编辑器、聚焦输入或弹出移动端键盘。

系统为本次定位自动展开的区域不得覆盖跨重启折叠偏好;只有用户之后亲自调整折叠状态时才能按 NAV-008 持久化。编辑器分类字段移动不触发本规则,因为任务编辑器本身保持当前上下文。

### NAV-012 · 从编辑器查看历史后返回清单

从任务编辑器选择“查看历史”时,必须先按 `task-editing.md` 处理最新有效编辑,再关闭编辑器并进入 `history-interface.md` 定义的当前任务预筛选全局历史页。用户从该历史页返回任务页时,必须恢复 NAV-007 的清单滚动与折叠上下文,但不得重新打开此前任务编辑器、恢复输入焦点或弹出移动键盘。

### NAV-013 · Hash 路由、浏览器历史与冷启动归一化

M1 顶层页面必须使用 React Router 的 Hash 历史模式。`APP_BASE` 表示以 `/` 结尾的应用部署目录 URL;规范地址分别为任务 `APP_BASE + "#/"`、历史 `APP_BASE + "#/history"`、垃圾箱 `APP_BASE + "#/trash"`、设置 `APP_BASE + "#/settings"` 与备份 `APP_BASE + "#/backup"`。根部署时可简写为 `/#/` 等;部署到子路径时不得跳回源站根目录。不得为任务编辑器、单个任务、分类筛选或其他临时上下文新增 M1 深链路由。

同一应用会话内,用户选择另一个顶层页面时必须更新地址栏并新增一个浏览器历史项;重复选择当前页面不得新增项。浏览器后退与前进必须按该会话已经访问的顶层页面切换,并继续遵守 NAV-007、NAV-010、NAV-011 与 NAV-012 的任务页上下文和主动定位规则。React Router 不得持有或重建业务事实。

每次新文档启动,包括完整刷新、完全关闭后重开普通网页或已安装 PWA,以及从外部直接打开缺失、非任务或未知 Hash,应用都必须在呈现顶层页面前以历史 `replace` 归一化到任务路由,并按 NAV-008 从任务清单顶部开始。不得恢复冷启动深链目标,也不得用 `push` 把启动 Hash 留在返回链中。应用运行期间遇到缺失或未知 Hash 时同样必须以 `replace` 回到任务路由;已加载会话内手动输入一个已知顶层 Hash 则按普通同会话导航处理。路由、当前顶层页面和浏览器历史不得写入 `IndexedDB` 或完整备份。

## 验收 Gate

- 分别从普通网页和已安装 PWA 启动,验证首个可操作主视图都是任务清单,不存在前置欢迎页或仪表盘。
- 桌面视口持续显示任务、历史、垃圾箱侧边入口,设置与备份位于侧边栏底部;三项主视图均可一次操作到达。
- 桌面端从侧边栏底部设置访问语言控件,验证任务主工具栏和三个主视图导航没有常驻语言按钮或独立语言页面。
- 移动视口底部只显示任务、历史、垃圾箱三个带图标和名称的标签,当前状态明确且三项均可一次轻触到达。
- 移动端从任务页右上角进入设置与备份并返回,验证不占底部标签且无需经过其他页面。
- 移动端从任务页右上角菜单进入设置并切换语言,验证底部仍只有任务、历史、垃圾箱三个标签且选择立即生效。
- 检查桌面和移动端,验证不存在独立分类管理页;全部分类操作仍在主清单或任务分类选择器中完成。
- 在窄屏和带底部安全区的移动视口滚动到页面末尾并打开快速新增,验证底栏不遮挡任务、输入器或固定 `+`,页面无横向溢出。
- 在任务页改变滚动位置并分别折叠分类、展开“已完成”,切换到历史或垃圾箱后返回,验证当前会话内这些浏览状态均恢复。
- 带着非空快速创建草稿切换页面后返回,验证原入口仍能继续该草稿,但输入框不被自动聚焦且移动端键盘不自动弹出。
- 从打开的任务编辑器导航离开再返回任务页,验证最新有效内容已经保存或待保存,但编辑器不会自动重新打开。
- 手动选择语言并调整多个分类和“已完成”区域后刷新并彻底重开应用,验证语言与折叠偏好恢复;新建分类默认展开,未调整过的“已完成”默认折叠。
- 在页面中部结束会话并重新启动,验证进入任务清单顶部且编辑器、焦点和移动键盘均未恢复。
- 导出完整备份并检查数据载荷,验证不包含语言偏好、分类折叠、“已完成”折叠、滚动、编辑器或焦点状态。
- 成功覆盖导入后验证任务页位于顶部、导入分类全部展开且“已完成”默认折叠,当前语言保持;取消或失败后验证原浏览、语言和折叠状态保持。
- 在恢复成功反馈中选择“查看任务”,验证任务页展开正确分类及必要的“已完成”区域、滚动并短暂高亮目标任务,且编辑器、焦点和键盘都不出现。
- 不选择“查看任务”直接返回任务页,验证仍按 NAV-007 恢复原浏览上下文;通过“查看任务”触发的自动展开在重启后不覆盖用户原有折叠偏好。
- 从任务行选择器移动任务后验证当前滚动位置不变;选择“查看任务”后才展开目标区域、滚动并高亮任务,且编辑器、焦点和键盘不出现。
- 通过移动反馈自动展开目标区域后重启,验证用户原有跨重启折叠偏好未被系统定位覆盖。
- 从打开的任务编辑器进入当前任务历史再返回任务页,验证清单滚动和折叠上下文恢复,但编辑器、输入焦点和移动键盘不恢复。
- 从根部署依次进入 `/#/`、`/#/history`、`/#/trash`、`/#/settings` 与 `/#/backup`,验证地址栏 Hash 和可见顶层页面逐项一致;再以 `/desktop-pull/` 作为代表性 `APP_BASE` 重复验证,所有路由都保留应用基址。
- 在同一会话内依次选择任务、历史、垃圾箱并使用浏览器后退与前进,验证按访问顺序切换且重复选择当前页面不新增历史项;返回任务页时仍遵守 NAV-007 的浏览上下文规则。
- 分别在缺失 Hash、历史、垃圾箱、设置、备份和未知 Hash 上执行完整刷新、外部直接打开与完全关闭后的 PWA 新会话启动,验证在任何顶层内容出现前都以 `replace` 回到 `APP_BASE + "#/"` 并位于清单顶部,且后退不会重新进入启动 Hash 或形成归一化循环。
- 在已经加载的会话内手动输入一个已知顶层 Hash,验证按同会话导航打开对应页面;输入未知 Hash 则以 `replace` 回到任务页。检查路由表,验证没有任务编辑器、单任务或分类筛选深链。
