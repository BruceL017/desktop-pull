# ADR-002 · 当前状态与审计历史分离

## Status

Accepted

## Date

2026-07-24

Amended 2026-07-30 by D-097

## Decision Drivers

- 主任务页必须快速、可靠地读取当前任务状态。
- 产品需要完整历史查看,但明确不支持整份清单回滚到任意历史时点。
- 删除任务只需在垃圾箱内按任务恢复,不需要通过重放全局事件恢复系统。
- 当前状态和历史不能发生一边成功、一边失败的不一致。
- 第一版是设备本地 PWA,应控制数据迁移与损坏恢复复杂度。

## Context

“完整历史”容易被实现为事件溯源:只保存事件,启动时重放事件得到当前清单。但 Desktop Pull 的历史用途是审计与解释,恢复用途仅限垃圾箱中的单任务恢复。事件溯源会引入事件版本兼容、全量重放、投影修复和迁移成本,却不改善已确认的黄金路径。

另一个方案是分别写当前状态与历史,但不提供事务一致性。这会产生状态已经改变却没有历史,或历史显示成功但任务未改变的不可解释状态。

## Decision

- 当前任务、分类和顺序记录是主界面的读取源。
- 每次成功变更在一个原子事务中更新当前状态并追加匹配真实任务或分类主体的审计历史事件;主体结构以 ADR-011 为准。
- 历史不用于重建整份当前任务清单。
- 软删除任务记录为垃圾箱恢复提供数据;永久清理原子删除任务及其全部任务主体历史,并按 D-097 在同一事务去身份化其他保留记录中的目标结构化邻居与恢复锚点,不连带删除无关历史或独立分类主体事件。该维护动作不追加审计事件。
- 第一版不采用事件溯源。

## Consequences

- 当前清单无需重放历史即可快速加载。
- 状态与历史必须共享支持原子事务的本地持久化边界。
- 历史结构可独立服务筛选与摘要,但不能成为第二份可编辑状态。
- 当前状态 schema 和历史事件 schema 都需要版本迁移策略。
- 若未来需要任意时间点回滚或多设备事件合并,必须新建 ADR 复核数据模型。
