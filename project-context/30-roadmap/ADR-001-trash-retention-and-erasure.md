# ADR-001 · 垃圾箱保留与彻底清除

Accepted

2026-07-23

## Decision Drivers

- 误删任务必须有明确的恢复窗口。
- 第一版只有本地数据,应用关闭时没有服务端进程可执行定时任务。
- 用户主动永久删除后,任务内容、任务主体历史和其他保留记录中可识别该任务的结构化引用不得残留在当前活跃数据库或后续新备份中。
- 自动清理可能重复触发,不能造成错误或额外副作用。

## Context

历史时间线需要支持非破坏性恢复,但垃圾箱也不能无限增长。永久删除又与“历史只追加”发生冲突:若保留历史正文,任务并未真正清除;若删除历史,时间线不再绝对只追加。

被考虑的替代方案包括无限期保留垃圾箱、要求应用关闭时仍在第 30 天准点清理,以及永久删除后继续保留任务历史。它们分别带来无限增长、与纯本地边界冲突、以及删除不彻底的问题。

## Decision

- 删除任务先进入垃圾箱,从 `deletedAt` 起保留 30 天。同一软删除事务还必须按 D-112 / FORMAT-027 追加一条只含删除时分类、状态与移出前位置的任务主体事件;事件位置是带发生时标题的只读审计事实,不得取代 FORMAT-014 无标题恢复锚点。
- 达到 30 天后,应用运行期间自动清理;应用已关闭时,在下次启动或回到前台、展示或恢复交互之前尝试清理。数据库已经完整读取但启动、回到前台或运行期自动物理清理事务失败时,必须按 ADR-014 立即逻辑排除到期任务及其任务主体历史,并把其他保留记录中指向目标的结构化任务引用投影为 D-097 的不可用值后继续提供产品,不得重新展示或导出目标身份。
- ADR-013 明确 30 天是恢复操作被工作状态接受的截止时间;到期前已经接受的待保存恢复先于清理生效,不再属于应清理的垃圾箱任务。
- 有效恢复必须按 D-113 / FORMAT-028 在同一事务冻结插入完成后的实际分类、不变状态与同状态直接位置;事件不复制删除现场、生命周期、恢复锚点或锚点算法分支,也不参与当前或后续恢复。
- 自动清理必须幂等。
- 用户可在二次确认后永久删除单个任务或清空垃圾箱。
- 自动或手动永久清理必须在同一原子事务中从当前活跃数据库销毁任务内容及其全部任务主体历史,并把仍保留且语义上指向目标的 FORMAT-014 垃圾箱恢复锚点 `task` 分支和 FORMAT-021 历史任务邻居 `task` 分支分别整体替换为 `{ "kind": "unavailable" }`;后者同时移除目标 ID 与发生时标题。FORMAT-027 的删除前位置与 FORMAT-028 的恢复后位置都属于 FORMAT-021 扫描面;同一目标同时出现在当前恢复锚点时,两种严格分支各自投影而不得串型。后续新生成的完整备份也必须反映同一结果。ADR-011 定义的不含任务身份的独立分类主体事件不属于该任务事实链,不得被连带删除。
- 去身份化只处理 schema 明确定义且语义上指向目标的结构化任务引用,不得全文搜索或改写偶然含有相同 UUID、标题的用户自由文本,也不得删除引用所在的无关任务或历史。不可用值不含任务标识、标题、指纹、时间或映射,不能定位目标、阻止删除前备份导入或充当墓碑;FORMAT-014 恢复逻辑把它视为无效锚点并使用另一锚点或既定回退,FORMAT-021 只把它作为历史位置已去身份化的审计语义,不得用于恢复或当前排序。
- 正常业务事件不得直接产生 FORMAT-021 `unavailable`;它只可来自本 ADR 的永久清理、ADR-014 的清理待完成逻辑投影、导入到期过滤,或经完整校验确认是既往合法清理结果的旧备份迁移。
- 清理、目标主体历史删除和所有保留引用去身份化必须整批原子提交;任一步失败全部回滚。该维护动作不追加历史、不占用 `operationSequence` 且重复执行幂等。
- “不可恢复”只承诺当前 Desktop Pull 数据库及其后续新备份内没有恢复入口。产品无权查找、修改或销毁用户此前保存到产品外的删除前备份;用户主动覆盖导入这类有效备份时,其中的任务及当时历史可以按备份快照重新进入当前数据库,但导入时已经到期的垃圾箱任务仍按既定过滤排除。
- 第一版不得为永久清理任务保留跨覆盖导入的隐藏墓碑、删除黑名单或第二持久化事实源,也不得用当前数据库后来发生的永久清理拒绝一份本应有效的删除前备份。
- 单任务永久删除与清空垃圾箱确认必须明确说明:当前设备中的任务内容和任务主体历史将被清除且不进入新备份,但用户此前导出的备份可能仍含这些内容,之后主动导入可能使其重新出现。不得使用“从所有副本永久消失”或“永远无法从任何地方恢复”等超出产品控制范围的承诺。
- 因此,“历史只追加”仅适用于任务仍处于可恢复生命周期内;永久清理可以删除目标主体事件,并只按 D-097 / D-106 去身份化其他保留事件中的目标任务结构化引用。

## Consequences

- 用户最多有 30 天恢复误删任务。
- 应用长时间关闭或任一自动清理事务暂时失败时,物理清理可能晚于到期时刻;但到期任务及其任务主体历史必须在启动首次展示前、回到前台恢复交互前或运行期到期时已经物理清理或按 ADR-014 完成逻辑隔离,保留记录中的目标引用也必须在逻辑状态与新备份中先去身份化。
- 永久清理后,历史时间线中不会再出现该任务,可能形成无法从产品内解释的时间间隔。
- 分类删除等独立分类主体事件可以保留发生时分类名称和汇总数量,但不得保留已永久清理任务的标识或标题;其他保留任务主体事件可以继续存在,其中指向已清理任务的 FORMAT-021 位置邻居只能显示不可用语义。FORMAT-027 与 FORMAT-028 主体被清理时都随全部主体历史消失;只作为其他事件邻居出现时才执行窄幅去身份化。主体边界以 ADR-011 为准。
- 用户自行保管的删除前备份可能继续含有已清理任务;Desktop Pull 不能替用户销毁产品外文件。主动覆盖导入这类备份属于恢复整个旧快照,不是撤销当前数据库中的永久清理操作。
- 实现必须支持可控时钟与重复清理测试。
- 若未来改为云同步,必须新建 ADR 复核服务端清理与多设备一致性,不能直接沿用本地触发规则。
