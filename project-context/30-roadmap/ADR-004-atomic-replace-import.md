# ADR-004 · 完整备份采用原子覆盖导入

## Status

Accepted

## Date

2026-07-24

Amended 2026-07-30 by D-097

## Decision Drivers

- 完整备份必须能确定性地恢复任务、分类、顺序、垃圾箱和历史。
- 第一版只服务单个用户且不提供同步,不应为导入建立一套冲突合并系统。
- 覆盖现有本地数据库具有破坏性,必须为误选文件或误确认保留产品外的恢复出口。
- 导入失败不能留下新旧数据混合或部分历史丢失的状态。

## Context

候选方案包括把备份合并进当前数据库、直接覆盖当前数据库,以及先生成安全备份再原子覆盖。合并需要处理重复任务标识、分类同名或缺失、顺序位置冲突及历史链分叉;这些问题与跨设备同步中的冲突处理本质相同,超出第一版本地单用户产品的边界。

直接覆盖虽然简单,但误选备份或确认错误会不可逆地销毁当前数据。先生成当前数据库副本并启动下载再覆盖,可以在不引入合并语义的前提下保留恢复出口。

## Decision

- 第一版只支持完整覆盖导入,不支持合并、去重或选择性导入。
- 写入前完整校验备份格式、版本和记录关联,并展示覆盖摘要。
- 最终确认前先成功生成当前数据库的完整安全备份并启动下载,再进行独立的二次确认。
- 清除当前核心数据、排除导入时已经到期的垃圾箱任务及其全部任务主体历史、把其余待导入保留记录中指向这些到期目标的结构化任务邻居与恢复锚点替换为 D-097 的 `{ "kind": "unavailable" }`、写入其余待导入数据,必须在一个覆盖所有相关 `IndexedDB` object stores 的原子事务中完成。ADR-011 定义的独立分类主体事件、无关任务与无关历史不得因某个任务到期而被连带排除。
- 任一校验、安全备份、到期过滤、引用扫描、去身份化或写入步骤失败时,当前数据库保持不变。

## Consequences

- 备份恢复和设备迁移具有单一、可测试的结果,无需冲突解决界面或隐式合并规则。
- 用户不能用第一版导入能力把两份任务库拼接起来,也不能选择性导入部分任务。
- 实现必须提供版本校验、关联完整性校验、导入摘要、当前库安全导出和跨对象存储事务测试。
- 成功覆盖后,旧数据库只存在于导入前启动下载的安全备份中,产品内不提供覆盖撤销。
- 导入后的运行时必须重新读取新数据库,导入前的自动保存、草稿重试和延迟回调不得写回覆盖后的状态。
