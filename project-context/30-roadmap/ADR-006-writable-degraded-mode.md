# ADR-006 · 写入故障时采用可写降级态

## Status

Accepted

## Date

2026-07-27

Amended 2026-07-30 by D-097

Amended 2026-08-04 by D-117

## Decision Drivers

- Desktop Pull 的日常任务整理不能因一次本地写事务失败就整体不可用。
- 未持久化变更不能被伪装成保存成功,否则违背“不丢失工作脉络”的北极星。
- 已确认的状态与历史原子性不能因可用性目标而放宽。
- 第一版仍需维持 `IndexedDB` 单一持久化事实源,不引入第二套本地或远程数据库。

## Context

候选方案包括写入失败后全面只读、静默在内存继续并显示保存成功、引入第二套持久化后备,以及显式的当前会话待保存队列。全面只读会让一次瞬时故障阻断全部任务工作;静默内存模式会制造数据已经安全保存的假象;第二持久化后备则引入多事实源、恢复裁决和迁移复杂度。

显式待保存队列允许契约明确支持的日常正式业务操作继续,同时把持久化状态、会话工作状态和会话终止风险如实暴露给用户。单任务永久清理、清空垃圾箱、自动永久清理和完整备份导入必须等待存储恢复,避免在无法兑现原子清理或安全备份时造成损失。

## Decision

- 核心数据已经成功加载后,正式任务、分类或历史业务事务失败使产品进入可写降级态,而不是全面只读。
- 契约明确允许入队的正式业务操作继续作用于“已持久化状态 + 有序待保存队列”的工作状态;这包括 D-117 所属的分类删除原子操作,但不扩大下一条列出的受限操作。
- 所有待保存变更持续标明未安全保存,后台按顺序重试;每条变更只有在状态和历史原子提交后才移出队列。
- 降级态提供包含工作状态和对应历史的应急完整备份;工作状态中已经到期但尚未物理清理的目标及其主体历史被排除,保留记录中的目标结构化引用投影为 `{ "kind": "unavailable" }`。
- 单任务永久清理、清空垃圾箱、自动永久清理和完整备份导入暂停到队列清空。
- 垃圾箱任务到达 `expiresAt` 后立即不可恢复且不进入应急备份;保留记录中指向目标的结构化任务邻居与恢复锚点同时从全部逻辑视图投影为 D-097 的不可用值,只把物理删除与去身份化写入延后到持久化恢复。
- 上一条由 ADR-013 细化:它只适用于到期前尚未接受恢复的任务;到期前已经进入待保存队列的恢复继续有效、进入应急备份并在到期清理前补写。
- 启动、回到前台或运行期自动到期清理事务失败都遵守 ADR-014 的清理待完成态。清理失败本身不进入用户待保存队列;若之后的日常业务写入也失败,再按本 ADR 建立队列,并在队列补写后重试物理清理。
- 自动清理、迁移工件清理等维护事务不得仅因本 ADR 进入用户待保存队列;它们必须遵守各自已接受 ADR 或继续保持为显式开放项。
- 待保存队列只存在于当前运行会话;第一版不引入第二持久化后备,关闭、崩溃或重载前未补写且未导出的变更可能丢失。
- 本 ADR 细化 ADR-002 和 ADR-003 的故障行为,不改变“持久化成功必须原子”和“IndexedDB 是唯一持久化事实源”。

## Consequences

- 瞬时写入故障不会阻断创建、编辑、拖拽和恢复等日常路径。
- 界面必须区分已持久化状态与待保存工作状态,并提供全局状态、重试和应急导出。
- 实现需要有序操作队列、失败注入、部分补写重试和应急快照测试。
- 用户在降级态终止会话仍可能丢失未导出的待保存变更;产品必须持续呈现该风险。
- 启动时因非迁移故障无法初始化或完整读取既有数据库时遵守 ADR-008,不得把可写降级态误用于尚无可信基线的场景。
- 清理待完成态可以与本 ADR 的可写降级态重叠;前者表达到期内容或目标结构化引用尚有本地物理残留,后者表达用户操作尚未安全保存,界面不得把两种风险混成一个计数。
