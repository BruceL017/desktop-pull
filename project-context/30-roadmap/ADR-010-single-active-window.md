# ADR-010 · 同一存储作用域只允许一个活动窗口

## Status

Accepted

## Date

2026-07-28

## Decision Drivers

- 两个窗口各自自动保存、拖拽和维护内存待保存队列会产生无法稳定解释的覆盖顺序。
- 第一版不包含逐记录冲突解决、跨窗口队列合并或多人协作模型。
- 永久删除和覆盖导入后,其他窗口不得继续持有或展示已经失效的任务数据。
- ADR-009 的隔离迁移需要一个无其他窗口写入或持有数据库连接的排他窗口。

## Context

候选方案包括允许所有窗口直接写入并接受最后提交覆盖、在每条记录上实现冲突检测、提供持续加载数据的只读镜像,以及只允许一个活动窗口。`IndexedDB` 可以串行提交事务,但不能替产品解释两个过期界面分别拖拽、自动保存或排队后的用户意图。

多写者和冲突解决会把单用户本地工具扩成同步系统。只读镜像仍会在后台挂起、永久删除或覆盖导入后展示陈旧敏感内容。单活动窗口牺牲同时打开多份任务视图,换取唯一、可解释的操作顺序和无损控制权移交。

## Decision

- 同一浏览器存储作用域内,普通网页标签页、独立窗口和已安装 PWA 任一时刻只能有一个活动窗口加载并操作核心数据。
- 其他窗口只显示应用已在另一窗口打开和“在此窗口继续”,不得读取或展示任务、分类、历史、垃圾箱、草稿或备份内容,也不得执行核心操作。
- 正常移交时,原活动窗口先停止接受新操作,立即提交待计时的最新有效编辑和草稿并等待进行中事务完成。只有数据库健康、正式待保存队列与草稿待保存快照均为空,且没有永久清理、覆盖导入或迁移流程时才能释放控制权。
- 新窗口取得排他控制权后必须重新完整读取当前活跃数据库,之后才能开放操作;原窗口必须丢弃已加载工作状态并转为非活动提示界面。
- 原窗口存在无法落盘的正式待保存变更或草稿快照时禁止移交。用户必须回到原窗口重试或导出应急备份;第一版不跨窗口搬运、合并或持久化内存队列。
- 原窗口正常关闭或崩溃后,排他控制权自然释放。其他窗口可以从已持久化数据库重新取得控制权;原窗口未导出的内存状态继续遵守 ADR-006 的会话丢失风险。
- 第一版不提供强制抢占。失去控制权的旧窗口必须在任何后续写入前检测所有权变化并保持非活动,不得以过期状态补写。
- 永久删除、清空垃圾箱、覆盖导入及 ADR-009 候选迁移从准备到提交完成期间暂停窗口移交。迁移复用同一排他控制权,并要求全部非活动窗口不持有核心数据库连接。

## Consequences

- 用户不能同时在两个窗口查看或编辑任务,但始终有且只有一个窗口提供完整一致的产品能力。
- 正常移交不会丢失有效编辑或草稿;存储故障时用户必须先在原窗口恢复或完成应急导出。
- 活动窗口崩溃仍可能丢失 ADR-006 已明确为仅内存的待保存状态,不会通过另一窗口猜测恢复。
- 实现需要跨标签页、窗口与安装形态共享的排他所有权机制,并在每次核心写入前防止失效所有者提交。
- 不需要多写者冲突解决、跨窗口操作日志合并或陈旧只读镜像同步。
