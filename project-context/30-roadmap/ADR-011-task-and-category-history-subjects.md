## Decision Drivers

- 分类创建、重命名、排序和删除本身没有合法任务主体,不能伪造任务标识或任务标题。
- 任务筛选和永久清理必须精确限定到一条任务的事实链,不能误删独立的分类管理事实。
- 分类删除同时产生一项分类事实和若干任务迁移事实,两者需要分别可读、可筛选和可备份。
- 已删除分类的名称与管理历史仍需脱离当前分类记录被完整解释。

## Context

既有历史模型要求每条事件都保存并显示任务标题,但八个动作组中已经包含不依附于任务的分类管理。给分类事件填入虚构任务字段会污染筛选和永久删除边界;省略分类管理事件又会让创建、改名、排序与删除无法追溯。把分类删除只展开成逐任务迁移事件也无法表达分类结构本身被删除的事实。

因此,历史需要一个明确的主体判别,让任务事实和分类事实共用同一全局时间线,但各自只携带真实存在的身份与快照。

## Decision

- 每条历史事件必须且只能是任务主体事件或分类主体事件,并保存可判别的主体类型。
- 任务主体事件的严格 `subject` 保存任务不可变标识与事件发生时用户原文任务标题,事件专属 `details` 保存该事件相关的分类语义快照。对 `task.content_changed`,事件发生时标题按 D-104 / FORMAT-019 精确为本次原子保存后的有效标题,标题新值只由主体表达;`task.created` 的主体标题精确为提交原文;其他事件继续保存各自操作发生时的有效标题。相关分类是自定义分类时保存发生时用户原文名称快照;相关分类是固定收件箱时只保存稳定系统身份并按 ADR-015 在当前语言下呈现,不得保存某一种语言的名称快照。D-105 / FORMAT-019 / FORMAT-020 明确内容变化、完成与重新打开事件都在 `details.categorySnapshot` 保存该快照;D-107 / FORMAT-022 明确创建详情保存同一分类快照及创建完成后的嵌套双邻居位置,不重复主体标题、操作时间或固定创建默认值;D-108 / FORMAT-023 明确优先级变化详情保存同一分类快照及不同的旧新优先级,不保存位置、排序或控件来源;D-109 / FORMAT-024 明确组内排序详情保存一份同类分类快照、一份语言无关状态及移动前后位置,不保存分类或状态新旧对、拖拽来源、绝对序号或内部排序键;D-110 / FORMAT-025 明确主动跨分类详情精确为 `{ status, source, target }`,来源与目标各只含发生时分类快照和位置,两侧分类引用必须不同,根状态只保存一次;D-111 / FORMAT-026 明确分类删除派生迁移详情精确为 `{ status, source, targetPosition }`,来源含被删 Custom 快照与整批前位置,固定 Inbox 只保存整批后的最终位置;D-112 / FORMAT-027 明确软删除详情精确为 `{ categorySnapshot, status, position }`,只冻结移出活动顺序前的分类、状态和同状态直接位置,不重复标题、时间、内容、优先级或恢复锚点;D-113 / FORMAT-028 明确恢复详情使用同名三字段,但只冻结插入完成后的实际分类、不变状态与同状态直接位置,不复制删除现场、生命周期、锚点或算法分支。分类主体事件只用于自定义分类,保存分类不可变标识和事件发生时用户原文名称,不得伪造任务标识、任务标题或任务关联;D-114 / FORMAT-029 进一步锁定 `category.created.details` 为精确 `{}`,分类 ID 与创建时名称只存在于公共主体;D-115 / FORMAT-030 锁定 `category.renamed.details` 只含改名前 `beforeName`,改名后的名称只由同一公共主体 `name` 表达;D-116 / FORMAT-031 锁定 `category.reordered.details` 只含移动前后方向严格的 Custom 分类邻居或自定义序列边界,被移动分类只由公共主体表达;D-117 / FORMAT-032 锁定 `category.deleted.details` 只含接受时活动迁移总数 `{ affectedTaskCount }`,被删分类仍只由公共主体表达。
- 任务新增、编辑、完成状态、优先级、移动归类、软删除和恢复产生任务主体事件。自定义分类创建、重命名、排序和删除产生独立分类主体事件。
- 分类删除在同一原子事务中产生一条精确符合 FORMAT-032 的分类主体删除事件:公共主体保留被删分类 ID / 名称,详情只保留接受时活动来源列表长度 `{ affectedTaskCount }`;每个实际迁入收件箱的任务另产生一条符合 FORMAT-026 的任务主体移动事件。未完成与已完成都计入,垃圾箱任务、到期残留、历史旧归属与草稿不计入;空活动分类保存 `0`。正常生产时分类事件后按来源权威总顺序形成 N 条完整任务事件集合;永久清理任务后可以删除部分或全部任务主体事件并留下 `eventOrder` 缺口,分类事件的发生时数量保持不变。分类删除事件不得保存受影响任务标识、标题、内容或数组来替代这些任务事件。
- 主清单内联创建空分类时,当前分类记录、`categoryOrder`、操作顺序进度与唯一一条 FORMAT-029 `category.created(eventOrder = 0, details = {})` 必须原子提交,不得创建或改变任务。选择器内新建分类并移动任务时,同一操作必须共享时间与顺序并原子产生该空详情分类事件与符合 FORMAT-025 的 `task.category_changed(eventOrder = 1)`;后者目标分类 ID / 名称必须与前者主体逐字一致,任务移动结果只归任务事件,不得把分类创建或任务移动拆成另一操作。任务后来永久清理会合法删除任务事件而独立保留分类事件,导入不得补建或拒绝该单边结果;反向孤立任务事件仍无合法来源。
- 分类重命名成功时,当前分类记录名称、操作顺序进度与唯一一条 FORMAT-030 `category.renamed(eventOrder = 0)` 必须原子提交。公共分类主体保存同一不可变 ID 与改名后的用户原文名称,`details` 精确只保存更新前 `{ beforeName }`;两者必须不同。分类顺序、任务顺序及全部任务事实不变,不得产生任务主体事件。处理后名称与当前名称相同不构成事件;后来再次改名、排序、删除或任务永久清理不得回写或移除该独立事实。
- 分类排序成功时,`categoryOrder`、操作顺序进度与唯一一条 FORMAT-031 `category.reordered(eventOrder = 0)` 必须原子提交。公共主体保存被移动 Custom 分类发生时 ID / 名称,详情精确为 `{ beforePosition, afterPosition }`;两个位置各只含方向严格的前后 Custom 分类 ID / 名称或 `start` / `end`,禁止 Inbox、`unavailable`、绝对序号和排序键。位置内双分类邻居不同且非主体,跨位置允许相邻移动复用同一邻居但名称一致。分类记录、任务与任务顺序不变;原位、取消、无效落点或只有一个 Custom 不构成事件。后来改名、排序、删除及任务永久清理不回写或移除本事件。
- 任务筛选只返回该任务的任务主体事件,不返回纯分类主体事件。分类筛选按分类不可变标识同时覆盖该分类的管理事件和归入该分类的任务事件;FORMAT-029 创建事件直接按公共 `subject.categoryId` 匹配,紧凑行使用同一主体的创建时名称,不得查询当前分类名称补写。FORMAT-030 改名事件同样只按公共 `subject.categoryId` 匹配,从 `details.beforeName` 到 `subject.name` 呈现并以两者搜索,不得查询当前分类或后来事件补值。FORMAT-031 排序事件也只按公共主体 ID 匹配被移动分类,不得因其他分类只作为邻居出现而形成筛选命中;名称搜索可读事件自身主体与邻居名称,但不得查询当前名称。任务事件只涉及一个分类时匹配该分类,包括按 FORMAT-024 的 `categorySnapshot` 匹配组内排序;FORMAT-025 跨分类事件只按 `target.categorySnapshot` 匹配目标分类,`source.categorySnapshot` 仍保留用于解释事件但不形成来源筛选匹配。分类删除主体事件匹配被删除分类,FORMAT-026 逐任务迁移事件只匹配固定目标收件箱,其来源快照同样不形成来源筛选命中;FORMAT-027 软删除只按删除时 `categorySnapshot` 匹配,不得按垃圾箱或恢复后的当前分类重算;FORMAT-028 恢复只按实际恢复 `categorySnapshot` 匹配,不得按删除时分类、垃圾箱或后来当前分类重算。
- 分类被删除后,其分类主体历史继续保留、可搜索、可筛选并进入完整备份;不得按时间、数量或某个任务的永久清理连带删除。
- 事件详情需要任务位置上下文时必须复用 D-106 / FORMAT-021:前邻居只能是 `start | task | unavailable`,后邻居只能是 `end | task | unavailable`,`task` 精确为 `{ kind, taskId, title }` 且标题固定为事件发生时用户原文。D-107 / FORMAT-022 把创建后的两侧邻居严格嵌套在 `position` 中,只描述初始分类未完成序列。D-109 / FORMAT-024 在 `beforePosition` 与 `afterPosition` 中各复用同一严格位置形状;每个位置内双任务邻居必须不同且非主体,跨两个位置允许同一邻居重复。D-110 / FORMAT-025 在 `source.position` 与 `target.position` 中复用该形状;正常事件中四个可识别邻居 ID 必须全局两两不同且非主体,不得产生 `unavailable`,但来源唯一任务移入目标空状态区时两侧都为 `start / end` 合法。D-111 / FORMAT-026 在整批前 `source.position` 与整批后 `targetPosition` 中复用该形状;每个位置内部仍不同且非主体,但批次相对顺序不变使同一迁移邻居跨两侧重复合法且必要,不得套用 FORMAT-025 的全局互异规则。D-112 / FORMAT-027 在软删除移出前单一 `position` 中复用该形状;正常双任务邻居不同且非主体,并只在删除事务发生时与 FORMAT-014 无标题恢复锚点表达同一现场。D-113 / FORMAT-028 在恢复插入完成后的单一 `position` 中复用该形状;正常双任务邻居不同且非主体,但它是锚点算法执行后的审计结果,不得成为恢复输入。邻居任务后来改标题、移动、改变完成状态或软删除不回写该事实;历史邻居不得驱动当前顺序或垃圾箱恢复,也不得与 `task` 分支仅含 `{ kind, taskId }` 的 FORMAT-014 恢复锚点混用。
- FORMAT-031 另定义独立的方向严格分类邻居联合,不得复用 FORMAT-012 或 FORMAT-021:前侧只接受 `start | category`,后侧只接受 `end | category`,`category` 精确为 `{ kind, categoryId, name }` 并只表示 Custom 分类。每个位置内双分类 ID 不同且非主体;跨前后位置允许同一邻居重复,同一 ID 的名称必须逐字一致,不得套用 FORMAT-025 四槽全局互异。该联合不接受 Inbox 或 `unavailable`,主体或邻居后来改名、排序或删除不回写快照,位置不得驱动或重建当前 `categoryOrder`。
- 永久清理任务删除以该任务为主体的全部事件。独立分类主体事件只保存分类事实与汇总数量,不因其中曾有该任务而删除;其他任务主体事件也继续保留,但其中语义上指向目标任务的 FORMAT-021 `task` 邻居必须按 D-097 / D-106 整体原子替换为 `{ "kind": "unavailable" }`,并移除目标标识和标题。正常事件生产者不得直接产生 `unavailable`;多个邻居去身份化使 FORMAT-024 的前后位置、FORMAT-025 的来源与目标位置、FORMAT-026 的来源与最终位置、FORMAT-027 的删除前位置或 FORMAT-028 的恢复后位置结构收敛时仍保留对应合法事件。FORMAT-026 同一邻居在两侧重复时必须把全部出现位置一起投影,不得只替换一侧。若 FORMAT-027 邻居同时存在于当前垃圾箱任务的 FORMAT-014 恢复锚点,带标题历史分支与无标题锚点必须按各自 schema 独立投影。该窄幅去身份化不等于删除或任意改写保留事件。
- FORMAT-031 不含任务引用,任务永久清理不得扫描、删除或改写分类排序事件。分类删除也不是分类身份永久清理,因此排序邻居继续保留发生时 ID / 名称,没有 `unavailable` 投影或前后位置合法收敛例外。

## Consequences

- 全局历史的紧凑行必须根据主体类型显示发生时任务标题或分类名称。
- 分类创建历史只由本地化动作与创建时分类主体名称呈现,展开详情没有额外字段;后来重命名、排序或删除不得回写该主体或 `{}`,当前分类结构也不得通过重放该事件重建。
- 分类重命名历史必须从 FORMAT-030 `beforeName` 到公共 `subject.name` 呈现;动作和方向词按当前语言本地化,两个用户名称逐字保留。筛选只读主体分类 ID,搜索只读事件自身旧、新名称;当前分类记录和后续历史既不补写本事件,也不得通过重放本事件建立当前名称。
- 分类排序历史必须从公共主体与 FORMAT-031 完整前后位置呈现;紧凑摘要只读后位置的顶部、末尾或发生时前邻居,分类筛选只读主体 ID,搜索只读事件自身名称,不得因邻居形成筛选命中或读取当前顺序。
- 创建历史必须从提交时任务主体标题与 FORMAT-022 的初始分类及创建后位置共同呈现,不得显示入口、草稿代次、默认值或当前重算位置;内容变化历史必须从保存后任务主体标题与 FORMAT-019 的精确详情字段共同呈现事实;完成与重新打开历史必须从各自事件类型与 FORMAT-020 呈现;优先级变化历史必须从 FORMAT-023 呈现不同的旧新值,不得显示控件来源、位置或后来当前优先级;组内排序历史必须从 FORMAT-024 呈现发生时状态区与移动前后位置;主动跨分类历史必须从 FORMAT-025 呈现一次状态、来源移除前与目标插入后事实,并只按目标分类筛选;分类删除派生迁移必须从 FORMAT-026 呈现一次状态、来源整批移除前与最终收件箱位置,并只按收件箱筛选;软删除必须从 FORMAT-027 呈现删除时分类、状态与移出前位置,并只按删除时分类筛选;恢复必须从 FORMAT-028 呈现实际恢复分类、状态与插入后位置,并只按实际恢复分类筛选;分类创建只从公共主体和 FORMAT-029 空详情呈现;分类重命名只从公共主体和 FORMAT-030 单字段详情呈现;分类排序只从公共主体和 FORMAT-031 双位置详情呈现;分类删除只从公共主体和 FORMAT-032 单一发生时计数呈现。十四类已锁定事件不得显示界面或手势来源、绝对序号、内部排序键或当前顺序,也不得从后来任务状态或归属补值、在详情中建立标题或分类名称新值副本或重复状态方向。任务邻居去身份化使任务排序位置无法表达具体边界或邻居时,紧凑摘要使用中性调整语义而不查询当前顺序;FORMAT-031 不存在该分类邻居例外。
- 历史存储与备份 schema 需要使用带主体判别的联合结构,不能要求所有事件共享任务字段。
- 历史任务邻居的发生时标题是审计事实,与邻居当前标题不一致不构成损坏;移动、软删除或完成状态变化后的保留任务仍可作为该历史引用的合法解析目标。
- 分类删除后永久清理其中部分或全部任务,分类删除事件仍保留 FORMAT-032 原始 `affectedTaskCount`;该数量是操作接受时实际迁移活动任务的发生时汇总,不是当前任务数、当前可恢复数或剩余 FORMAT-026 数量。
- 分类主体历史没有第一版产品内的单条删除或分类级永久清理入口。
- ADR-001 所称删除任务的“全部历史痕迹”包括该任务的全部任务主体事件,以及其他保留记录中对该任务结构化引用的可识别身份与标题;它不包括不携带任务身份的独立分类主体事件,也不授权删除无关任务主体事件。
- 同一 FORMAT-025 跨分类移动不会同时出现在来源与目标分类筛选结果中;分类筛选只读取 `target.categorySnapshot`,而展开记录仍能审计完整来源与目标。FORMAT-026 派生迁移只匹配固定收件箱,来源被删分类仍只在展开与摘要中出现。FORMAT-027 软删除只匹配其删除时分类,恢复后当前分类和恢复落位都不得改变该筛选结果;FORMAT-028 恢复则只匹配其实际恢复分类,不得按删除时分类或后来当前分类重算。两种位置都只供审计。
- FORMAT-031 分类排序事件只匹配公共主体分类,四个邻居槽位不扩展分类筛选结果;主体或邻居后来改名、排序或删除不改变该归属,位置只供审计。
- 历史中的系统分类、任务状态、精确事件类型和位置边界由语言无关语义按当前界面语言呈现,动作组从精确事件类型稳定映射;用户原文快照不随语言切换变化。
