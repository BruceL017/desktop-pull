# 任务模型(Task Model)

## 状态

- 任务只有“未完成”和“已完成”两种状态;新增任务默认为未完成。
- 标记完成不会删除任务,也不会改变任务的分类、优先级或持久手动顺序。
- 已完成任务可以重新设为未完成。
- 每次实际状态切换都作为一条已提交操作进入历史时间线。

## 内容

- 每个任务从创建起具有不可变的规范小写 UUID v4 唯一标识;当前状态、历史、垃圾箱和完整备份始终复用该标识,不得在导出或导入时重新映射。标题只用于展示和编辑,不作为任务身份。
- 标题必填,用于在清单中识别任务。
- 合法标题按用户提交原文保存;是否非空只用于校验,不得把去除首尾空白后的临时值写回任务。
- 不同任务可以使用完全相同的标题,不得按标题自动合并或覆盖。
- 备注在产品交互上可选,用于保存标题之外的补充信息;任务记录始终使用字符串,没有备注时保存 `""` 而非缺失或 `null`。
- 第一版备注是保留换行的多行纯文本;不包含富文本、Markdown 语义、内嵌清单、附件或图片。
- 第一版不包含截止日期、提醒、重复规则、子任务或附件。

## 生命周期与时间

- 每条逻辑任务只有 `id`、`title`、`notes`、`status`、`priority`、`createdAt`、`updatedAt` 七个公共字段及 `lifecycle` 判别字段,合计八个顶层字段;活动与垃圾箱状态由 `lifecycle` 严格判别,不依赖可空删除字段猜测。`status` 只使用语言无关的 `open` / `completed`。
- 活动任务生命周期只表达 `active`;其分类和持久顺序只存在于权威分类任务顺序中,任务记录不保存副本。
- 垃圾箱生命周期保存删除时间、30 天到期时间、删除时分类快照及前后恢复锚点;删除时内容、状态与优先级继续使用任务公共字段,不建立重复快照。
- `createdAt` 是创建操作时间且永不改变。`updatedAt` 是最近一次实际改变该任务内容、状态、优先级、分类、顺序或生命周期的原操作时间;重试、导入导出、无变化操作、维护清理和周围任务被动位移不重新计时。
- 恢复复用原任务身份与创建时间,移除全部垃圾箱专用字段后重新成为活动任务;只把原任务插入当前清单,不覆盖或移动其他任务。

## 优先级

- 每个任务必须且只能有一个优先级。
- 合法值为 `P0`、`P1`、`P2`、`P3`、`P4`、`P5`,优先级从 `P0` 到 `P5` 依次降低。
- 新增任务默认使用 `P3`;用户创建后可直接从任务行优先级菜单修改,也可在任务编辑器中修改同一字段。
- 默认值满足必填约束,用户无需每次手动选择优先级才能创建任务。

## 手动顺序

- 默认任务顺序由用户拖拽决定,并作为任务清单的持久顺序。
- 快速新增会话的首条任务插入目标分类未完成区顶部;同一会话后续任务紧随上一条,以输入顺序建立新任务的初始持久位置。
- 修改任务优先级不会自动改变任务位置。
- 一次成功拖拽只改变目标任务的顺序位置,并作为已提交的移动操作进入历史时间线。

## 分类

- 每个活动任务必须且只能有一个当前分类,并只由权威分类任务顺序表达;任务记录不保存第二份归属。垃圾箱任务没有活动分类位置,只在生命周期保留删除时分类快照用于展示与恢复。
- 系统提供具有稳定系统身份的固定收件箱分类;简体中文显示“收件箱”,英文显示 `Inbox`,任务归属不得用任一显示文本作为身份。新增任务未选择自定义分类时,默认进入该系统分类。
- 全局快速新增始终以收件箱为目标;从分类标题发起的快速新增直接以该分类为目标,不再要求选择分类。
- 自定义分类在任务创建时不是必填选项;用户无需处理分类即可先把任务创建进收件箱。
- 用户可以创建具有不可变规范小写 UUID v4 标识的自定义分类,并在任务创建后随时把任务移到任一已有分类、新建分类或收件箱。固定收件箱使用独立系统身份,不占用 UUID。
- 创建后既可直接跨分类拖拽,也可从任务行“移动到…”或编辑器分类字段使用同一个单选选择器。选择器移动保持完成状态并把任务放到目标分类对应状态区顶部;选择“新建分类”时在选择器内完成命名并按同一规则立即归入当前任务。
- 用户也可以脱离具体任务,从主清单分类列表末尾原地新建空分类;成功后分类追加到现有自定义分类末尾,不自动创建任务。
- 自定义分类名称去除首尾空白后必须非空且唯一;无论当前界面语言为何,系统名称“收件箱”与 `Inbox` 都不可用于自定义分类,`Inbox` 按 ASCII 大小写不敏感匹配。
- 删除仍含任务的自定义分类时,其中任务按原相对顺序整体追加到收件箱末尾,任务本身不被删除。
- 删除任何自定义分类都先经过一次阻断式确认;非空分类的确认必须明确任务数量以及“移入收件箱而非垃圾箱”的后果。若分类标题入口还有未提交草稿,同一确认还必须展示可识别预览并明确草稿将被丢弃;取消完整保留,确认后草稿按入口与代次随分类删除原子消费,不迁移、不创建任务、不进垃圾箱或历史。
- 自定义分类可以从标题菜单原地重命名;分类身份、任务归属和顺序不变,固定收件箱不可重命名。
- 收件箱固定在分类列表第一位;自定义分类可从标题非控件区域直接拖拽并持久化顺序,排序不改变其中任务。
- 分类创建、重命名、排序和删除各自以分类主体事件进入历史;分类删除造成的每个任务归属变化另以该任务为主体进入时间线。
- 第一版不支持一个任务同时属于多个分类,也不提供标签模型。
