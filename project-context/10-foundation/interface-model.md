# 界面模型(Interface Model)

## 应用导航

- 普通网页和已安装 PWA 默认直接进入任务清单,不经过欢迎页或仪表盘。
- 顶层页面使用相对于应用部署基址 `APP_BASE` 的可见 Hash 路由:任务 `APP_BASE + "#/"`、历史 `APP_BASE + "#/history"`、垃圾箱 `APP_BASE + "#/trash"`、设置 `APP_BASE + "#/settings"`、备份 `APP_BASE + "#/backup"`。同一会话内页面切换支持浏览器后退与前进。
- 桌面端使用常驻窄侧边导航切换任务、历史和垃圾箱,设置与备份位于侧边栏底部。
- 移动端使用任务、历史和垃圾箱三个底部标签;设置与备份从任务页右上角菜单进入。
- 桌面与移动设置使用同一个带地球图标的语言行和选项为 `简体中文` 与 `English` 的双选分段控件;语言不成为任务工具栏按钮或移动端第四个标签。
- 分类仍直接存在于任务清单,不建立独立分类管理页面或底部标签。
- 当前会话内从历史或垃圾箱返回任务页时,恢复滚动、分类折叠和“已完成”折叠状态;快速创建草稿仍可继续,但任务编辑器、输入焦点和移动键盘不自动恢复。
- 刷新、完全关闭后重开普通网页或 PWA,以及直接打开缺失、非任务或未知 Hash 时,先以替换当前历史项的方式回到任务路由;随后恢复当前设备最后一次手动选择的界面语言以及分类与“已完成”折叠偏好,并从任务清单顶部开始,不恢复冷启动深链目标、编辑器、焦点或键盘。没有语言偏好时重新执行 D-087 的首次匹配。
- 完整备份覆盖导入成功后从清单顶部以“分类展开、已完成折叠”的默认状态展示,不继承导入前同名分类偏好,但继续使用当前设备语言;导入未成功时当前视图不变。

## 响应式验收基线

- 两分钟首次用户参考环境分别是 Windows 11 当前 Chrome Stable 的 `1440 x 900` CSS px、100% 页面缩放、鼠标与实体键盘,以及当前 iOS Safari 的 `390 x 844` CSS px 竖屏、单指触控与系统软键盘。
- `1280 x 720` CSS px、100% 页面缩放是桌面非计时边界视口;`360 x 800` CSS px 竖屏是移动非计时边界视口。两者必须完成同一核心路径且没有横向溢出、内容遮挡或不可达控件。
- D-090 的其他正式支持组合执行相同非计时功能 Gate。首次用户两分钟结果只来自两个参考环境,不得用熟练实现者自测或把用户样本乘以全部浏览器组合。

## 多窗口入口

- 同一存储作用域只有活动窗口进入正常应用导航并加载任务数据。
- 其他网页标签页、窗口或已安装 PWA 只显示“Desktop Pull 已在另一窗口打开”和明确的“在此窗口继续”,不显示任务、历史或垃圾箱预览。
- 正常移交完成后,新活动窗口按新会话规则从任务清单开始;原窗口移除数据界面并显示相同的非活动提示。

## 主任务页

- 主页面采用纵向分类清单,不采用横向看板。
- 收件箱和每个自定义分类各自显示为一个可折叠分组。
- 任务在分类分组内纵向排列。
- 用户可以在同一分组内拖拽排序,也可以把任务拖到另一分组并放在指定位置。
- 桌面端与移动端使用相同的信息结构;响应式布局只改变尺寸与控件呈现,不改变分类和任务关系。
- 每个分类默认展开未完成任务,并在分组底部提供默认折叠的“已完成”区域。
- 已完成区域只是状态视图;任务底层分类和手动顺序不变,重新设为未完成后按原顺序位置出现。
- 最后一个分类分组下方常驻“新建分类”入口;触发后在原位置展开并聚焦单行名称输入,移动端同时打开软键盘。
- 只有桌面 `Enter`、移动端“添加”或确认图标明确提交才创建分类;输入法组合回车、失焦、点击外部、`Esc` 或取消都不创建。确认图标优先于其造成的失焦。
- 独立新建分类成功后恢复入口并停留在主清单;不弹窗、不跳页、不自动创建任务,入口与全局任务快速新增明确分离。无效名称保留文字、焦点和键盘并行内提示;未提交名称在取消或刷新后清除且不进入备份。
- 独立新建分类成功时只形成 `category.created(eventOrder = 0)`:创建时分类 ID 与名称写在公共分类主体,FORMAT-029 `details` 精确为 `{}`;不得记录入口、位置、设备、语言或任务信息。
- 自定义分类标题菜单提供“重命名”;触发后标题原地变成单行输入,一次提交立即保存且不弹确认。有效新名称经统一规则处理后,真实变化原子更新当前分类名称并只追加 `category.renamed(eventOrder = 0)`:公共 `subject.name` 是新名称,FORMAT-030 `details` 精确为 `{ beforeName }`;同一有效当前名称完全无操作。固定收件箱不提供该操作,成功改名也不改变分类 ID / 顺序、任务归属 / 顺序 / 状态 / 内容 / 优先级 / 生命周期 / 时间或追加任务事件。
- 自定义分类真实拖拽换位只在投放后原子更新 `categoryOrder` 并追加 `category.reordered(eventOrder = 0)`:公共分类主体保存被移动分类发生时 ID / 用户原文名称,FORMAT-031 `details` 精确为 `{ beforePosition, afterPosition }`,每侧只含发生时 Custom 分类前后邻居或 Custom 序列 `start` / `end` 边界;Inbox 固定在序列外且不成为邻居。放回原位、取消和无效投放完全无操作;成功排序不改变分类名称或任何任务事实,也不追加任务事件。

## 快速新增

- 桌面主列表提供全局单行标题输入;移动端通过固定的 `+` 按钮唤起相同的单行快速新增交互。
- 全局入口创建到固定收件箱。
- 每个分类标题提供紧凑的 `+` 操作,使用同一套单行快速新增交互并直接创建到该分类。
- 快速新增只要求任务标题,不先展示备注、优先级、分类选择器或完整任务编辑器。
- 新任务默认未完成、`P3`;创建后普通点击任务行再进入既定编辑器补充备注或调整属性。
- 一次快速新增会话的首条任务插入目标分类未完成区顶部,后续任务依次跟在上一条之后,保持输入顺序而不反转。
- 每次创建成功后清空标题并保留输入焦点;移动端软键盘保持开启,直到用户显式关闭输入器或离开当前页面。
- 桌面端以一次 `Enter` 为键盘主提交动作,移动端以软键盘“添加”为主提交动作;两端均提供提交图标作为替代,但不增加确认步骤。
- 输入法组合期间的 `Enter` 不提交;失焦、点击外部或 `Esc` 也不自动创建。任务直接出现在列表中就是成功反馈,不弹确认或成功弹窗。
- 未提交文字与其语义快速入口关联;失焦、按 `Esc` 或关闭输入器后再次打开同一入口时恢复原文字与折叠光标。全局入口跨桌面和移动布局保持同一身份;全局入口与收件箱分类标题入口即使目标相同也不得合并。提交、点击清空图标或用户直接编辑为空字符串会无弹窗移除草稿;删除其自定义分类则复用该破坏性动作已有的一个阻断式确认,展示草稿预览并由“删除分类并丢弃草稿”明确消费确认代次,不再叠加第二个弹窗。
- 非空草稿以语义入口、当前代次、标题原文和 UTF-16 光标偏移保存在同一版本化 `IndexedDB`;纯空白仍是草稿但不能提交任务。刷新页面、关闭重开网页或 PWA 后,同一入口仍恢复草稿。

## 拖拽手势

- 不设置专用拖拽手柄或专用拖拽区域。
- 除复选框、优先级控件和操作菜单等明确交互控件外,任务行的其余区域都可直接发起拖拽。
- 桌面端按下后移动超过约 `6px` 即进入拖拽;未超过阈值即松开属于普通点击。
- 移动端在非控件区域按住约 `200ms` 后移动即进入拖拽;在等待时间内直接滑动属于页面滚动。达到长按阈值但未移动便松手属于无操作,不会打开编辑器。
- 拖拽预览直接跟随指针或手指,当前有效目标持续显示唯一的完整宽度精确插入标记;松手前不修改数据或历史。
- 任务只能放入与自身完成状态相同的序列,跨分类拖拽保持状态;拖拽不会代替复选框完成或重新打开任务。
- 空分类直接出现匹配状态落点;折叠分类或“已完成”区域停留约 `500ms` 后临时展开。取消恢复原折叠状态,成功后当前会话保持展开,但自动展开不覆盖持久折叠偏好。
- 长清单拖拽接近顶部或底部时自动滚动并持续更新落点;在有效标记外松手、按 `Esc`、系统取消或失去活动窗口控制权时恢复原位且不写历史。
- 可拖拽非控件区域的手势判定与拖拽过程抑制原生文本选择、图片拖动和长按菜单,但不影响输入与明确控件。
- 自定义分类标题的非控件区域复用同一套桌面与移动拖拽判定来调整分类顺序;收件箱固定第一且不可拖动。
- 分类折叠、快速新增和操作菜单等标题控件不发起拖拽;分类排序复用精确落点、边缘滚动和取消规则,且不改变其中任务的归属或顺序。

## 任务查看与编辑

- 在任务行非控件区域完成普通点击时,打开该任务的编辑界面。
- 桌面端编辑界面从右侧面板打开;移动端使用全屏编辑页。
- 普通点击任务行不会切换完成状态;完成与重新打开只能通过明确的复选框操作。
- 每条任务行直接显示紧凑的当前优先级标识;点击或轻触后用六项单选菜单一次完成修改,不先打开编辑器或弹确认。
- 优先级控件与任务行点击、完成复选框和拖拽命中互相隔离;编辑器内仍可修改同一个优先级字段。
- 任务行操作菜单提供“移动到…”,与编辑器分类字段共用包含收件箱、已有分类和“新建分类”的单选选择器;选择另一分类后立即生效、不弹确认,并把任务放到目标分类对应完成状态区顶部。选择当前分类属于无操作,不置顶、不改变时间或生成历史;精确位置继续通过拖拽表达。
- “新建分类”直接在选择器中展开并聚焦同一套单行名称输入;只有明确提交才原子创建分类、把当前任务归入其中并关闭选择器,取消或无效输入不改变任务且不跳转到分类管理页。成功操作先写 `category.created(eventOrder = 0, details = {})`,再写目标身份一致的 FORMAT-025 `task.category_changed(eventOrder = 1)`。
- 从任务行移动成功后保持当前清单位置,用“已移到「分类」”及“查看任务”提供可选定位;从编辑器移动时关闭选择器但保持编辑器打开并更新分类字段。待保存移动不显示成功文案。
- 清单分组已经表达任务归属,任务行不重复显示分类标签。
- 任务编辑器的标题和备注自动保存,不提供作为持久化必经步骤的“保存”或“完成”按钮;关闭桌面侧栏或从移动端返回时不要求额外确认保存。
- 连续编辑停止约 `600ms` 后形成一次正式保存;失焦、关闭侧栏、移动端返回或应用进入后台时立即尝试保存最新有效内容。每次成功保存只形成一条编辑历史,不逐字记录。
- 已有任务标题为空时只在标题输入处报错并暂停该字段保存;其他有效修改继续保存,用户仍可离开编辑器。离开后任务保留最后一次有效标题。
- 备注使用多行纯文本输入,保留换行但不提供富文本、Markdown、内嵌清单或媒体工具。
- 有备注的任务在标题下显示最多一行弱化纯文本预览,超出宽度省略;无备注时不占预览空间。预览属于任务行非控件区域,不提供独立展开或编辑。
- 主清单任务标题最多显示两行,超出后省略;连续超长字符也在行内断开,不得横向溢出。完整标题只在编辑器等详情上下文展示。

## 历史与垃圾箱入口

- 历史使用独立的全局页面,按本地自然日分组且默认最新事件在前排列。
- 每条历史记录收起时显示时间、动作及主体发生时名称:任务事件显示任务标题,分类事件显示分类名称且不伪造任务标题;点击后在原地展开该事件专属且实际存在的完整精确事实,不弹窗或跳详情页,也不要求整实体新旧快照。
- `category.created` 的紧凑行与分类筛选只读取公共分类主体中的创建时 ID / 名称,该行已经完整表达事件;点击不得因 FORMAT-029 空详情打开空白面板或显示原始 `{}`,统一展开时也只能重复公共外壳与主体中已经存在的事实。后来重命名、排序或删除分类不改写该名称,呈现也不读取当前分类、当前分类顺序或重放历史补值;永久清理任务不隐藏或改写该独立分类事件。
- `category.renamed` 的紧凑行与展开从 FORMAT-030 `details.beforeName` 到公共 `subject.name` 显示“旧名 -> 新名”;动作按当前语言显示,两个名称保留用户原文且不翻译。分类筛选只按公共 `subject.categoryId`,名称搜索匹配该历史中的旧名和新名;不得读取当前分类、当前顺序、后来事件或重放历史。后来再次改名、排序、删除及任务永久清理不改写或隐藏该独立事件。
- `category.reordered` 的紧凑行只从 FORMAT-031 `afterPosition` 表达移到 Custom 序列顶部、末尾或某个发生时邻居之后;展开完整显示 `beforePosition` 与 `afterPosition`。动作与边界按当前语言显示,公共主体及四个邻居槽中实际存在的用户名称逐字保留。分类筛选只按公共 `subject.categoryId`,名称搜索匹配该事件自身的主体和邻居名称;不得读取当前分类、当前 `categoryOrder`、后来事件或重放历史。后来改名、排序、删除主体或邻居及任务永久清理不改写或隐藏该独立事件。
- 历史展开只读,不提供编辑、撤销、回滚、恢复或删除;后来修改任务或分类名称不会改写旧事件。相邻任务永久清理或清理待完成投影时例外地把 D-106 / FORMAT-021 的整个 `task` 位置快照原子替换为通用“不可用”,不保留原 ID、标题、链接或筛选项。
- 历史页面通过一个筛选按钮打开桌面浮层或移动底部面板;任务与分类可搜索单选,动作可多选,选择立即生效。
- 不同筛选维度取交集、多个动作取并集;已选条件显示为可移除标签并可一键清除。筛选在当前会话内保留,但不跨重启或进入备份。
- 动作筛选固定为创建、内容编辑、完成状态、优先级、移动与归类、删除、恢复、分类管理八组;FORMAT-017 的 14 个事件类型各自只进入一个组,分类创建、重命名、排序与删除都只属于分类管理。事件行仍显示组内精确动作;创建按 FORMAT-022 显示发生时初始分类与创建后位置,连续创建也不改写先前事件;内容编辑按 FORMAT-019 除共有 `categorySnapshot` 外的变化字段存在性区分标题、备注或两者变化而不拆持久类型,标题新值读取保存后的任务主体标题;完成与重新打开按 FORMAT-020 只从事件类型区分方向;优先级变化按 FORMAT-023 显示不同的旧新值而不显示控件来源或位置;组内排序按 FORMAT-024 显示一份发生时分类、一份状态和移动前后位置;主动跨分类变化按 FORMAT-025 显示根部一次状态、source / target 分类及各自位置;分类删除派生迁移按 FORMAT-026 显示一次状态、来源被删分类与整批前位置、以及整批后最终 Inbox 位置;软删除按 FORMAT-027 显示删除时分类、一次状态与移出前位置,不显示恢复锚点或确认来源。分类重命名按 FORMAT-030 从 `details.beforeName` 到公共 `subject.name` 显示旧新名称,只按公共主体分类 ID 筛选且两名均可搜索。分类筛选只按 FORMAT-025 的 target 分类匹配主动跨分类事件,FORMAT-026 只匹配固定 Inbox,FORMAT-027 只匹配删除时分类;所有显示与筛选都不读取后来当前归属、状态或顺序,也不显示拖拽来源、绝对序号或内部排序键。
- `category.reordered` 同样只属于分类管理动作组,并按 FORMAT-031 只从公共主体与事件自身前后位置生成排序动作、摘要、展开、主体分类筛选及主体 / 邻居名称搜索;它不改变 14 个事件类型与八组映射,也不得因邻居名称命中而归入邻居分类筛选。
- `category.deleted` 只属于分类管理动作组,并按 FORMAT-032 从公共被删分类主体与单一 `affectedTaskCount` 生成摘要和展开;`0` 表示删除时没有活动任务,不是数量未知。分类筛选只按公共主体 ID,逐任务 FORMAT-026 仍只按固定 Inbox 匹配。任务永久清理后分类删除行继续显示原始计数,不得查询剩余任务事件或当前状态补值。
- 恢复事件按 D-113 / FORMAT-028 显示实际恢复目标分类、未改变状态与插入后的同状态直接邻居;原 Custom 分类改名时显示恢复时当前名称,已删除时显示固定 Inbox。分类筛选只按该实际 `categorySnapshot` 匹配,不得按删除时分类、恢复锚点、垃圾箱或后来当前归属匹配。
- 创建与移动事件以发生时分类、完成状态区及相邻任务或分类描述位置,使用顶部、末尾或相邻对象语言,不显示内部排序值和绝对序号。FORMAT-022 创建事件只显示创建完成后的未完成序列位置;FORMAT-024 组内排序显示同一分类和状态区内的移动前后位置;FORMAT-025 跨分类展开显示发生时 source / target 分类及移出前、插入后完整位置,紧凑摘要先显示“从 A 移到 B”且只按 `target.position` 补充目标落点。目标位置因去身份化无法可靠表达时只保留中性跨分类摘要,不查询当前事实。FORMAT-026 展开显示整批前来源分类位置与整批后最终 Inbox 位置,紧凑摘要表达“因删除 A 移到收件箱”并只按 `targetPosition` 补落点;批次邻居可以跨来源与目标同方向重复,不得套用 FORMAT-025 的四槽互异规则。FORMAT-027 展开显示删除时分类、状态及移出前位置,紧凑摘要只表达从该分类状态区移入垃圾箱;它不得参与恢复或从当前生命周期补值。任务前邻居按 FORMAT-021 只接受 `start`、恰含 `kind` / `taskId` / 发生时 `title` 的 `task`,或清理后的 `unavailable`,后邻居只接受 `end`、`task` 或清理后的 `unavailable`。正常 FORMAT-025 四槽位中的可识别任务 ID 必须跨侧两两不同且非主体;正常操作不得生成不可用,后来改标题、移动、改分类或完成状态、软删除都不改写旧任务快照。已永久清理的邻居只显示通用“不可用”,不伪造成位置边界或另一任务;多个槽位清理后可以收敛;FORMAT-026 同一重复邻居被清理时全部出现位置一起显示不可用;FORMAT-027 邻居清理后相应整个历史任务分支显示不可用,但不改变分类和状态摘要。若去身份化使 FORMAT-024 新位置无法表达具体落点,紧凑摘要使用中性“调整顺序”,不读取当前顺序补值。
- FORMAT-028 恢复紧凑摘要表达“恢复到「实际分类」的未完成/已完成区”并可从插入后 `position` 补充落点;展开显示同一实际分类、状态与完整位置。邻居去身份化后只降级为中性恢复摘要,不得从当前任务、FORMAT-027 删除现场或 FORMAT-014 锚点补值;后来变化不改写旧摘要或展开内容。
- 从任务编辑器查看历史时,先保存或排队最新有效编辑,再打开同一个全局历史页面;此前全部筛选被替换为当前任务条件,确保先显示其完整时间线。用户随后可继续组合筛选,返回任务页时恢复浏览上下文但不重开编辑器。
- 任务筛选排除纯分类管理事件;分类筛选按分类标识同时覆盖分类管理事件和归入该分类的任务事件,FORMAT-025 主动跨分类任务事件只匹配 `target.categorySnapshot`;FORMAT-026 分类删除派生迁移只匹配固定 Inbox,FORMAT-027 软删除只匹配删除时分类。它们都不按来源分类、垃圾箱或任务后来当前归属重算。分类删除后,其管理历史仍可通过历史中的名称搜索和查看。
- FORMAT-028 恢复事件只匹配实际恢复目标分类;删除时分类与回退路径只用于恢复算法内部且不形成额外筛选命中。
- 垃圾箱是独立页面;历史页面只负责查看事实链,不提供任务恢复操作。
- FORMAT-021 的历史邻居只用于只读审计,包括 FORMAT-028 的恢复后位置也不参与当前清单排序、拖拽落点或垃圾箱恢复;FORMAT-014 的恢复锚点是另一种不含标题的定位引用,两者不得互相补值。
- 垃圾箱只展示未到期任务并按最近删除优先排列;每行显示标题、优先级、删除时分类、删除时间和剩余保留天数。
- 每行直接提供无需确认的“恢复”;单任务永久删除收进任务菜单并继续使用不可恢复确认。
- 恢复成功后继续停留在垃圾箱,任务行消失并显示含实际目标分类和“查看任务”的短暂非阻断反馈;不会自动跳页。
- 成功反馈与随后追加的 FORMAT-028 必须来自同一实际恢复结果;分类改名或删除、锚点命中或末尾回退都不得让反馈与历史显示不同分类或位置。
- 用户主动查看时才进入任务页,展开目标分类及必要的“已完成”区域,滚动并短暂高亮任务;不打开编辑器、聚焦输入或弹出键盘。
- 垃圾箱不是第二套任务清单,不允许编辑、切换完成状态、改优先级或分类、拖拽和重排;任务必须先恢复再修改。
- 任务行操作菜单底部和任务编辑器底部提供“删除任务”,并共用同一个软删除确认流程;任务行不显示常驻垃圾桶,第一版不提供滑动或单键删除。 确认后同一原子操作建立 FORMAT-014 垃圾箱生命周期并追加精确 FORMAT-027 删除事件,不另写移动。
- 从编辑器发起删除时,尚未自动保存的有效内容先保存或排队;确认显示最新有效标题,取消删除不撤销刚才的编辑。 内容变化与删除是两个有序操作,FORMAT-027 主体标题取前序编辑后的最新有效标题。
- 编辑器顶部用一个安静状态区域表达自动保存:待计时或写入时显示“保存中…”,成功后短暂显示“已保存”并消失,失败时持续显示“待保存”并连接全局重试和应急备份。主清单任务行不常驻保存状态。
- 任务移入垃圾箱前显示阻断式确认弹窗;取消或关闭时不产生软删除、顺序变化或删除历史,但不会撤销确认前已经触发保存的有效编辑。 成功后历史只读显示 FORMAT-027 删除现场,恢复仍只从垃圾箱使用 FORMAT-014 锚点。
- 删除自定义分类前也只显示一次阻断式确认;非空分类必须展示任务数量并说明任务会移动到收件箱而非垃圾箱。分类标题入口有草稿时,同一弹窗显示可识别原文预览,纯空白使用明确语义,并把按钮标为“删除分类并丢弃草稿”;取消完整保留,草稿换代或从无到有时刷新预览并要求重新确认。
- 垃圾箱内永久删除单个任务或清空垃圾箱仍使用独立的不可恢复确认;“不可恢复”明确限定为当前数据库与之后的新备份。
- 单任务永久删除从任务菜单发起并在确认中显示标题;清空垃圾箱从页面菜单发起并显示冻结目标数量。两者都明确销毁当前数据库中的内容与全部任务主体历史,并去身份化其他保留记录中的目标结构化引用:包括 FORMAT-028 恢复位置在内的 FORMAT-021 整个 `task` 分支替换为精确 `{ "kind": "unavailable" }`,FORMAT-014 恢复锚点按其独立结构执行同类替换。同时提示删除前导出的产品外备份可能仍含这些内容且主动覆盖导入后可能重新出现,但不要求输入名称或确认短语。
- 确认框打开后才进入垃圾箱或已经恢复的任务不参与本次清空;确认后的目标删除与保留引用去身份化整批原子且可安全重试,不得留下 FORMAT-021 的 `taskId`、`title` 或混合分支。

## 待保存降级状态

- 数据已加载后发生正式任务、分类或历史业务写入故障时,任务列表和编辑界面继续接受契约允许入队的正式业务操作,包括已确认的分类删除;维护事务失败使用各自状态,不得伪装成用户待保存操作。
- 只有草稿写入失败时,对应快速入口显示非阻断的“草稿未保存”、自动重试、会话风险和应急完整备份入口;后续按键只更新该入口的最新待保存快照,不因草稿本身显示全局横幅、冻结无关操作或解除其他独立状态已有的限制。
- 正式任务、分类或历史业务写入失败时,所有主视图必须持续显示全局待保存状态,包括待保存变更数量、自动重试状态和应急完整备份入口。
- 待保存提示必须明确说明变更尚未安全落盘以及关闭或重载应用的风险,不得使用成功保存的视觉或文案。
- 全局历史中若展示待保存操作,必须与已持久化历史明确区分。
- 永久删除、清空垃圾箱和覆盖导入入口在降级期间不可执行,并就地说明其等待持久化恢复。

## 自动清理待完成状态

- 核心数据完整读取后若启动、回到前台或运行期自动到期清理失败,任务、垃圾箱和历史页面仍可正常使用,但所有目标到期任务及其任务主体历史已经从界面、搜索、筛选、计数和直接访问中排除,保留记录中的 FORMAT-021 `task` 邻居已经作为整个分支投影为精确不可用,FORMAT-014 恢复锚点按自身结构投影,且都不显示残留身份。
- 桌面和移动端所有主视图持续显示非阻断“清理待完成”状态,说明部分到期内容尚未从当前设备物理清除、已经隐藏并正在自动重试,同时提供手动重试。
- 清理提示不得显示为“待保存”、不得增加用户待保存数量,也不得声称已经彻底清除。后续正式任务、分类或历史业务写入失败时,清理提示与用户待保存提示分别存在。
- 新的永久删除、清空垃圾箱和覆盖导入入口在清理待完成期间不可执行;完整导出继续可用并排除物理残留的到期内容,把保留记录中的 FORMAT-021 整个 `task` 分支及 FORMAT-014 恢复锚点分别按各自结构去身份化。
