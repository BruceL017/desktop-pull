## 锁定实现

- 保持 ADR-016 的 control DB + 六个 core stores 与现有索引,不新增生产依赖。
- 正式业务操作冻结操作接受时的完整结果、原时间、稳定逻辑键与期望操作序号;控制器按 FIFO 作用于工作状态,仓储在覆盖六 Store 的单一事务中校验基线并提交。重试不重新推断业务事实。
- 草稿仍使用独立 Store 写入;正式队列非空时延后草稿写入,避免完整正式事务覆盖更新的草稿代次。
- 桌面拖拽使用原生 DragEvent,触控使用 PointerEvent 长按状态机;两者调用同一领域落点操作。
- Manifest 与 Service Worker 为仓库内静态资源;Service Worker 只缓存应用壳,不打开 IndexedDB。
- 单活动窗口使用 Web Locks 的不可抢占排他锁;不支持该能力时进入保护态,不建立不可靠租约。
- [已被当前 v2 实现覆盖]评审时 schema 仍为 v1;当时要求未来真实 schema 变化必须单独提供候选复制和迁移函数及升级测试,不能把无迁移启动冒充已执行迁移。当前 v1 到 v2 路径已按该要求实现并由 TP-M1-05 / TP-M1-RC-01 提供证据。

## 拒绝方案

- 为每种操作建立不同仓储事务与重试队列:会重复创建已由完整逻辑快照共同承担的一致性边界。
- 增加状态库、拖拽库、PWA 插件或 i18n 框架:当前行为可由既有 React、浏览器 API 与静态资源实现,新增依赖扩大评审和离线表面。
- localStorage 心跳或超时抢占窗口:崩溃与挂起状态无法满足 WINDOW-005/009。
